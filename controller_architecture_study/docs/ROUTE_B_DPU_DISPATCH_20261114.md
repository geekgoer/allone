# 路线 B｜基于控制义务的 DPU 派发

## 研究问题

在当前板端，每次 DPU 调用会把一个模型完整跑完。开始执行的瞬间，调度器就承诺让它连续占用设备一段时间。**特殊之处在于，这段不可抢占的时间可以在派发瞬间改变，因为同一条控制更新可以改用另一个闭环合格模型。** 同时，受保护的控制更新可能还在 CPU 前处理，或者是之前主动跳过之后承诺的补更。两者都有必须兑现的时间。

RICH 的 MRAF 用剩余加速段数决定先服务谁。本研究用**派发后仍能兑现控制义务的最大连续设备占用时间**约束动作，在线决定“跑谁、用哪个模型、或者等”。这条规则可在独立模型的现有整任务 DPU 上工作。[RICH，DATE 2025](https://date25.date-conference.com/programme)

## 1. 将控制义务转换为设备时间

为进入短预测窗口的每条必需更新 $j$ 维护三项。

| 量 | 含义 | 得到方式 |
| --- | --- | --- |
| $q_j$ | 输入可以交给 DPU 的最晚预计时刻 | 由释放日历、当前 PS 前处理阶段及其剩余服务预算给出。已经 ready 的任务用已知时刻 |
| $d_j$ | DPU 最迟结束时刻 | 从命令生效期限扣除走完下发路径所需的上界。补更任务还受上一条有效控制的保持期限约束 |
| $p_j$ | 已选合格保底模型的设备占用时长上界 | 按已验证状态、保持区间和输入有效期筛出合格模型，再取最快者。计入相关派发、切换和 DMA 开销 |

将一次计划跳过表示为在日历上删除一条可撤回的更新，同时写入强制补更义务。它原先的资源请求可以让出，旧命令的保持上限仍然有效。只有相位、实际控制、预计保持区间全部有证据支持时，才允许这种变换。早期建立纠偏的更新、相位未知以及已欠一次补更的回路属于受保护状态。转弯相位来自已观测状态和参考进度，并随路线核验。[相位与补更条件](ROUTE_B_PHASE_AWARE_FRAMEWORK_20261114.md)

## 2. 从未来任务倒推出此次最多占用多久

在 DPU 空闲时刻 $t$，考虑先派发 ready 任务 $i$。把 $i$ 从保留集合中取出，余下的任务沿用上一份已经通过检查的设备顺序 $j_1,\ldots,j_n$。在这个短窗口内，固定剩余任务的合格保底模型和次序，从尾向头算

$$\ell_{n+1}=+\infty,\qquad
\ell_k=\min(d_{j_k},\ell_{k+1})-p_{j_k}.$$

$\ell_k$ 是在该顺序下仍能完成所有后续任务时，$j_k$ 最迟何时可以占用 DPU。如果任何 $q_{j_k}>\ell_k$，这条尾序列自身已经无法执行。否则，派发给 $i$ 的连续占用上限为

$$b_i(t)=\min\{d_i,\ell_1\}-t.$$

空尾序列时，$\ell_1=+\infty$。从 $i$ 已合格的模型中选择 $C_i(c)\le b_i(t)$ 的最高质量档。如果最大档不合适，查一档可塞入的合格模型。当前 ready 的任务都无法填入时，等待下一个被保护任务的 ready 事件。优先考虑已验证尾顺序的首项。该首项仍在 PS 阶段时，在有合法空档的 ready 任务中按原命令期限排序，再以预测余量、误差区分平局。每次最多检查固定数量的队首与 ready 任务，剩余候选的处理交回有界修复。在普通派发路径上无需重跑全组事件仿真。保留顺序失效、引入新任务或变更周期才调用 A／B／C、全组时序验证及原子提交。

对**固定尾顺序、确定的释放时刻、截止期及服务时长**，可以证明候选的精确可行条件。给定首个占用，尾任务最早按 $s_k=\max(q_{j_k},s_{k-1}+p_{j_{k-1}})$ 执行。倒推递推恰好给出了每个 $s_k$ 的上限。于是，候选自身按期、候选结束不晚于 $\ell_1$、且所有 $q_{j_k}\le\ell_k$，等价于按该顺序前推全部按期。计算一次尾序列为线性时间。若 $q_j,p_j$ 来自可信上界且 $d_j$ 已扣齐其他路径耗时，执行已验证顺序的结果给出相应假设下的充分条件。对实际系统，有模型相关的切换上界时，应用覆盖所有准入模式的边界上界或按候选重新计入首个交接。还应校验 PS 工作槽及数据年龄。预测上界来自 P99 时，结果只具有回放或经验调度含义。

安全期限在提交后收紧时，需要重新检查。这项保证只覆盖已经登记的有限窗口。尚未观测到的扰动或新到达可能需要额外保留、降级或新的可调度性证明。待跑任务状态变化时，替换保底模型、时刻与命令版本需一起更新。

## 3. 一个能分辨旧规则与新规则的例子

时刻 0，普通更新 A 已 ready，4×1024、3×256 等模型的成本—质量关系决定 A 有多个可选执行时长。为便于手算，令 A 可选择占用 5 ms、3.2 ms 或 2 ms。A 自己的设备期限为 10 ms。另一架飞机 B 正进入转弯早期，输入还在 PS 准备。C 是此前跳过后已经承诺的补更。

| 任务 | DPU ready | DPU 期限 | 保底占用 |
| --- | ---: | ---: | ---: |
| B，关键更新 | 2.5 ms | 5.5 ms | 2 ms |
| C，强制补更 | 4 ms | 7 ms | 2 ms |

只看 B，A 可以占用到 3.5 ms。此时如果给 A 派发 3.2 ms 的档位，B 能于 5.2 ms 完成，C 却要到 7.2 ms，晚 0.2 ms。把 C 的补更承诺沿尾顺序反推，C 最迟 5 ms 开始，B 最迟 3 ms 开始。因此给 A 的连续占用上限是 3 ms，调度器可以让 A 用 2 ms 档先算，再执行 B 和 C。这个例子用同一组义务说明两种收益。相较于立即提交 5 ms 档，它保住了期限。相较于直接空等 B，它利用了设备空档。

离线核对使用 Python 对 50,000 组随机的固定尾序列比较倒推与逐项前推，结果逐组相同。上述 0、2、3.2、5 ms 四个首占用的结果依次为通过、通过、失败、失败。这是数学边界的自检，性能和闭环收益依赖后续实验。

## 4. 哪一点有机会成为论文贡献

倒推最迟开始是标准实时调度工具，前瞻空等与回收余量也已有研究。TimelyNet 已经用动态预算选网络，弱硬实时也已有跳过和恢复要求。**可检验的贡献是让共享队列中的多个控制回路共同决定当前模型的最大不可抢占时长，并让某条被延期的更新以强制补更的形式参与同一计算。** 因此，派发预算会随另一架飞机的飞行相位、在途 CPU 进度和补更期限变化。相同的任务和自身期限，可能因另一个回路进入关键阶段而采用完全不同的模型。[非抢占前瞻调度](https://www-roc.inria.fr/rapports/sophia/RR-2966.pdf) · [Slack Stealing](https://igm.univ-mlv.fr/~masson/pdfANDps/davtinbur93.pdf) · [TimelyNet](https://tanrui.github.io/pub/TimelyNet-EMSOFT.pdf) · [DMAC](https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.ECRTS.2019.1)

同一批配对输入至少做以下对照。

| 对照 | 要回答的问题 |
| --- | --- |
| 非抢占 EDF＋同样的模型池和自身预算 | 其他回路形成的联合预算是否额外减少了关键更新迟到 |
| 非抢占前瞻 EDF＋可空等＋固定档位 | 允许在空档中选择更合适的完整模型，是否比单纯预留空档提高按期交付和设备利用率 |
| 同等预算的前瞻 EDF＋同样可换模，只检查最近一条受保护更新 | 多任务尾链和补更期限是否解决了由第二条或更晚义务触发的阻塞 |
| 完整规则，禁用计划跳过／加入补更 | 相位与补更约束在哪些真实负载下改变了决策和控制结果 |

按相同总时限和候选数比较。主要指标采用相位分层的关键更新迟到、补更超期、最小净空、设备空等、按期交付的控制质量、调度开销。独立报告预测过时和模型资格不足。若只在构造例得到改善，或考虑 PS 时间后联合预算没有可用余量，则学术主张应收窄到可证明的固定尾序列判据。当前证据包括旧 FP32 AirSim 相位配对与整任务回放，新的 INT8 相位资格和延迟上界仍需实测。
