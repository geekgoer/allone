## 2. 安全条件：已经考虑什么，没有做到什么

`recovery_budget.py`不再只计算距离除以速度。其原型约束为：

\[
v_+(\tau+\ell)+\tfrac12a(\tau+\ell)^2+
\frac{[v_++a(\tau+\ell)]^2}{2b}\le d.
\]

它加入外向加速度、制动距离、额外物理响应滞后和门前适用范围。当前配置中的b=2、加速度界6/5和额外80ms物理响应滞后均未获得实际控制器/飞行器的严格认证。

`framework_runtime.analyze_budget()`记录实际发送控制，但安全界计算仍标注：

```text
uses_control_in_bound = false
is_safety_certificate = false
```

所以它不是Yang 2019的CBF safe period。Yang的安全时间针对给定动力学、当前状态及保持不变的实际控制，利用轨迹与CBF约束的下界计算；其适用条件必须满足，不能只换一个公式名字。

后续保留一个Safety Analyzer接口即可，不增加DNN–MPC误差模块：

\[
B_k=\mathcal B(x_k,u_k^{actual},\Omega),\qquad
a_{k+1}\le d_{k+1}^{safe}.
\]

必须说明安全集合、飞行器包络、动力学适用范围、命令生效与状态时间戳，以及实际保持控制。当不存在可认证的正安全时间或资源不足时，应返回不可行/无法保证；缩短T不自动使任意DNN命令变安全。

只在明确模型假设和可行域内声明条件性保证；AirSim与真实飞行器的模型偏差不会因为引用Yang而自动消失。采样点没有碰撞的统计也不能替代整个保持窗口的安全推导。

## 3. 当前触发、选择与提交算法

### 3.1 触发

`anticipatory_mode()`综合：当前余量h、向边界移动趋势、未来2秒参考轨迹偏转，并在稳定一段时间后退出恢复状态。物理B另外约束新控制最晚完成时间。

因此当前触发并非完全由B驱动，轨迹预览规则本身也会触发20ms建议。需要用消融实验分清B、路线预览和运行时优化各自的收益。

### 3.2 T、c与调度的实际关系

1. 规则先选择预设cruise/recovery模型，并产生期望周期：危险时请求20ms，平稳时倾向60ms。
2. `allocate()`估计前端和后端持续需求；超出0.95预算时，从低紧迫度回路开始逐档放宽周期。恢复回路不得放宽到比原选定周期更慢；当前原选定周期为30ms。
3. `admit_group()`最多检查联合候选与保留候选两种配置组，保护其他已知作业的期限。
4. C++整组提交仅作用于尚未发布的作业；任一参与回路的发布进度已变化则撤回，不能部分安装。
5. 后端一直使用段级EDF。每完成两层全连接才允许切换作业，不是遇险后在EDF、RM等算法之间搜索切换。

这是“风险规则＋有界贪心＋全局准入”，不是在线J最优搜索，也不是遍历T、c、调度排列的联合最优算法。c目前不具备“更复杂就更安全”的选择保证。

### 3.3 与用户最新版Framework的差别

最新版要求：

```text
状态/当前控制 → 安全绝对期限
状态          → 最低成本合格c
二者          → 有界release规划 + 段级EDF
release结果   → T
```

当前实现仍显式分配离散T，再产生release，是过渡实现，尚未完全实现上述顺序。后续应按该接口收敛，而不是继续叠加更大的(T,c,σ)搜索。

### 3.4 会不会仍退回旧配置

会。最终两组联合候选安装82次、23次，但实际周期/模型配置变化只有9次、7次；另有477次、1040次发布竞争撤回，以及大量负载或过渡期限检查失败。

拒绝至少有三种含义：模型预测的资源不足、有限候选未找到满足期限的过渡安排、预测期间任务已发布使快照失效。它们不等于“安全条件过于敏感”。有限搜索失败也不等于理论上不存在可行调度。

后续分别记录触发、提出、准入、提交、首次使用与物理控制结果的时间。重点指标是从检测危险到新配置真正用于控制的延迟，不能仅统计建议次数。

## 4. 扩大实验：先消除混杂，再增加场景

### 4.1 公共运行时

静态和动态必须共用：C++ I/O、输入等待保护、即时完成处理、模型池、CPU/加速器资源、在途名额、测量与日志、碰撞后只退出该回路的规则，以及相同的过期输出/旧任务处理规则。

当前`joint_adaptation`还同时控制部分前端优化。正式比较前，应将公共运行时优化与动态决策开关分开，防止“动态策略”的收益主要来自其独占更好的前端。

### 4.2 三个对照，回答不同问题

| 方案 | 配置如何得到 | 回答的问题 |
|---|---|---|
| 离线静态 | 按相同J目标与资源条件，离线选择每架机的固定T、c、优先级；运行时不调整 | 动态是否优于离线固定配置 |
| 路线预先计划 | 仅依据已知路线/名义轨迹预定各阶段的配置；不使用实际危险状态反馈 | 收益是否仅来自预先知道后面有急弯 |
| 在线反馈 | 使用实际状态与安全期限更新配置和release | 实时反馈本身是否带来额外收益 |

第一阶段可以固定c比较T与调度，但必须标注为T/调度消融，不能写成完整T、c、σ框架已验证。c选择完成后再加完整版本，不用提前大规模训练新模型。

静态候选应包含动态实际经常使用的固定组合，例如平稳回路60ms、困难回路较短周期，避免因静态搜索漏掉好配置而制造优势。允许静态每架无人机使用不同T和c，不能强制所有无人机同一配置。

20个候选的局部搜索只能称“本次候选/搜索预算内最好”，不称数学全局最优；没有复现SVM与目标FPGA时，称FALCON式离线静态近似基线。

### 4.3 建议场景规模

先保持5m/s和1.7m门洞，不增加外部扰动；扩展自然路线和共享负载。

| 维度 | 建议取值 |
|---|---|
| 活跃无人机数 | 3、6、10 |
| 路线类型 | 平缓路线；长平稳前缀＋末段急弯；多机异质混合 |
| 独立场景种子 | 每个组合10个，正式评价种子提前冻结 |

共90个配对场景；三个策略完整比较为270次多机运行。先用独立于正式评价的小规模场景检查协议与数据完整性，再一次性执行正式批次，不在正式结果上不断调参数。

混合路线按比例分配连续弯、平缓、末段急弯，而不是继续依赖“前三架固定困难、9/10号固定末段变化”的编号规则。种子应真正改变弯向、幅度、门间距和困难段位置；原生成器主要只改变小幅度参数，单纯增加其seed数量不等于充分增加场景多样性。

正式飞行覆盖整段实际路线；快速搜索阶段可以用明确标记的前缀估计，但不把`J_hat`或虚拟重复的平稳段冒充整段实飞结果。新路线须在控制器/教师适用范围内；不要通过制造连低延迟教师都飞不过去的路线来强迫静态失败。

低负载下静态已经足够好是正常结果。研究关注动态在何种局部危险与共享负载下改善安全/性能，不预设每个场景都应胜出。

### 4.4 指标与失败处理

共同报告：碰撞、物理任务完成、有效过门及余量、原公式形式的J、触发到配置生效延迟、控制空窗、响应R、名义超期和安全期限违反、被替换/未交付任务，以及对其他回路的影响。

J使用相同状态定义、权重、时间网格和窗口。失败/提前退出的轨迹单列缺失和失败率，不只保留成功回路平均，也不临时给失败赋零后仍称原论文J。若需统一含失败的标量排名，应事先定义并单独命名任务得分。

以完整多机场景为配对和统计单位，不能把共享资源下同一运行的10架机当成10个独立样本。报告每个负载/路线组合的配对差异及区间；路线种子或场景级配对bootstrap可用于估计不确定性。

## 5. 建议实施顺序

1. 对齐绝对安全期限、实际控制与状态时间语义；明确B的当前原型边界和后续严格模型。
2. 将公共运行时优化与策略开关分开；完善触发到实际生效记录及拒绝原因分类。
3. 对齐最新版“选合格c→有界release规划→得到T”的接口；在尚未完成c选择前固定c作消融。
4. 用少量独立场景核对公平性、控制器可用性和完整评分；不以找到静态失败作为通过条件。
5. 冻结规则、模型池、时延预算、静态搜索预算和正式场景种子，执行上述扩大批次。
6. 将FPGA实测时延与分段代价替换CPU经验值；CPU结果不作为FPGA安全/性能结论。
