# 七机状态感知时序：阶段结果与边界

2026-10-26。本阶段共完成44次七机完整航程：19次周期/调度对照、15次首次更新对照、10次选择性纠正对照。所有碰撞、迟到与未通过结果都保留，没有因查表缺记录提前截断。

## 当前可以下的结论

已经观察到同资源、同模型、同初态下，静态配置撞门、提前给危险回路计算纠正命令后七机通过的案例。更小的T并不自动更好，全机同步更新也有排队代价。当前最简洁的有效方向是：**保持正常错峰，只为危险回路插入及时的纠正任务。**

这只是固定DNN下的时序与调度消融，尚不是完整FALCON与最终框架的论文级对比，更不是安全证书。

## 实现了什么

七条控制回路共享一个CPU推理进程，实际执行原DNN；最多在两个完整FC层之间重新选任务，每个任务保存自己的激活，不在半个FC内抢占。主控、推理、通信与Unreal使用分开的物理核集合；这是CPU原型，不等价于FPGA时延或操作系统独占核。

两边固定使用原237D `plain_mlp_h9_w1024_seed0`，归一化、权重和控制映射一致。全部六个模型的SHA256复核未变化，没有训练、改权重、MPC接管或隐藏悬停替代任务。

门洞净宽2m、高4m，已有environment48/route1的C2曲线与约5m/s参考速度。七机有2.1s的物理路线相位差，分别从航路中段开始，飞完各自剩余3/4个门，再观察终点3s；总窗口约11.071s。物理运动阶段不暂停、不重新放置飞机。

目前的选择性策略 `event_insert`：

1. 首次状态观察时，若 `h + 0.5*min(hdot,0) <= 0`，为该回路立即请求一次纠正计算。h是参考轨迹管道余量，0.5s是预先固定的启发式观察尺度，不是严格安全时间。
2. 首个任务期限用连续紧迫度缩紧，EDF在FC分段边界选择任务；模型保持不变。
3. 纠正任务结束后，回到原来错峰的周期任务日历，不把七条回路永久同步，也不一直提高全部回路频率。相邻请求间隔至少20ms。
4. 门框距离/速度原型B继续限制后续EDF期限；期限不满足如实记违例，探索试飞继续执行。

该版本**只在首次观察状态处触发额外纠正任务**，尚未实现飞行途中任意时刻的独立事件检测器。后续任务的期限仍依据反馈状态更新。没有格子查找或未知状态中止，c暂时固定；完整的admissible-mode选择与超网切换尚未接入。

## 静态基线如何确定

先固定既有9×1024模型，在正常场景有限测试五种周期。预先规定：完整任务、恢复与时钟通过，且没有名义截止期迟到，再按总J选最高者。

| T | 正常总J | 名义期限迟到数 | 本次可入选 |
|---:|---:|---:|---|
| 20ms | 1.553365 | 129 | 否 |
| 30ms | 1.541370 | 22 | 否 |
| 40ms | 1.538099 | 0 | 是，选定 |
| 60ms | 1.476391 | 6 | 否 |
| 80ms | 1.447518 | 0 | 是 |

因此在困难场景之前冻结40ms，而不是刻意选容易撞的80ms。60ms一次运行有迟到、40ms没有，反映Windows时延波动，不能推断60ms一般比40ms更难调度。该搜索只覆盖固定c的五种T，不是六模型、所有优先级和相位的联合全局最优，也没有SVM。

## 观察到了什么

### 首次更新与排队

第七架的困难初态为横向位置偏差−0.05m、速度偏差−1.2m/s，其余六架正常。

在`seven_first_update_20261026_v1`的两次反序配对中，原静态40ms均实际撞到第2门左框；事件EDF均七机完整通过。危险机首个命令返回从约41ms提前到约10.5～12.1ms。

但“静态也把所有首批请求立即释放”的对照同样两次通过。因此，这组结果不能单独证明动态机制不可替代：改变静态相位也可能救回。它同时揭示了全机同步的代价：平均R约15ms，而原错峰约7ms。

### 最新选择性纠正结果

最新批次：`seven_event_insert_20261026_v1`。同一困难状态，两次反序配对，七架初态与held control全部一致。

| 策略 | 通过任务与恢复 | 实际碰撞 | 危险机首次返回 | 总体平均R | 总J |
|---|---:|---:|---|---|---|
| 冻结静态40ms、原错峰 | 0/2 | 1/2 | 40.11 / 40.44ms | 7.11 / 7.17ms | 任务未通过，留空 |
| 危险机插入一次纠正、回原错峰 | 2/2 | 0/2 | 7.35 / 8.28ms | 6.80 / 6.90ms | 1.472939 / 1.475423 |
| 全机同时请求的静态对照 | 1/2 | 1/2 | 19.10 / 25.50ms | 14.73 / 16.26ms | 1.457572 / 任务失败 |

原错峰静态的另一次没有实际接触门框，但第2门横向偏差−0.4849m，超过沿用的0.475m净空判据，不能写成“撞门”。最新组严格的“静态实际撞门、动态任务通过”配对为1/2；“静态任务不通过、动态通过”为2/2。早一批的实际碰撞救回为2/2。这些都是开发样本，不是独立大样本可靠性结论。

最新策略每次仅为危险机多计算**一个**任务。请求时刻从原来的34.29、74.29、114.29ms，变为0、34.29、74.29、114.29ms；没有把其余六架持续加速。每次预算/规则分析平均约0.077ms，仍需实测FPGA平台的开销。

正常场景同批结果：原静态J=1.528695，选择性纠正J=1.533774，后者没有产生额外任务；全机同步静态J=1.511178。这只能说本次观察未见明显正常QoC损失，不能把一次约0.3%的差别宣称为显著提升。J沿用Eq4形式、Wx=I、公共20ms评估网格，越高越好；失败任务没有补0或用碰撞后的残缺数据补算漂亮分数。

另一侧第1架+1.2m/s的控制场景也通过了选择性策略。第一版持续20ms缩短策略曾在该侧擦框，后续立即更新版本又能通过，说明临界门框附近对实际执行时刻敏感，不能把“周期越小一定越安全”作为结论。

## 还没有解决的事情

- **B尚未变成可靠安全约束。** 最新两次选择性策略各有7次B主导期限、5次该期限未满足，尽管两次均无碰撞通过。其普通40ms名义期限迟到数为0。必须区分“物理观察通过”与“所有预算承诺满足”；当前不能写严格physical safety guarantee。
- 当前B是距离/速度估计，不使用held control做动力学预测。接口有实际u，但还不是Yang-style/robust safe period；没有引入DNN误差模型。
- “危险发生”目前设置在实验初态，静态相位可以预先对齐。真实学术主张需要进一步验证危险机与危险发生时刻变化时，不能靠固定相位同样解决。
- 本轮固定c，不证明超网、动态DNN复杂度或有限抢占本身必不可少；实际FC分段恢复次数已经记录，但这不是其独立收益证明。
- Windows仍有时延尖峰和跳过的周期，初次正常选型没有迟到不代表硬WCET。所有超期输出均保留并继续应用，仅适用于本轮明确的AirSim探索。

最小的下一步是：保留当前40ms正常错峰日历，在飞行中改变危险出现时刻和危险回路，公平比较冻结静态相位、全机同步静态与选择性纠正。两边必须拥有相同的状态观察信息，事件检测/采样开销计入资源和R，不能给动态策略免费的“已知扰动”通知。先做这个关键对照，不增加新训练、RL、复杂搜索器或能耗模块。
