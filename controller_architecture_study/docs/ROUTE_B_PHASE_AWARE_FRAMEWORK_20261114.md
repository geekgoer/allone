# 路线 B｜相位感知的周期、模型与派发联合调整

## 1. 研究问题

多架无人机共享一个不可中途抢占的 DPU。每次更新前，调度器需要回答两个问题。当前任务还能不能让新命令按时生效？如果资源冲突，应该提前发布、换模型、改派发顺序，还是让另一架飞机暂时沿用旧控制并确保它及时补更？

候选论文贡献是**把跳过一次计算与按时补更绑定成一个调度动作，再让 A／B／C 瓶颈诊断选择何时值得做这个动作**。这样既可以说明哪项修改能缓解当前冲突，也可以指出修改把哪些时序义务转移到了下一窗口。把“连续漏几次”扩展成“哪条更新可跳，下一条最晚何时生效”，是这里最值得检验的假设。

## 2. 一条控制更新有两种期限

令 $r_{ik}$ 为日历上的计划发布时间，$T_i$ 为周期，$a_i$ 为上一条真正生效的命令的时间。$B_i(x_i,u_i)$ 表示在该命令下，从匹配的观测时刻起可继续保持旧控制的保守时长。若在命令生效时观测，则起点为 $a_i$。若使用后续观测，则使用其实际时间戳并核对仍是同一命令。用 $d_i^{hold}$ 表示由此得到的绝对时刻，并同时限制最长控制保持时间。

正常更新的绝对期限为

$$d_{ik}=\min\{r_{ik}+T_i,\ d_i^{hold},\ d_{ik}^{fresh}\}.$$

$d_{ik}^{fresh}$ 是该次采样结果的有效期。任务响应时间定义为 $R_{ik}=f_{ik}^{act}-r_{ik}$。其中 $f_{ik}^{act}$ 是命令生效时刻，或者在明确定义执行语义后对它的上界。发布、采样、前端处理、设备排队、推理、下发都在这条链上。故正常完成要求 $R_{ik}\le T_i$，同时命令需要在物理保持预算和数据有效期内生效。对既有日历，使用已提交的下一释放边界计算周期限制。

计划跳过时，原任务的日历槽保持可见，单独记为计划跳过。保持时间的物理上限不变，**下一条补更仍须在它自己的期限内完成，而且不能晚于旧命令的保持上限**。这对应按回路约束的受控降级。若系统要求每个日历槽都有新输出，就禁用计划跳过，保留其余 A／B／C 逻辑。运行中已经过期的结果单独记录，按有效期和命令版本丢弃。

## 3. 怎样把“早弯漏得更严重”用起来

现有 FP32 AirSim 证据来自一条路线的第 4 门。干预分别在参考到门前约 0.94 s 和 0.15 s，两组各连续漏两条。50 ms 组连续飞行时，早期净空从约 8.8–9.4 cm 降至 2.4–2.5 cm，晚期变化为毫米级。80 ms 组早期 4 次干预全部撞左框，晚期无接触。早期正常命令相对旧命令的变化也较大。这提示要保护正在建立纠偏动作的更新。其他路线的敏感阶段由状态、参考变化和保持旧控制的后果共同决定。[原始配对和图](ROUTE_B_GROUP_MEETING_20261110.md)

**可解释的资格规则。** 同时考虑飞行在路线上的进度、门横向误差和速度、当前实际命令，以及参考转向变化。在历史状态和独立路线做配对闭环，冻结两张简单表。一张给出初态和保持时长下哪些模型合格，一张给出哪些状态下允许继续保持已作用的控制。如果存在物理可证的保持界，取它和实测资格范围的交集。表覆盖不足时记为状态未知，保护更新。若预计保持区间会跨入待纠偏区，也保护更新。用各路线实际阶段及状态对齐，避免把到门前 0.94 s 写成全局常数。首版试验只评估单次计划跳过，此前的“两次漏更”证据用来识别敏感阶段。

对准备跳过的任务 $j$，构造补更任务 $j^+$，保留已知的下一槽，定义

$$S_j^{recover}=\min\{d_j^{hold},d_{j^+}^{fresh},r_{j^+}+T_j\}-\widehat f_{j^+}^{act}.$$

候选只在以下条件下可被提交。当前更新尚可撤回，未连续跳过，整个延长保持区间在资格范围内，$S_j^{recover}\ge0$，且所有其他保留任务及不可变余留工作通过全组检查。每次只允许一条计划跳过，并将补更义务写入同一个日历事务。若新状态缩短保持界，立即重审并报告剩余时间内可用的降级动作。

例如控制在 0 ms 生效，后两次计划发布为 50 和 100 ms。若跳过 50 ms，并预计 100 ms 的补更在 120 ms 生效，那么本次实际保持约 120 ms。旧控制到 110 ms 就会到期时，即使 DPU 及时处理其他飞机，这次跳过也不合格。

## 4. A／B／C 怎样决定改什么

每次以锁定版本的日历、已执行任务剩余量和最新命令做一次有限窗口估计。涉及已经发布的工作时，只允许使用真实执行平台支持的动作。当前独立 DPU 模型按整任务运行。每一轮先找能恢复全部义务且保留已验证控制能力的解。

| 类型 | 明确判断 | 动作与优先依据 |
| --- | --- | --- |
| A，单条链路来不及 | 诊断时间加上独占后剩余链路仍超过该任务期限。在既有发布下，若连最快合格模型都超期，改派发顺序也无法修复 | 用 $r_i^{latest}=d_i-L_i^{solo}$ 找最晚可发布时刻。尚未发布时先尝试最小的可行提前量，或换更快的合格模型。若眼下连最快路径都晚，记录为发现或处理过晚 |
| B，窗口容量不足 | 对确实必须在同一窗口内完成的 PS 或 PL 工作，需求超过该资源在窗口内的可用时间 | 只比较能减少这个窗口真实需求的调整，例如把合格模型换小，放宽未来低风险回路的周期，或对符合资格的一次更新检查跳过。当前回路加频通常会增加后续需求 |
| C，当前派发造成阻塞 | 单条链与容量检查没有发现超量，当前回放仍有失败 | 先沿迟到任务的 PS／PL 等待查阻塞源。整任务 DPU 可重排尚未开始的任务，也可短暂保留即将到达的紧急任务所需的设备时间。需要全组反事实确认可修；C 只表示值得检查派发 |

诊断式中的必要条件应使用乐观下界。以 $L_i^-(c)$ 表示模型 $c$ 的独占路径下界，则 $\max(t,r_i)+\min_c L_i^-(c)>d_i$ 时，本次排序无解。B 同样使用已知必须执行的服务下界，剔除跨窗口且无法证明全量落在窗口内的工作。用成本预测和 P99 代入时，这些条件只描述当前的工程回放模型。实际准入需要与执行语义一致的上界或明确的统计假设。持有区间的绝对期限应在整个补更窗口内有效，不能因为改了 $T$ 就向后推物理期限。

### 模型怎样选

对每个状态先筛出经过闭环资格验证的集合 $\mathcal A_i(x,\delta)$。对其按服务时间与教师误差构建局部前沿。预算 $b_i$ 来自绝对期限，扣除当前时刻、预测排队、输入与输出路径和交付预留。

$$c_i^*=\arg\min_{c\in\mathcal A_i(x,\delta),\ C_i(c)\le b_i} E_i(c).$$

资源紧张时，在相同窗口内优先比较有效减少的服务量和质量代价。对于需要额外服务的升级，可按 $(E_{\rm old}-E_{\rm new})/(C_{\rm new}-C_{\rm old})$ 排序，再重查其余回路。质量更好且服务更短的选择优先。同一调度窗口的成本也应计入切换、跨模型缓存以及前端占用。局部模型候选和全组回放次数设上限。完整论文实验应以闭环跟踪、碰撞和净空复核教师 MSE 这个代理目标。

### 提交规则

先检查所有应交付任务的期限及每机工作槽空闲，再考虑跳过或用剩余时间提高模型精度。提交前须确认输入新鲜、命令版本未变、释放仍可编辑、补更槽仍然存在。任何一个条件不满足就撤销方案并记录原因为哪项义务不再可满足。对进入硬件的老任务按剩余工作量承担阻塞。在线运行每次采用有限候选与预测窗口，PS 上再单测反应时间、抢跑和反馈延迟。

## 5. 以 Ubuntu 摘要作反事实输入，实际跑了什么

假定新 INT8 在真板上保留 Ubuntu **512 条候选选择样本**上给出的误差，并且旧版板端服务 P99 可作为名义成本。摘要只披露六个模型的具体误差。六档按成本和误差得出的点估计前沿为 **2×128、3×256、4×1024**。4×1024 的假定误差 0.003289、旧版 P99 1.323 ms，优于这六档中其余三个深档位的成本和误差。6×1024 的假定误差 0.003303，与它很接近。后续应使用独立的样本和区间判断近似并列，完整 18 档也可能改变前沿。[旧板端精度与成本来源](ROUTE_B_MAIN18_BUDGET_SELECTOR_20261111.md)

复用已有 PS／PL 整任务模拟器，4／8 机、相近／错峰释放、旧板端服务耗时 ×1／×1.25／×1.50，各 40 个种子。共 480 个场景，每个策略同样本。窗口仅看一次可编辑更新与每机固定的下一条补更。旧板外的延迟、保持期限、.0055／.008 质量门槛及相位标记均是合成设定。名义决策预留为 0.5 ms。每策略最多 5 次全组检查。预算分给 A／B／C 修复、计划跳过和最多一次质量升级。跳过策略在 A／B／C 仍失败且有剩余检查预算时尝试。

| 策略 | 时序通过 | 同时通过相位规则与代理质量门槛 | 计划跳过次数 | 跳过受保护更新 |
| --- | ---: | ---: | ---: | ---: |
| 固定配置，EDF | 55 | 55 | 0 | 0 |
| A／B／C＋误差门槛 | 325 | 325 | 0 | 0 |
| 上项加忽略相位的跳过 | 327 | 326 | 2 | 1 |
| 上项改为按相位准入跳过 | 326 | 326 | 1 | 0 |
| 按相位跳过，但取消换模时的误差门槛 | 325 | 100 | 0 | 0 |

固定基线的周期为 50 ms，每机初始模型从四档中按种子指定。它用于配对消融，论文中的强静态基线仍需离线选优。完整方案在合格的 326 个场景里，324 个有模型改变、55 个有周期改变、42 个改派发。各动作可重叠。这个负载设置下可换模型是最常用的动作。准入门槛组与成本组的验收采用同一假定误差标准，因此两组通过数反映的是此规则的计算后果。当前回放在运行中没有 UAV 状态演化。

**相位配对例。** 两条任务都在 2 ms 发布，期限 8 ms，其中一架只允许使用 11.783 ms 的模型。若它处在可保持阶段且下一个补更在 62 ms 前能生效，跳过它的这条更新后，两架的保留义务都通过，最小余量约 3.84 ms。只改相位为早弯，方案被相位规则拒绝。忽略相位时相同的删除仍通过时序检查。保持可跳相位、只把补更期限改成 52.1 ms，也会被拒绝。这个例子检验规则的行为，不能估计实际负载出现的频率。

**决策预留是主要限制。** 把同批场景的预留改为 8 ms，并锁定此前已经发布的任务，完整方案只通过 29/480。Windows Python 完整方案 P99 约 6 ms，因机器负载会波动。0.5 ms 结果是理想预算下的机制实验。8 ms 结果显示，需要提前做评估并在发布前提交，或在相同语义下压缩决策路径。合成负载中额外跳过只多通过 1 个场景，目前不足以把跳过包装成主要吞吐收益。

## 6. 文献定位和下一项需要验证的证据

- FALCON 给出 FPGA 上的实时神经控制实现。当前研究在相同硬件资源下问，在线状态是否足以给出可解释的局部改动，并在修改时保留其他回路的补更义务。[FALCON](https://xplorestaging.ieee.org/document/11315118)
- 弱硬实时已有连续丢期限约束与恢复要求。DMAC 早已比较过杀掉任务、跳过下一激活、限长队列等处理。RTAS 2025 的工作从安全控制延时界推导周期性的调度义务。近期也有按系统预测动态选择 overrun 策略的预印本。因此需要拿出证据证明“可撤回的控制义务＋由瓶颈指导的联合修复”具有额外价值。[DMAC](https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.ECRTS.2019.1) · [连续漏期](https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.ECRTS.2020.21) · [RTAS 2025 联合控制与调度](https://www.sudvarg.com/publications/RTAS2025_Integrated_Control_and_Scheduling.pdf) · [自适应 overrun 预印本](https://arxiv.org/abs/2610.18361)
- 真机条件恢复后，用相同 480 条样本的 18 档配对表替代六档假设；先检验每模型服务时长、误差与有效率。用等时延真板闭环绘制单次跳过、补更延迟与净空的关系，至少包含多条未知路线和状态。最后用最佳静态、ABC 无跳过、ABC 忽略相位和相位约束版做配对，在相同资源和候选预算下同时对比安全、跟踪、期限、计划跳过、意外漏更和决策耗时。
- 足以削弱路线的证据包括，在独立路线中相位预测无法识别有害的跳过，同等质量下跳过几乎无可回收的计算量，或者策略耗时吞掉绝大多数可用于提交的时间。无跳过的 ABC＋预算选模可以独立检验。收益应按场景和负载报告。
