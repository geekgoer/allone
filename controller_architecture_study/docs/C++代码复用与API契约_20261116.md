## 3. 重要：Python API参数和C++ API参数不能直接混用

此前文档中的 `roll=u[1], pitch=-u[2], yaw=-u[3]` 是给 **AirSim Python客户端** 的参数；Python客户端内部还会对pitch/yaw取负后发送RPC。

现有C++ AirLib `moveByAngleRatesThrottleAsync()`直接把传入参数放进RPC，没有这一步取负。原 `native_io.cpp` 已按这一差异处理，直接传 `u[1],u[2],u[3]`。

例如物理控制的角速度为 `[0.3,-0.2,0.1]` rad/s：

| 层 | roll | pitch | yaw |
| --- | ---: | ---: | ---: |
| 物理控制量 | 0.3 | -0.2 | 0.1 |
| 本工程传给AirSim Python API | 0.3 | 0.2 | -0.1 |
| Python API最终发送的RPC | 0.3 | -0.2 | 0.1 |
| 本工程应传给AirLib C++ API | 0.3 | -0.2 | 0.1 |

油门映射仍相同：`clip(0.6+(u[0]-9.81)/19.62,0,1)`。

之前fixture中的 `expected_command` 对应Python API层，不是直接用于C++ AirLib的参数。C++实现应核对最终RPC参数与物理输出一致，不能照搬Python层转换结果再直接调用C++库。

核对依据是当前AirSim Python `client.py` 的 `moveByAngleRatesThrottleAsync()`、C++ `MultirotorRpcLibClient.cpp` 的同名方法，以及现有 `native_io.cpp` 的实际下发代码。增量包记录这三份来源的SHA256；没有更改AirSim源码。
