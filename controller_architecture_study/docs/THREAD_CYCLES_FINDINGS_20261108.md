# Windows逐线程周期诊断

本轮固定/动态双机各一次，真实DPU与相同冻结case，开启`--trace-thread-cycles`。默认关闭；`QueryThreadCycleTime`记录线程CPU周期，不能直接转换CPU毫秒、计算等待百分比或作为WCET。硬件频率及系统计数语义仍限制精确比较。

结果：两组均飞行与机身检查通过，严格时序均失败。固定组995交付，1命令返回越期、6 busy丢弃、2推理丢弃；动态组647交付，1命令返回越期、1 busy丢弃，6次周期变更。记录在`results/thread_cycles_20261108_v1/`。单次诊断运行包含插桩开销，不作为策略优劣对照。

这些样本支持线程未执行的等待/阻塞占明显部分，而非CPU工作量随墙钟耗时同比增长；不能据此定位为Windows调度、Python GIL、socket服务端或AirSim，也不能宣称搬到PS就消除。动态本轮历史最大post被抬到90.08ms，固定组准备/post为35.70/31.98ms，说明该成本模型会把等待长尾长期当成共享服务需求。
