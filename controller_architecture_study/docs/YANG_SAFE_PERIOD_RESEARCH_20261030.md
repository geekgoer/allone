# 从有效原型走向控制感知的安全期限

日期：2026-10-30。

## 1. 本次完成和边界

保留原有有效实现，新增独立研究组件，没有把实验性的安全条件直接接管现有 AirSim 飞行。

已完成：

- 冻结上一阶段最终有效代码与结果身份：`results/framework_safe_period_20261030_v1/working_prototype.zip`。原始模型、训练结果和旧飞行日志未修改。
- 控制感知的完整保持窗口安全时间计算；包括有限门框、当前姿态、实际推力/角速度和显式误差界。
- 最低成本合格模式的有界选择接口，明确区分合格、不合格和证据不足。
- 以绝对期限为输入、由释放时间产生 T 的有界联合规划组件。
- 将输入等待保护独立成公共运行时开关，静态方案也可获得同样的优化，旧入口默认行为保持不变。
- 两组历史状态回放、36个状态的候选控制输出探查，以及90个正式配对场景的准备。

未完成：真实飞行器误差界认证、新策略在线接管、具有延迟保证的恢复资格模型、递归可行性，以及270次正式飞行。以下区分数学条件、软件实现和实飞证据，不能互相替代。

## 2. 更简洁的学术主线

建议采用：

> 在当前实际控制仍有有效安全时间的条件下，选择足够完成控制要求的低成本计算，并安排它在该时间耗尽前产生新控制。

运行时不搜索大规模的 `(T,c,σ)` 笛卡尔积：

```text
当前状态、当前实际控制
        ↓
控制相关安全截止时间 d
        +
合格控制器集合 A、测得计算成本 C
        ↓
按成本顺序选择 c；有界联合释放规划
        ↓
段级 EDF 执行；T 由新旧释放时间之差得到
```

同一组安全约束连接 c、响应时间和释放时间。σ 不需要在多种调度算法之间反复搜索：改变安全绝对期限就改变 EDF 的实际顺序；抢占仍只发生在完整的两层 FC 段边界。某个回路不能仅因为 B 大就无条件被抢占，必须检查它剩余工作量与绝对期限之间的余量。

这不是“提出一个新 CBF 公式”就形成创新。已有自触发控制研究了安全时间和动态调度；需要用实验支撑的贡献是计算资格、控制有效时间与共享分段执行之间的联系及其低开销实现。

## 3. Yang 式安全时间的具体实现

### 3.1 没有把原论文公式原封不动贴进 UAV

Yang、Belta、Tron 的 ACC 2019 工作以保持不变的实际控制为条件，对整个保持窗口内的 barrier 约束建立下界，再求安全时间。本文组件采用同样的构造原则，使用适合当前 UAV 接口的多项式下界，而非照搬其一般 Lipschitz 球界。

名义模型在 NED 坐标下为：

\[
\dot p=v,\quad \dot v=g e_3-F R(q)e_3+w,
\quad \dot q=\tfrac12q\otimes[0,\omega],
\]

其中 F 和 ω 是实际下发并保持的推力加速度和右手系 body rates。必须先考虑 throttle 限幅与标定映射，不能直接把未经限幅的 DNN 输出当成实际命令。

误差假设是：相对于上述名义保持模型，实际加速度偏差在完整窗口内的范数不超过 ε；初始位置、速度误差不超过 E_p、E_v。ε 必须覆盖动力学不匹配、姿态/角速度跟踪、执行器滞后、推力标定误差和外扰，而不仅是测得加速度的瞬时差。

固定 F、ω 时有：

\[
\|\dot a_{nom}(t)\|\le F\|\omega\|=:J.
\]

相对于单位法向平面，设 h=nᵀp-b，v_n=nᵀv，a_n=nᵀa_nom(0)，则：

\[
\underline h(t)=h_0-E_p+(v_n-E_v)t+
\tfrac12(a_n-\epsilon)t^2-\tfrac16Jt^3,
\]

\[
\underline {\dot h}(t)=v_n-E_v+(a_n-\epsilon)t-\tfrac12Jt^2,
\qquad
\underline {\ddot h}(t)=a_n-\epsilon-Jt.
\]

使用高阶 barrier 条件：

\[
\psi_1=\dot h+\kappa h,\quad
\psi_2=\ddot h+2\kappa\dot h+\kappa^2h.
\]

初始 h、ψ₁ 合格，并在完整窗口内满足 ψ₂≥0，即可在该模型假设下保持 h≥0。证明是两次比较：ψ₁′+κψ₁=ψ₂≥0，因此 ψ₁≥0；再由 h′+κh=ψ₁≥0 得 h≥0。

代码把 ψ₂ 的三次多项式下界中正的一至三次项舍掉，得到单调不增的保守下界。正系数被舍去只会更保守。最多24次向下取界的二分得到整个前缀的安全时间，而不是只检查离散采样点或末端。若某个平面在整个最大窗口都满足这个单调下界，直接走快速路径，无需求根。

κ 是 barrier 设计参数，不是任意固定的“两秒预览”。当前 κ=10/s 是开发选择，正式实验前须冻结，并用独立开发场景检查其保守性，不能在正式结果上寻找有利值。

### 3.2 有限门框，而非无限横向墙

安全对象是四根实际有限长的门框。几何复用 `gate_visualization._gate_parts`，按无人机球形包络半径与额外余量膨胀每个盒体。

对于一个盒体，只要六个外侧分离平面中至少一个在整个窗口保持分离，就不会碰到这个盒体。因此一个盒体取六个平面安全时间的最大值；所有盒体同时要避开，再取最小值。这里的 max 是对同一个障碍物的“或”，并不是放松不同安全约束。

这允许无人机在门前暂时位于未来门洞的侧面，避免旧的无限门洞走廊把合法转弯直接标成越界。球形半径0.50m、额外余量0.025m继承现有协议，仍是需要核实的包络假设。本组件未覆盖地面、场景其他物体或机间碰撞；当前独立航道实验仅声明门框接触范围。

### 3.3 何时才算严格

软件已经实现的是“假设成立时的完整保持窗口条件”。目前不宣称真实 AirSim/硬件闭环已获得安全证明：

1. ε、初始误差和机体包络尚未认证。
2. RPC 返回时间只是生效时间代理，必须有延迟不确定性的上界。
3. 实际系统必须确保分析对应的 held-control 序号仍是当前控制；若分析期间已有新命令生效，不能把旧控制的预算装给新控制。
4. 新命令真正生效时的状态必须被覆盖；不能把数毫秒前的状态无误差地当成当前状态。
5. CPU 的经验响应时间不是 WCET，Windows 也不是硬实时执行平台。

当前配置始终保存 `plant_bounds_verified=false`，不借由测试通过改变该标记。B=0 表示当前充分条件不能给出证书，不等于物理上已经碰撞或必然无法恢复；实验探索可继续，但必须标明当时没有安全保证。不能为了飞完就把 B 人为夹成20ms。

### 3.4 时间线

令 s 为新鲜状态的实际采样时间，a_k 为当前控制生效时间，则：

\[
d_{k+1}=\min(s+B_s,\ a_k+H_{ctrl}).
\]

该预算是从 s 开始的“剩余保持时间”；不能把它再加到更晚的分析完成时间上。调度要求下一次新控制在 d 前生效。若把 T 定义为两个 release 的间隔，还应保留：

\[
a_{k+1}-a_k=T_k+R_{k+1}-R_k,
\]

所以绝对时间戳形式比不带时间原点的 T+R 更直接。安全时间从 actuation 计算时，T+R 可以采用明确说明的保守关系，但不能混淆 release 和 actuation。

### 3.5 是否加入 DNN–MPC 误差

用户已允许加入。当前安全时间直接检查实际 DNN 控制，所以不需要再把 DNN 与 MPC 的输出差额重复计为物理加速度扰动。该误差更适合辅助跟踪/恢复资格筛选：能安全保持的命令不一定能完成任务。后续若用 MPC 作为名义控制来建立候选网络的误差包络，则必须显式传播这个误差，不能以平均 MSE 冒充逐状态上界。

## 4. “最低成本合格模型”的做法

数学目标为：

\[
c^{sel}=\arg\min_{c\in\mathcal A(x,\bar\delta,H)} C(c).
\]

合格集合必须同时满足控制质量/恢复要求和适用的延迟、更新间隔、输入年龄范围。不能假设深层一定优于浅层，也不能把较小 MSE 当成安全证据。

新增两个组件：

- `cost_ordered_modes.py`：按实际测得成本排序，有界扫描资格；未知结果不当作否定或合格。遇到未知/预算耗尽可明确返回基线，而不是终止飞行，但该返回不能称为有保证的合格选择。回调超时会记录并弃用结果，不伪称 Python 能瞬间抢占一个耗时回调。
- `probe_qualified_modes.py`：在历史实飞状态上实际计算候选输出，复用 barrier 与同一动力学误差界，检查50ms保持安全和末端跟踪误差上界。它是局部控制输出探查，尚不是全局恢复判据，也没有覆盖“等一段时间再接管”的状态变化。

推荐部署路径：离线建立覆盖延迟的恢复/质量资格契约，在线仅检查少数便宜资格条件，再对实际输出做一次控制感知安全检查。这样无需每个周期把8个乃至136个网络全部算一遍。

进一步需要严格资格时，可以使用同一旧控制可达管，把候选生效前的状态集合传播到候选接管时刻，再检查候选在整个该集合上的条件。这是复用同一模型，并非增加一个独立的大型预测器。但在姿态跟踪/执行器误差界尚未确定时，不能跳过这一步直接声称资格严格成立。

本次36个状态的探查：29个由测得成本最低的3×256模型满足局部条件，另外7个在全部8模型探查中均未满足。多数失败来自跟踪末端界，部分还来自过短的 barrier 窗口。**尚无证据证明这些状态必须使用大模型；更不能把这36个点当成恢复热图或正式控制结论。**

一个值得保留的联合优化方向是区分“单次最便宜”与“单位控制时间计算最少”。假设两个已验证的质量契约分别允许小模型1ms/20ms更新、大模型2ms/80ms更新，后者的平均计算需求反而更低。这只是说明性的假设，不是当前模型的测量结果。若这种差异在离线延迟/更新资格实验中存在，可以用 `(C_c+C_frontend)/H_c` 为少量合格模式排序；无需搜索所有 T。但 H_c 必须是覆盖状态变化与接管延迟的资格契约，不能拿当前旧控制的 B 冒充下一模型的未来安全时间。本阶段先保留原最低成本目标，不凭假设更换评价目标。

全候选探查平均4.24ms、P99约19.70ms，明显不适合20ms任务。优化快速路径、固定独立核心并把检查数限制为2后，平均0.574ms、P99约1.507ms；含被拒绝模型的实际推理耗时也已计入。两次测量的实现/核心条件不同，因此不能把差异全部归因于“只检查两个”。

## 5. T 不再只有20/60ms

新 `bounded_release_planner.py` 不按危险标签选20或60，而是：

1. 每个回路已有绝对截止时间和候选 c；已发布任务保持冻结。
2. 根据当前计算与 I/O 成本形成最早合法 release 和孤立情况下的最晚候选。
3. 对整组回路最多尝试5组候选释放时间，从较晚候选向较早候选收缩；每一组都经过前端、后端和段级 EDF 的联合预测。
4. 检查持续需求及全部已知未来承诺，不能独立把每个回路都安排在自己的最晚时刻。
5. 成功后 T=r_next-r_previous，可为27.3ms、43.8ms等，不限两个档位。

这是有上限的可行性搜索，不是数学意义的最晚释放或全局最优。规划预留5ms，计算本身一旦超出预留就不能提交该预测。固定最多5次不代表 Windows 下真实耗时有硬上界。最终仍需现有 C++ 整组原子提交和发布序号校验，不能局部安装。

它目前是独立组件，尚未替换旧试飞循环。有限下一组预测加持续需求筛查仍不是无限任务序列的可调度性定理；硬实时结论需要进一步的执行时间界与可行域约束。

使用现有冻结CPU成本的18组合成调度探查已执行。规划最多5次，实际测得最长约2.26ms；确实产生35.42、55.63、70.63ms等释放间隔，并保持原模型、作业ID和绝对期限。部分组合未找到可行安排，未扩大期限或强行输出“安全”。这些是有限作业合成调度数据，不是18组实飞；失败也可能来自候选数量或成本包络保守，不能自动判定物理不可行。

c 与释放时间的联合关系来自共同约束：资格决定允许用哪些 c，c 的成本改变响应时间，响应时间改变可释放时刻，绝对期限决定 EDF 顺序。第一版无需再搜索调度算法排列。

## 6. 实际测得开销

安全分析最终快速路径版本，进程固定在逻辑核心12，未启动 AirSim、新训练或 GPU 推理：

| 历史运行 | 状态数 | 平均分析 | P99分析 | 最大分析 | 无法给出20ms窗口的状态 |
|---|---:|---:|---:|---:|---:|
| seed4 联合动态 | 859 | 0.151ms | 0.446ms | 0.768ms | 63 |
| seed5 联合动态 | 973 | 0.157ms | 0.435ms | 1.106ms | 85 |

这些是历史状态回放中的经验值，不是运行时新闭环时延或 WCET，也没有包括状态采样、输入构造、DNN推理、排队和命令发送。

开发敏感性假设：ε=2m/s²、位置误差1cm、速度误差0.05m/s、最大保持150ms。采样点瞬时加速度残差最大约0.389/0.573m/s²，低于2；但这并不证明完整保持窗口内的误差界有效。

移除的是“额外固定两秒预览作为触发器”的依赖。原237D网络输入本来包含2秒左右的参考窗口，其训练契约保持不变；不能把这两种预览混为一谈。

## 7. 扩大实验已经准备到哪里

`campaign_protocol.json`冻结90个配对场景：

- 3、6、10架活跃无人机。
- 平缓、长平稳前段后接急弯、按比例分配的异质路线。
- 每组10个预留种子1000–1009；开发/静态选择使用独立种子101、102。
- 每条路线10个真实门，改变门间距、弯向、幅度、危险段起点；3机混合路线也包含全部三类。
- 速度5m/s、门洞净宽1.7m、没有外部冲击、没有虚拟前缀或虚拟J。

90条场景参考轨迹已作有限采样的定义域检查：最大速度约5.317m/s，最大分量加速度约4.409m/s²。它说明参考值没有明显超出当前教师训练范围，但不是连续时间参考界证明或实际教师试飞。汇总不同路线族时，宜按场景种子聚类估计不确定性，避免把共享随机因素的运行当成完全独立样本。

策略为离线静态、路线预先计划、实际状态反馈。三者共用 C++ I/O、前端等待保护、即时完成、模型池、核心资源和队列规则。碰撞只退出对应无人机，后续负载改变须记录。

正式飞行尚未开始。不能把准备90份JSON算作90个实飞结果，也不能直接在新路线使用旧路线选出的静态配置然后称“离线最优”。静态必须在独立开发场景、同一资源条件下重新选择；20次搜索是预算内最好，不是全局最优或完整 FALCON SVM。

保留包是代码快照，模型仍由原始路径与哈希引用，没有复制或修改大型训练权重。

## 8. 后续实施顺序

1. **误差界与时间语义**：检查完整保持窗口误差、控制序号与实际生效延迟；冻结开发模型和适用域。不因采样点残差小就打开认证标志。
2. **单回路接入**：新 barrier 先影子运行；判断零预算原因，区分模型/充分条件保守、状态已出可认证域、时序真的不足。不要先调参找有利碰撞。
3. **资格与延迟**：为候选 c 补齐接管延迟的状态集合传播及跟踪/恢复条件。先两候选，记录包括失败尝试在内的全部开销；大模型无优势也如实报告。
4. **释放规划接入**：使用新 release-first 组件，保留独立硬编码 release 日历、段级抢占与整组原子提交；先确认其他回路承诺未被破坏。
5. **小规模协议检查**：独立开发场景核对完整评分、自然路线可飞性和静态搜索。此步骤的通过条件不是“静态一定撞”。
6. **冻结并执行90个配对场景**：三策略270次，按完整场景做配对统计，同时报告碰撞、任务完成、J、控制空窗、期限违约与实际配置生效延迟。
7. **FPGA阶段**：替换真实板端段成本、I/O与上下文保存代价；量化/超网加入同样的输出资格接口，不把CPU数据当成板端实时保证。
