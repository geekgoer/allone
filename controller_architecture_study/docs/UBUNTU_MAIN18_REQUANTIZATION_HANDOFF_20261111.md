# Ubuntu 交接｜重做 Main18 的 INT8 量化与板端验证

日期 2026-11-11。目标平台为 AXU3EGB B1152、PetaLinux 2020.1 和现有 Vitis AI 1.2.1 CPU Caffe／DNNDK 工具链。

## 任务与当前基线

请为同一组 18 个独立的 237D FP32 模型重新生成一套 INT8 候选，目标是降低真实板端误差，让同一样本上的模型精度排序尽量接近 FP32。主实验采用同权重的训练后量化（PTQ），冻结模型结构、FP32 权重、237D 输入契约、四通道控制标签和归一化。先定位误差出现的阶段，再调整量化。若同权重方案仍有明显损失，再单独尝试量化感知微调（QAT）。最终提交逐模型结果、可复跑命令和独立板端候选包。

现有 5237 服务的同样本对照来自 480 条验证样本。下表的 MSE 均按冻结训练集输出标准差归一化。

| 板端 ID | 模型 | FP32 MSE | 旧板端 INT8 MSE |
| ---: | --- | ---: | ---: |
| 5 | 2×128 | 0.001343310 | 0.009256300 |
| 10 | 3×256 | 0.000593739 | 0.006669738 |
| 11 | 4×1024 | 0.000324923 | 0.013615234 |
| 16 | 6×1024 | 0.000271971 | 0.009203549 |
| 2 | 21×1024 | 0.000287821 | 0.081738690 |
| 6 | 33×1024 | 0.000352461 | 0.187368458 |

全 18 个模型上，MAC 数与 MSE 的 Spearman 相关在 FP32 为 **−0.746**，旧板端 INT8 为 **+0.715**。逐模型 FP32 与旧 INT8 MSE 的排序相关为 **−0.247**。这些数值把问题定位到了 FP32 与板端之间，具体环节由下面的逐级对照确认。实际目标是恢复板端精度和减少有意义的排序反转，保留真实的非单调性。[基线与同样本对照](ROUTE_B_MAIN18_BUDGET_SELECTOR_20261111.md)

1. **校准和权重微调**使用原 TRAIN 4096 校准输入。需要扩大覆盖时，从 TRAIN 按 `family_id`、环境、状态误差及参考速度分层补样。另留一块独立的训练内保留集供定点位置、校准方案和微调轮次选择，记录抽样种子及行号。保留相同 237D → 240D 补零顺序和既有 `x_mean/x_std/u_mean/u_std`。

3. **额外边界回归**可复用 ID 11 历史 37 条问题样本，单列状态码、范围和误差。曾用于校准的样本标为回归集。误差统计采用旧、新与 FP32 都有效的配对行，同时报告每个模型的有效率和全池共同有效行数。拒绝、超时和输入饱和按原原因保留，采用相同的运行时输入检查。

## 1. 先定位误差出在哪一步

先跑 **ID 5、10、11、16、2、6** 六个代表档位。同一批原始输入依次跑下列四个阶段，逐样本保留四通道输出。定位阶段使用训练内保留样本和共同黄金样本。

| 阶段 | 检查内容 | 若首次出现明显差异 |
| --- | --- | --- |
| A · 原始 FP32 | 冻结模型基准，保存标准化输出和还原后的物理控制量 | 检查模型与归一化身份 |
| B · 导出的 Caffe FP32 | A／B 对齐，检查首层 237→240 补零、各层 W/b、激活、通道顺序、输入归一化和输出还原 | 修导出或预处理，先恢复黄金向量一致性 |
| C · Caffe 定点仿真 | 用实际 FixedNeuron 语义和同一套输入比较 B／C。先以官方固定点图验证快速仿真器，再拿快速仿真筛候选 | 导出逐层定点位置、量化步长、激活范围和饱和比例，定位首个明显误差层以及误差是否持续累积 |
| D · 真实板端 | 核对 C／D 黄金向量，记录编译器 topology、kernel/node、实际 I/O 尺度、整数码与物理输出。分开记录板内服务与 UDP RTT | 查编译后的移位或融合、实际输入量化舍入、尺度方向、输出布局和反量化 |

重点检查 ID 6 与 ID 2。判断某层出错时，用同一组层输入分别跑 FP32 与定点计算，再结合端到端误差找出误差从哪里开始累积。对终端输出额外检查四通道各自的误差与饱和比例。FP32 导出沿用旧脚本的黄金向量容差，另记录最大绝对误差。板端对同源 INT8 参考最大绝对误差采用原流程的 **≤1e−4**。在同一输出坐标、单位和黄金输入上分别报告这两项一致性检查。[旧流程及黄金校验](../../ubuntu_transfer/RUNBOOK.md)

## 2. 重新量化，先试六档再扩到 18 档

1. **复刻旧量化作为对照。** 对六个代表模型保存旧校准数据、官方量化选项、产物哈希和测量输出。每次实验使用新的工作目录或新 attempt，逐模型记录实际命令。
2. **先比较官方 PTQ 的两种校准取舍。** 在容器中用 `vai_q_caffe` 的帮助核对实际支持的参数。已验证的命令使用 `-method 1`。若实际版本支持 `-method 0`，用**相同输入、批次和迭代数**分别比较。再保持方法不变，对照原 TRAIN 4096 和按状态族、速度及恢复误差分层补样的 TRAIN 校准集。记录批次构成、大小和实际迭代数。旧 FixedNeuron 会按批次统计定点位置，只把少量边界输入加在尾部未必足以改变最终位置。
3. **按定位结果调整定点位置。** 若误差主要出现在终端，复用 ID 11 已验证的流程。基于同源 INT8 前缀的预量化输出，在训练内保留集枚举邻近的终端 FixedNeuron 位置，先检查范围，再比较对 FP32 的输出 MSE 和对教师的 MSE，最后用官方 deploy 和 compile 生成候选。若误差在隐藏层累积，针对第一处异常层及相邻层小范围扫描，逐次验证编译、官方定点仿真和真板一致性。每次调整保存层名、旧／新位置、尺度、饱和率、命令和结果。
4. **PTQ 仍不能恢复时，单列 Caffe 量化微调。** 先对 ID 6 或 ID 2 试少量轮次，使用原 TRAIN 输入、教师标签、可审计的四通道回归损失和小学习率，保留原 FP32 checkpoint 为参考。保存微调得到的权重和父哈希，单列为 QAT 候选，分别报告其浮点参考和实际板端表现。18 模型的同权重 PTQ 表单独保留。版本与格式按现有 CPU 容器实测。[AMD Vitis AI 1.2 Caffe 量化微调](https://docs.amd.com/r/1.2-English/ug1414-vitis-ai/vai_q_caffe-Quantize-Finetuning?contentId=9ggu44OCja6qRT5uX7KnBA)
5. **扩到全部 18 项。** 在训练内保留集冻结每模型的候选方案，优先用已在代表档位有效的配置。每模型至少交付一次重测记录及结果。失败项附失败阶段与证据，继续完成其他模型，最终仍报告完整 18 项和有效覆盖率。

## 3. 怎样验收“趋势接近 FP32”

对于模型 $m$，用共同样本、相同四通道标准差 $s_k$ 计算

$$
E_m(u)=\frac{1}{4N}\sum_{i=1}^N\sum_{k=1}^4
\left(\frac{u_{m,i,k}-u^{\mathrm{MPC}}_{i,k}}{s_k}\right)^2 .
$$

表里给出 FP32、旧 INT8、新 INT8 三列，并额外算新、旧 INT8 对同源 FP32 输出的标准化 MSE。推力和角速度各用物理单位单列 RMSE、P95／P99 绝对误差。按 route 或状态族给出分组结果和有效样本数。报告服务 P50／P95／P99、RTT 与旧／新成本—精度 Pareto 前沿。对照时统一 MAC 口径。

- **先过数值与覆盖。** 黄金向量和模型身份对齐，报告每模型有效率与 18 模型共同样本数。旧池在上述 480 条上全部有效。若新池发生拒绝，先报覆盖差异，再报共同样本误差。
- **确认大档位确实变准。** 至少单独报告 ID 2 和 ID 6 相对旧部署的误差变化，也报告 ID 5 和 ID 10 的绝对误差变化。每模型选择以降低真实误差为目标，固定原 FP32 参考与样本集合。计算量相近或误差接近的档位允许互换名次。
- **整体趋势用两个量表达。** 报告 $\rho(E_{\rm FP32},E_{\rm new})$ 衡量排名相似度，再报告 $\rho(\mathrm{MAC},E_{\rm new})$ 衡量容量趋势。阶段性目标可以预先定为前者 **≥0.6**、后者 **<0**，同时要求 ID 2、6 的旧板端误差各下降至少 **50%**、ID 5 和 10 的核对组 MSE 各增加不超过 **5%**。这些是本轮工程目标，物理安全由后续闭环另验。冻结候选后统一计算。若部分达成，逐项报告实际改善和阻塞原因。
- **给 Windows 留下可接入的档位。** 给出 Pareto 模型的 numeric ID、核对组误差、板内服务时延及建议初始预算范围。Windows 再用与旧实验相同的路线、\(T\) 和命令施加时刻复验过门净空与切换，随后接入真实调度预算。
