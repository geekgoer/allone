# 自然长路线演示：实现与实测记录

目标是“按全程总J选择的固定配置在末段触框，动态配置完整通过”。未实测达到这一条件前，不把入口称为成功演示。FPGA迁移仍暂停。

## 实现

- 七机，共用同一CPU推理资源；神经网络在完整的两个FC计算段之间调度，当前job内不改模型。
- 约40秒、17门。前面新增12段匀速直线，再接已有环境48路线13的连续弯道。参考轨迹C2连续。
- 初态为参考轨迹上0～2.1秒的正常相位，不添加初始跟踪误差；飞行后没有侧推、风或状态写入。
- 静态搜索包含9×512、9×1024、21×1024三个237D模型和20/40/60/80ms，共12个公共配置。它是限定候选集的全程选型，不是完整FALCON所有逐机配置和硬件的数学全局最优搜索。
- 只在完整、时钟有效且没有超期、未交付或跳过更新的候选中选择总J最高者。安全接触另报，不按“是否会撞”挑候选。
- 离线测量跑完整个公共时窗，碰撞后仍保留后续轨迹。正式演示首次接触后立即暂停整个仿真，终端打印飞机、门框和时间，查看后按Enter才继续。暂停后的时间不补成飞行成绩。
- 动态采用风险相关周期、段边界EDF和按下一job生效的模型选择；没有MPC后备接管，也不因模式表缺记录中止。

## 性能函数口径

重新查看了FALCON原PDF第5页Eq.(4)：J是20步预测窗口内加权状态误差和的倒数。该公式没有单独规定新增长路线的跨窗口汇总方式。

本实验继续使用已声明口径：位置3D、速度3D、同号对齐四元数4D，Wx=I，公共20ms网格，21点窗口成本先平均再取倒数，各机求和。不为找到反例改成“各窗口倒数先平均”。这是Eq.(4)形式的工程评估，不是原论文全部数值细节的复现。

## 修复与在做的开发检查

1. 越过预留边界后，即使逼近速度降到零，也保持20ms，不立即放宽周期。
2. 跳过的计划更新计入时序失约。
3. 控制RPC先读到接触并暂停、独立传感器尚未取下一帧时，接触事件仍计入碰撞数。
4. 接触暂停后的未来未完成请求不算作暂停前已发生的超期，原始请求日志保留。
5. 窄门正常余量约0.275m，固定0.3m阈值会把正常状态长期判成恢复状态；新`relative_preview_v2`规则使用相对于可用余量的阈值，并在识别困难模式时同步收紧周期。没有按门编号硬切换。

相关回归检查16项通过。修正后的两次动态开发飞行在`results/long_route_relative_preview_20261027_v3`，旧数据不覆盖。两次均完整、零接触、净空通过，J分别为2.235739、2.245292，但各有90、76次超期／缺失更新，不能称为完整实时验收通过。巡航／恢复模型两种模式均实际执行，已经消除了窄门正常余量被长期误判的问题。

候选D使用参考曲线3/4位置、门面法向沿参考速度、净宽1.8m：
`results/long_route_tail_gate_screen_20261027_v5`。

该次静态沿用9×512、60ms，在Drone7第15门触框；动态七机完整通过、零接触、原净空检查通过，J=2.206984。但静态有24次时序问题，动态也有363次，所以它只是一条需要进一步检验的发现，绝不能直接宣称“FALCON最优静态被救回”。

为排除选弱基线，已在D场景重新评估全部六种FALCON规模模型（9/21/33隐藏层×512/1024宽度）与20/40/60/80ms，共24个有限候选。原始记录在：
`results/long_route_tail_final_search_20261027_v6`。

结果：最优候选是9×512、60ms，J=2.130154，没有接触。正反序两组的静态和动态都完整通过，因此该场景仍不是救回案例。动态J=2.229323和2.216577，但存在时序失约。没有把原先静态碰撞的单次结果冒充复核通过。

## 平缓段长度敏感性与长路线实测

`results/long_route_prefix_sensitivity_20261027_v7/report.json`检查了完整有限时间窗内的应释放请求，计入缺失和超期。原24候选中三个候选在该轮校准没有失约：

| 静态候选 | 原全程J | 原场景接触车辆 | 平缓段平均状态成本 |
|---|---:|---:|---:|
| 9×512 / 60ms | 2.130154 | 0 | 0.006085 |
| 9×1024 / 80ms | 2.104607 | 7 | 0.005700 |
| 33×512 / 80ms | 2.068426 | 7 | 0.005846 |

保持性能汇总公式不变，用8～20秒实测稳态成本估算延长路线：增加210秒才预测到前两者排名翻转；增加336秒时，预测9×1024/80ms的J=15.157079，9×512/60ms为15.058634。它只是选取后续实验长度的估算，不是已经飞出的结果。

据此把先前126秒的实用上限修订为336秒，并在新飞行之前存入plan。新路线共约375.734秒：12段直线各30秒，仍然17扇门、同样5m/s巡航、同样末段曲线和1.8m门洞。没有在飞行中平移无人机或快进仿真。代码为`long_route_prefix_search.py`，轨迹延长与末段动力学保持的回归检查新增一项，共17项通过。

新实测目录为`results/long_route_extended_prefix_20261027_v8`。比较三个已冻结容量域中的候选，按新路线完整实测J选最高者，不按碰撞筛选。若最高者有接触，再冻结选择并做正反序配对；若最高者本来安全，仍判为没有找到救回演示。

这里的容量域来自原24候选的一轮实测，**不是WCET证明**；新长飞行发生的超期全部保留。它是已校准有限域中的局部离线选型，不能称作完整FALCON全局最优。动态目前也存在经验预算与实际响应的偏差，物理零接触不等于时序或严格安全证明通过。

### 长飞行记录器的终点问题

第一项9×1024/80ms已完整记录，全程J=15.633013，七架有接触，7次名义时序失约。第二项9×512/60ms控制流程完整、无接触，但独立记录缺少最后约半秒。仿真／电脑时钟比约0.99869，在375秒上累计约0.49秒；旧记录器只采到电脑时窗结束后0.2秒，因而不能覆盖仿真终点。原报告保留`complete=False`，没有直接改成通过。

记录器已改成每架飞机实际仿真时间覆盖任务终点后才停止采样，仍用原20ms间隔。为比较本轮已记录的数据，`long_route_endpoint_repair.py`取**三个候选全部飞机**实际覆盖终点的最小值，向下取整到完整21点评分窗口。该规则不读取碰撞或J，且必须覆盖完整过门任务与至少0.25秒终端保持，否则拒绝重评分。不外推、填补缺失尾部，不覆盖原报告。后续新飞行直接使用修正后的记录器。

同时把预期门列表和飞行后的门平面检查改成批量平面预筛，候选交点仍调用原函数，接触判定仍来自AirSim真实事件。它只减少初始化和事后分析耗时，不改变控制器或在线调度。旋转门框及近零平面边界的等价性检查通过；相关检查共27项通过。

## 已得到的自然飞行物理配对

重评分及新配对：`results/long_route_extended_prefix_20261027_v9`。共同评分时窗375.06秒，前362.33秒参考时间属于启动与平缓段，末尾为原曲线。所有候选、所有飞机均实际记录覆盖该时窗，且所有门均在其中。模型、门洞、Wx及评分聚合方式不变。

| 校准域内静态候选 | 共同时间窗J | 有接触的车辆 |
|---|---:|---:|
| 9×1024 / 80ms | 15.618300 | 7 |
| 9×512 / 60ms | 15.535885 | 0 |
| 33×512 / 80ms | 15.334066 | 7 |

冻结校准域内选择9×1024/80ms后，新做了一组反序配对（动态先、静态后），相同初态已核对：

- 动态：7机完整通过，零接触，过门净空及终端跟踪检查通过，J=16.449741。独立记录完整，记录器的终点问题已修复。
- 静态：Drone1在364.222770秒接触第15门左柱，`collision_flag=True`。随后读回`simIsPause=True`，确实在接触时暂停。它没有跑完整个时窗，**不把暂停前的短轨迹补成全程J**。
- 动态请求周期20～80ms，平均实际命令间隔约42.5～42.6ms；前述响应预留值较保守，使平缓段实际更新也快于80ms。
- 本配对巡航与恢复均用同一个9×1024 DNN，没有模型切换，也没有MPC后备。收益主要来自更新时机和段间EDF，不能把它归因于超网。
- 动态执行485次段间恢复；经验物理预算主导178/61694次分析。仍有324次实际期限失约，其中114次越过名义期限；严格实时／物理安全保证没有通过。

### 强基线审计仍是必要条件

上述是**校准域内的一组物理救回**，不是完整FALCON的反例。原校准中9×1024/60ms因2次失约被排除，但80ms新长飞行也发生了失约。若只依赖这一次排除，就有选择较弱静态基线的风险。

因此追加`long_route_static_check.py`，在同一375.06秒任务、相同模型、CPU布局、记录器、评价公式下完整测量60ms。结果在`results/long_route_stronger_static_20261027_v10`：**完整通过、零接触、净空和终端跟踪通过，J=16.014146**，有35次名义时序失约；平均R=6.973ms，p99=13.268ms，最大118.407ms。

因此必须否决“80ms代表合理离线最优”的说法：60ms既安全，J又比80ms高约2.53%。动态J比这个强静态高约2.72%，但平均更新更频繁，计算次数也更多，尚未在共同容量限制下证明净收益。**当前没有完成用户要求的“公平离线最优静态撞门、动态安全”的研究反例。**

原24候选一次校准的零失约筛选会把偶发OS抖动误当作容量差异，不能据此永久排除60ms。动态也仍有期限失约。不能一边以静态偶发超期为由删除强候选，一边忽略动态的超期再宣称公平胜出。物理演示保留；完整FALCON、可调度性和安全保证的更强结论收回。

## 12机扩展与本轮明确未解决的问题

短路线使用相同的17门D几何、没有额外336秒前段，count改为12。它是发现性检查，没有完成12机下的全部候选离线优化。记录分别为`results/twelve_natural_capacity_20261027_v11`、`results/twelve_same_model_20261027_v12`、`results/twelve_deadline_frontend_20261027_v13`。

| 12机策略 | 完整物理通过 | 接触 | J |
|---|---|---|---:|
| 同模型固定40ms | 是 | 无 | 3.870912 |
| 同模型固定60ms | 是 | 无 | 3.763295 |
| 小模型巡航／大模型恢复＋动态周期 | 否 | Drone1第15门左柱，28.209602秒 | 不补全 |
| 全程同一大模型＋动态周期 | 否 | 同一处，28.188601秒 | 不补全 |
| 全程同一大模型＋动态周期＋前端期限排序 | 否 | 同一处，28.209602秒 | 不补全 |

所以这次失败不能简单归因于独立模型切换，也没有因为把前端改成EDF就解决。分析决策平均约0.4ms，不能把这次瓶颈说成T/c搜索太慢。

在Drone1的24～28秒关键段，同模型动态实际命令平均间隔33.27ms，最坏86.79ms；固定40ms平均40.03ms、最坏53.26ms。**平均更新更快但最坏空窗更大**，这正是不能只看平均R或请求T的原因。最坏动态空窗分解为：

- 计划等待34.812ms；
- 任务到释放时间后仍等待36.254ms；
- 采样／计算／命令返回15.717ms；
- 其余分派约0.003ms。

此前那条命令的后续回读只1.667ms，前端结果等待0.330ms，处理0.819ms，**新计划并非生成时已经过期**。不能把36ms都算成回读或输入构造。在该关键段，推理队列最大约5.25ms，也不是DNN自身排队86ms。

前端期限排序将对应最坏间隔中的释放迟到降到13.079ms，但下一响应增至35.976ms，实际空窗仍83.875ms，物理仍失败。当前证据不能把全部延迟直接归因于OS或某个单一函数；有限事件排序不足以保证整个前端／I/O／计算流水线可行。

### 阶段结论与接下来真正需要的修改

1. 保留已实现并实测的自然飞行物理对照、触框暂停、修复后的记录器。
2. **不宣称已经找到公平FALCON离线最优静态碰撞、动态安全的反例。**7机有更强安全静态；12机当前动态反而有碰撞。
3. 原型当前是经验风险周期＋可选模型＋段间EDF，尚不能等同于Framework_latest中“全局可行后再提交释放计划”的完整实现。所有动态期限都仍有失约，不是安全证明。
4. 下一步应先补全前端／I/O／计算一起核算的全局释放可行性，约束多个回路同时缩短周期的需求，并检查实际相邻控制生效代理间隔。不能只在推理段之间换顺序，也不能继续缩门来掩盖这个缺口。
5. 静态和动态必须使用同一容量判断口径，再重新优化静态。不能用一次零超期校准排除强静态，却允许动态大量超期后仍声称公平安全优势。

审计原始数字在`results/long_route_extended_prefix_20261027_v9/claim_audit.json`；简明说明在`docs/LONG_NATURAL_DEMO_EXPLAINED_20261027.txt`。

## 入口与复现限制（说明）

`controller_architecture_study.long_route_demo`提供搜索与触框暂停演示；`--confirm`进行非交互的正反序配对。`--selection`会校验模型与源文件哈希；规则修改后旧selection会拒绝直接当作同版执行，不能为了运行而删除校验。

物理演示入口可以观看固定80ms与动态的差别；最终“离线最优被救回”的研究结论仍需通过强基线和统一容量域审计。不能把固定较慢配置、单机通过或仅平均J提高当成已经完成用户要求。
