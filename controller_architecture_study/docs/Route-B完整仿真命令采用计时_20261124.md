# 在 Blocks 里记录哪条命令真正被飞控采用

## 这次测量什么

之前的板端程序把命令发给 AirSim，然后发一个 `ping()`。我们已经在隔离的 AirLib 程序里看到 `ping()` 和飞控用上命令可以有不同的先后顺序。这一次把两者放进完整 Blocks 仿真测量，地图沿用 `/Game/FalconEmpty`。[前一轮隔离验证](Route-B命令确认与生效计时_20261124.md)

测试程序给每条命令一个唯一序号。服务端记录进入 RPC、SimpleFlight 接受这个目标、以及首次在这个目标下执行整次固件更新的开始和结束。固件更新包括写入模拟电机输出。测试只记录启用 API 控制、目标和模式仍匹配该命令的更新。如果某条命令提交后没有观测到匹配的固件更新，它单独记为「只看到目标」或「只看到 RPC」。这是**仿真里的采用证据**。它没有测真实电机响应，也没有验证无人机安全性。

客户端还记录 `ping()` 返回。两端的单调时钟用多次 RPC 估出偏差范围，不确定的样本标为跨线。比较 20 ms 时同时记录两种起点。一种从提交命令算起，用于判断下发段。另一种从周期的名义发布时间算起，把采样和发布迟到也计入。最终版探针在采样前与提交前分别检查期限，过期立即跳过当次任务。

## 实测结果

**受控对照确认序号能把两类延迟分开。** 单机每种情况运行 12 次。正常的 12 条都在提交后 20 ms 内采用。40 ms 加在命令处理前时，12 条的 `ping()` 都按时返回，12 条都晚采用。40 ms 加在实际 `ping()` 返回之后时，12 条都按时采用，调用方记录的 12 次确认都晚了。

**最终默认负载仅一次确认超过 20 ms。** 两次早期筛查分别发出 13,000 条和 15,600 条，最大的提交到 `ping()` 时间分别为 18.721 和 17.820 ms。使用最终的过期跳过规则复跑十二机，10,800 条均提交，按发布时间算也全部在 20 ms 内采用。最慢的一条是 Drone6 第 894 周期，`ping()` 在提交后 **24.654 ms** 返回，固件更新在提交后 **最迟 1.468 ms** 已完成。

**限制诊断副本为两个逻辑核后，两种分歧同时出现。** 当轮十二机共有 10,800 个发布时间，1,277 次在采样前超期，4,737 次在准备后超过期限，仍提交 4,786 条。按提交后 20 ms 看，2,288 条按时采用，2,313 条晚采用，17 条的计时区间跨线，168 条只看到目标写入。1,489 条 `ping()` 超过 20 ms，其中 **450 条飞控按时采用**。另有 **1,330 条 `ping()` 及时、飞控采用却迟到**。

限 CPU 并启用过期跳过时，提交到 `ping()` 在 37～40 ms 的命令有 46 条。按提交后 20 ms 判断，10 条按时采用，36 条晚采用。下面是两个 `ping()` 时间相近的实测例子。

| 命令 | 提交到 `ping()` | 提交到首个固件更新的时刻区间 |
| --- | ---: | ---: |
| Drone1 第 39 周期 | 39.7665 ms | 14.2504～14.3327 ms |
| Drone1 第 626 周期 | 39.1596 ms | 26.9117～26.9941 ms |

两个例子的差别看提交后的那一段。第 39 周期从名义发布时间到固件更新最迟约 24.53 ms，采样和调度前段已经花掉一部分时间。要判断整条控制链是否按时，必须继续计入这部分。

**这改变了下一步的优先级。** 对同样约 39 ms 的 `ping()`，有的命令早已在飞控上运行，有的在 20 ms 后才进入固件更新。先把「接收」和「实际采用」按序号分别传给 \(T,c,\sigma\) 日历做旁路对照。确认真实缺口来自采样、共享计算、命令采用，还是确认处理后，再决定机载分工。当前默认负载没重现历史板端的 38～39 ms，限 CPU 是另设的压力条件，诊断客户端只有状态读取和低油门命令，没有运行板端 DPU 或过门任务。原十机真板长尾的归因仍待复测。

## 如何复现

从已有 Blocks 工程复制出一个只供本实验使用的副本。程序只在副本中增加带序号的 RPC，复用已有 `moveByAngleRatesThrottle`，并给 SimpleFlight 目标写入和固件更新加计时与互斥。互斥也可能改变负载，所以本报告只比较本副本中两个事件的先后，绝对时间需要在原场景重新测量。

在当前 `airsim_control` 的 PowerShell 中运行。原始工程、共享 AirSim 端口 41451 和板端都可照原方式使用，测量副本监听 `127.0.0.1:41591`。需要本机已有 UE4.27、MSVC 和 Python `msgpack`。

```powershell
$out = 'controller_architecture_study/results/ct_recheck_' + (Get-Date -Format 'yyyyMMdd_HHmmss')
$from = 'F:\Airsim\AirSim\Unreal\Environments\Blocks'
$engine = 'E:\epicGamesStrg\UE_4.27\Engine'
python -m controller_architecture_study.airsim_command_timing.prepare_blocks --blocks $from `
  --output "$out/Blocks" --settings controller_architecture_study/configs/airsim_safety_12.json
if ($LASTEXITCODE -ne 0) { throw 'Blocks copy failed' }
$blocks = (Resolve-Path "$out/Blocks").Path
& "$engine\Build\BatchFiles\Build.bat" BlocksEditor Win64 Development "-Project=$blocks\Blocks.uproject" -WaitMutex -NoHotReload -NoXGE
if ($LASTEXITCODE -ne 0) { throw 'Blocks build failed' }
if (netstat -ano -p tcp | Select-String ':41591\s+.*LISTENING') { throw 'Diagnostic port 41591 is busy' }
$launchArgs = @('"' + $blocks + '\Blocks.uproject"', '/Game/FalconEmpty', '-game', '-unattended',
  '-RenderOffscreen', '-nosound', '-nosplash', '-ResX=640', '-ResY=400',
  ('"-settings=' + $blocks + '\diagnostic_settings.json"'), ('"-abslog=' + $blocks + '\falcon_game.log"'))
$diag = Start-Process -FilePath "$engine\Binaries\Win64\UE4Editor-Cmd.exe" -ArgumentList $launchArgs `
  -WorkingDirectory $blocks -WindowStyle Hidden -PassThru
```

等副本启动并监听后，可执行以下命令。默认负载和限 CPU 对照用同一版插件。限 CPU 是故意的压力条件，两个逻辑核运行于哪个物理核由本机拓扑决定。

```powershell
netstat -ano -p tcp | Select-String '127\.0\.0\.1:41591'
python -m controller_architecture_study.airsim_command_timing.probe_blocks --paired --output "$out/paired.json"
python -m controller_architecture_study.airsim_command_timing.probe_blocks --vehicles 12 --seconds 18 `
  --output "$out/default12.json"
$savedAffinity = $diag.ProcessorAffinity
try {
  if (($savedAffinity.ToInt64() -band 3) -ne 3) { throw 'Logical CPUs 0 and 1 are unavailable' }
  $diag.ProcessorAffinity = [IntPtr]3
  python -m controller_architecture_study.airsim_command_timing.probe_blocks --vehicles 12 --seconds 18 `
    --output "$out/limited12.json"
} finally {
  $diag.ProcessorAffinity = $savedAffinity
}
```

本轮原始结果在 `controller_architecture_study/results/ct_20261124_01/`。`paired_001.json` 是受控注入。`natural_10_001.json` 和 `natural_12_001.json` 是第一版默认负载筛查，`limited_12_001.json` 是同版限 CPU 筛查。最终对照是 `natural_bounded12_001.json` 与 `limited_bounded12_001.json`，二者使用相同的过期跳过规则。
