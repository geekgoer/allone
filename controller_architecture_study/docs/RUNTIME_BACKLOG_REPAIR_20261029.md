# 已知运行时原因修复与复核（2026-10-29）

## 本阶段结论

已经修复已确认的“IO 完成后仍占着流水线”“等待队列无限保留旧请求”“历史超期直接冻结所有后续修改”等实现问题。202 项相关回归检查通过。

最终复核：两组相同模型、初态、B 参数和实际 CPU/IO 资源的 C++ 十机修复前后对照，seed4 前→后，seed5 后→前。平均完整任务响应时间由 1351/2111ms 降至 26.4/24.5ms；收到 IO 完成后平均约 0.13ms 释放占位。动态 20ms/60ms 配置已经有实际发布记录。

最终两组修复后仍各有一架碰撞，不能宣称系统已达到硬实时或已全面减少碰撞。本阶段证明的是具体实现故障得到修正，以及端到端等待显著减少。

## 具体修改

### 1. 命令完成不再被低优先级收尾卡住

- 命令 IO 完成并被前端收到时，立即移除该任务的 `pending` 占位，记录 `pipeline_released_s`。
- 保持同一飞机 IO 顺序；不会在旧命令 IO 尚未完成时任意重叠发送。
- 已收到的完成事件优先做短小收尾。已有输出就绪的命令仍先下发。
- 后续状态分析、B 和下一配置规划独立保存为每机最新一份反馈，不再占着控制流水线。
- 规划维护的时限基于原任务固定锚点，不再不断追逐下一次日历 tick，避免维护饥饿。
- 新命令已确认时，后续规划只能使用最新已确认控制，不能被旧反馈覆盖。

### 2. 每机只保留一条尚未开始的最新请求

观察模式下，发布仍独立按日历进行。每次发布的任务都进入完整历史记录，但同一飞机最多留一条未派发请求。

旧的未派发请求被新请求替代时，记录：

```text
status = superseded_before_dispatch
superseded_by = 新请求ID
discarded_s = 发生替代的时刻
```

这些是跳过的控制更新，不能当作零开销的成功任务。已开始采样/推理/下发的任务不被这一规则删除；没有新增任意时刻的 FPGA/DPU 抢占。

所有已发布任务的原模型、释放时间、deadline 都保留。逐条审计已核对这些承诺没有被修改。

### 3. 区分已经发生的超期和未来是否可行

严格模式保持原行为：已超期仍是不合格，不允许合并发布或忽略历史期限。

观察/恢复模式下：

- 已经超期的未完成任务仍保留剩余执行成本和调度干扰。
- 预测不再试图“让过去的 deadline 重新被满足”，但历史超期仍保留为失败。
- 所有尚未过期的未来义务仍检查期限；不能把它们也加入忽略集合。
- 若未来可行、过去已有超期，允许采用配置，但标记 `recovery_accepted` 或 `recovery_retained_previous`。
- 此时 `future_feasible=True`，整体 `feasible=False`，`historical_deadlines_repaired=False`。
- 如果连未来约束也无法满足，仍回退并记录 `infeasible_retained`，不会强制放行危险配置。

这修正了故障后的恢复处理，不是把 B 放宽，也不是延长原 deadline。它不能把已经违约的执行重新认证为硬实时。

### 4. 预测与执行使用同样的流水线语义

- 实际已完成的 IO 不再在预测中继续占同机流水线。
- 延后规划不占 IO/在途名额，但它消耗的前端时间仍计入预测。
- 实际最多有 10 路 IO、最多 10 个在途任务时，预测按真实限制计算；不再硬编码旧的 3 个 IO 名额。没有增加实际硬件/线程资源。
- 只有已经在决策时刻到期的期限可以作为历史违约处理；模型会拒绝把未来期限当作历史期限忽略。
- 预测自身的耗时继续计入可行性检查。

### 5. 异步状态到达不再被误判为时钟倒退

规划可能先处理较新的传感状态，稍后再处理已经采样的较早 DNN 输入。输入保留自己的真实时间，不回写更新的轨迹记录，也不把飞机内部状态回退成旧快照。

真正早于本次试验原点的仿真时间、默认轨迹记录中的时间倒退仍报错。没有伪造数据新鲜度。

主结果：`results/runtime_backlog_repair_20261029_v5/repair_audit.json`。

| seed4 修复后 | 26.4ms | 80.7ms | 1 | 9/10 | 80/80 |

R 是已交付任务的响应时间，不包含被合并掉的任务。修复后 seed4/seed5 分别有 **1643/1629** 条未派发请求被替代，全部保留在 `requests.json` 中，并单独统计。

不能只凭 R 的下降声称控制更新全部按期：仍有命令间隔长尾、跳过的更新和期限违约。`observed_strict_timing_passed` 没有被改成成功。

合格过门记录与碰撞也不是同一个指标：飞机穿过门平面时位置合格，随后机体仍可能碰到门框。因此 seed4 修复后即使记录到 80 次合格穿越，也仍如实报告一次碰撞。

### 动态周期是否真的生效

最终发布历史中：

- seed4 修复后：370 个请求使用 20ms，4668 个使用 30ms。
- seed5 修复后：777 个使用 20ms，4210 个使用 30ms，88 个使用 60ms。
- seed5 一号机和二号机都有 30→20ms 的实际任务记录，不只是分析器建议。

本次没有观察到实际模型身份切换，不能把这些数据当成 c 切换或超网验证。准入仍经常因为预测未来不可行而拒绝变更，后续应区分成本模型保守性、规划开销和真实资源不足。

### 仍未解决的部分

- 最终两组均剩十号机在第八个门附近碰撞。尚未在本阶段逐项分离它的模型、局部采样/命令间隔和未来准入拒绝因素。
- 修复后部分命令间隔仍超过 100ms。没有重新出现秒级旧任务积压，不意味着已经满足所有物理期限。
- 仍使用既有冻结阶段耗时估计。更准确的当前 C++ 平台校准可能改善准入，但不能通过随意缩小时间估计或延长 B 来制造成功。
- 本次是原型实现修复，不是 FALCON 与新算法的最终论文比较，也不是 FPGA 验收。

过程中有一组中间版本全十机通过，但最终重复中仍有碰撞；因此没有挑选那次作为最终验收。v2 的乱序状态报错和 v3/v4 的中间复核保留为调试证据，最终表格统一采用 v5。

## 验证范围

202 项相关检查涵盖：

- 最新等待队列不修改在途任务；所有被替代请求可追踪。
- 旧任务完成不能误释放新任务的占位；未完成 IO 不能提前释放。
- 最新确认的实际控制优先于旧反馈。
- 收尾不会被重复到来的过期请求无限挤后。
- 过去超期仍计为失败，残余工作仍阻塞未来资源；不能忽略未来期限。
- 模型增大若会破坏另一健康回路期限，依然回退。
- 普通已完成 IO 和延后规划在预测中正确释放占位，且仍计前端成本。
- 较早的异步输入保持原时间，不倒退最新轨迹。

未训练、修改或替换任何 DNN；B 公式、扰动假设和门洞尺寸未改。
