# 同模型池、同资源：静态离线选择与动态调整的十机比较

日期：2026-10-28。

## 结论先说

**公平比较已经完成，但结果没有支持“当前动态原型整体优于重新优化后的静态方案”。**

动态曾经救回较弱静态配置的碰撞；不过，把动态可用的小模型也允许静态永久使用，并重新按总性能选择配置后，得到更强的静态方案。在最终两组十机实飞中，静态分别撞0架、1架，动态分别撞3架、1架。

第二组里，动态确实救回了静态撞门的9号，却让静态能够通过的1号撞门。因此可以说观察到了局部纠正，不能说整组安全性已经提高。这个结果不证明框架不可能有效，但说明现有周期和调度调整规则还不足以支撑预期结论。

本报告以最终强化静态比较为准。较早的诊断试验、原20候选比较均保留，不能从中挑选更容易失败的静态配置作为最终证据。

## 这次怎么保证公平

| 项目 | 两组共同条件 |
|---|---|
| 可选模型 | 8个已有237D控制器：隐藏层9/21/33、宽512/1024的6个模型，另加2×128和3×256 |
| 推理资源 | 1个共享CPU推理工作进程，固定CPU放置；没有给动态增加计算核 |
| 流水线 | 最多10个在途任务；采样、推理、反馈服务资源相同 |
| CPU放置 | 推理逻辑CPU14；前端12；I/O为8、10，相关物理核同胞保留 |
| 输入与权重 | 相同归一化、输入契约、权重文件；记录SHA256，未重新训练或修改权重 |
| 飞行任务 | 十机、5m/s、各8门、门洞净宽1.7m，无外部扰动 |
| 路线 | 1～3号连续转弯，4～8号平缓，9～10号后段转弯；各机独立横向航道 |
| 初态 | 每组静态/动态成对核对相同初态；没有让部分无人机额外靠近门 |
| 观测 | 两组均用20ms独立观测服务；它不等于控制任务的释放周期 |
| 碰撞处理 | 只停止碰撞的无人机，其余继续；碰撞后的活动负载变化保留在记录中 |

静态仍然依据实时状态计算DNN输出。“静态”指模型、释放周期与优先级固定，不是开环飞行。

静态任务按固定日历到达，不因上一任务未完成而把释放周期顺延；等待体现在响应时间中。动态显式选择后续释放时刻，并使用状态相关期限和分段调度。当前分段边界为至多两个完整全连接层及原有ReLU，单个任务内部模型不变，没有模拟任意指令级抢占。

## 静态如何重新选择

先冻结模型池、资源和评分方法，执行20次静态候选尝试。候选覆盖原有配置、两个小模型以及先前有恢复表现的组合，再做有限邻域搜索。周期候选为20/30/40/50/60/80ms。

另在原20候选的静态选择与验证开始前，登记了两项额外静态挑战：把动态的恢复控制器永久用于相应回路；再试同一组合下把关键回路固定周期降到20ms。这样检查“把动态常用的好模型直接固定部署，是否已经足够”。这两项的构造没有使用随后物理验证的碰撞结果。

总计22次候选尝试，其中2项未通过预先冻结的计算需求筛查，20项完成评分。筛查使用单推理核的测得计算需求≤0.95，不是完整端到端期限保证。**在通过该资源筛查并取得完整有限评分的候选中，只按总性能估计J_hat最大选择，没有按碰撞或超期结果挑选。**

| 静态选择阶段 | 最佳候选编号 | 校准J_hat，越大越好 |
|---|---:|---:|
| 原20次尝试 | 17 | 34.123374 |
| 加入两项预登记挑战后 | 20 | **34.266982** |

最终选择在它自己的配对验证开始前再次冻结。它是有限搜索中观测到的最佳候选，不能称为全局最优，也不是已复现原FALCON的SVM优化器。

最终静态配置：

- 1、3、9号：2×128模型；其他七架：9×1024模型。
- 十架均固定30ms释放周期。
- 固定优先级顺序：1、3、2、4、5、6、7、8、9、10。
- 初始释放偏移依次0、2、4……18ms，在途上限10。

审计实际已施加命令发现：**最终三个配对阶段中，静态和动态对每一架无人机实际使用的模型都相同，没有发生有效的模型切换。** 因此这次结果主要比较当前T和调度s调整，不能归因于动态获得了不同的控制器，也不能当成超网切换实验。

## 最终物理实飞结果

种子4按静态→动态顺序，种子5反过来按动态→静态顺序，避免始终让一种方法先跑。

| 路线种子 | 静态实际接触 | 动态实际接触 | 全组物理检查 |
|---|---|---|---|
| 4 | **0架** | **3架：1、3、2号，第7门** | 静态通过；动态未通过 |
| 5 | **1架：9号，第7门** | **1架：1号，第7门** | 两组均未通过 |

这些接触来自AirSim的simGetCollisionInfo及具体门框对象记录，不是把额外安全余量不足当作实际碰撞。

种子4动态在第7门中心平面的横向偏差分别约为：1号+0.3554m、3号+0.3387m、2号−0.3305m，随后记录到对应门框接触。当前门宽及机体余量要求中心横向偏差不超过±0.325m。种子5静态9号约+0.3595m；动态9号通过，但动态1号另有门框接触。

碰撞任务不再补算完整任务J，也不把停止后的悬停当成完成任务后继续贡献性能。

## 性能函数结果及范围

为了得到两种方法均完整覆盖的评分，在同一种子4上另做无实体门框的名义飞行配对，轨迹和控制流程保持一致。它用于比较完整跟踪评分，不用于证明没有物理碰撞。

| 指标，越大越好 | 静态 | 动态 | 动态变化 |
|---|---:|---:|---:|
| J_hat：代表性前段重复加权估计 | 34.426648 | 33.835866 | **−1.72%** |
| 实际短飞窗口J | 11.488884 | 11.122955 | **−3.19%** |

两组都实际飞行约14.7秒；为节约实验时间，J_hat按约定重复使用实测的代表性平缓前段成本，估计额外84秒前段的贡献。**它不是完整长任务实飞J，也不是原FALCON的SVM预测值。** 两组使用同一估计方式，原始短飞评分同时保留，避免只报告有利的加权结果。

## 为什么较早看到动态更好，现在却反过来了

原20候选胜者给十架都用9×1024、30ms。以它为静态基线时，种子4/5分别出现3架/2架接触；动态分别0架/0架接触，其中种子4虽零接触，仍有一处额外过门余量不合格。

但新增预登记静态挑战表明：把1、3、9号永久换为2×128，固定30ms，既提高校准J_hat，也显著改善物理通过结果。采用这个更强候选重新配对后，前述动态优势不再成立。

这说明之前的改善有一部分来自控制器组合没有被静态充分利用。不能把这部分改善全部解释为在线安全反馈的收益。

## 当前能判断什么，不能判断什么

1. **局部救回存在，整组优势尚未建立。** 种子5的9号是具体局部救回，但动态同时新增1号失败。
2. **当前动态T/s规则可能损害原本可通过的回路。** 种子4中实际模型相同，静态十机通过、动态三机接触。这给后续定位提供了更干净的对照。
3. **尚不能把原因全归于DNN精度或计算核不够。** 本轮没有换模型；动态改变释放、排队及处理顺序，必须对齐碰撞前相同状态窗口再做归因。
4. **更低目标周期不自动等于更好的实际命令序列。** 例如种子4碰撞前共同参考窗口6.0～9.5秒，1号实际命令最大间隔静态约60.3ms、动态约97.7ms，3号约49.8ms、91.9ms。这些数据提示尾部执行行为值得检查，但不能仅凭窗口最大值认定它导致了碰撞。
5. 任务到达后等待输入服务的时间，不等于输入状态已经陈旧同样久；采样发生在服务阶段。响应时间、样本年龄、两次命令间隔继续分别记录，不能混称。

按本阶段约定，超期先记录、不作为结束飞行或选择静态候选的额外条件。最终物理阶段记录的任务期限未满足计数为：种子4静态1104、动态155；种子5静态1847、动态161。两组期限规则不同，这些原始计数不能直接当成同一安全标准下的优劣排名；减少这些计数也没有自动带来零碰撞。本轮不构成硬实时、CBF物理安全或FPGA可达时序保证。

## 下一步应该做什么

先保留这个强静态候选，不继续换回更弱基线、缩窄门或训练更多模型来寻找预期结果。下一项应是有针对性的故障定位：对齐种子4第7门前1/2/3号的释放、命令作用间隔和排队，区分“周期调整本身”和“优先级变化”分别造成的影响，再增加“状态没有显示净收益时保持原配置”的规则。

这是后续工作建议，本次没有在看过验证结果后继续调动态参数并重新挑选有利结果。
