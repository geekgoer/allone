# 实验主线：局部危险识别、启发式调整与安全收益

2026-11-07。按用户最新目标设计：最终要“又安全、总体控制性能又好”。本文件是新的实验方案；离线场景已经生成并检查，正式板端危险场景飞行尚未执行。旧路线A和现有RC1部署包保留。

## 1. 要验证的命题

在相同模型池、硬件资源、轨迹、初态和观测条件下，一个按整段任务性能选出的较好固定配置，可能在少量局部危险区间失效。在线反馈若能及时识别、提出并真正采用合适调整，应减少局部碰撞/任务失败，同时保留较好的总体J。

不要求所有静态配置都必定碰撞。应同时展示：离线高J静态、较保守静态、动态在安全—QoC—资源上的关系。若某个资源可行的固定配置同时达到同等安全和更好J，本场景就没有证明动态优势。

不预设“周期越短必然越安全”或“网络越大必然越好”。用真实闭环找到可恢复区间；无人机已经超出任何可用控制器的恢复能力时，不能靠调度保证救回。

## 2. 当前容易路线为何不够

三机固定50ms、固定80ms、动态均15/15穿门。动态主要在开头把50ms变为80ms，没有稳定进入20/30ms危险恢复段。板端小模型内部服务约1.32ms，三机50ms对应服务占比约8%，六机也不能直接假定达到算力极限。

还有一个几何机制：已核对的源路线在门中心强制侧向速度和加速度回零，曲率较高的位置往往位于两门之间。因此单纯加大两门之间的偏移，不一定使实际穿门时刻困难；控制器有较长纠正时间。

新方案把部分门放在持续转弯中，保持相同连续轨迹，门朝向对准水平切线，仍保持竖直。这是自然障碍布置，不能根据某一次静态失败轨迹专门移动门框。

## 4. 执行分三步，先回答决定性问题

### A：找出“有恢复机会”的局部危险窗口

先用1号的完整自然路线、同一个真实RC1模型，对比实际可执行的30ms和80ms。门洞从2.1m开始；若两者都通过，再依预定顺序收窄。必要时加20ms，不能把它当作必然正确答案。

同时满足以下条件才标记为周期能力差异：

- 慢周期出现物理接触或明确的机体几何余量不足；
- 快周期实际穿过并完成任务，接管不依赖瞬移/悬停跳过门；
- 真实响应和更新间隔支持该周期，成功不是通过丢掉大量任务或延长实际周期获得；
- 至少三次交错顺序复测，差异不只是一两毫米或一次系统抖动。

首个宽度没有差异，只能说明该宽度尚未构成需要调整的工况。所有已试宽度全部报告，不只留下有利例子。最短可实现周期下仍失败时，检查MPC教师/模型能力，不继续把门缩到物理上不可恢复。

这一小步不是重新全面验证DNN，是防止在“本来都能过”或“谁都过不了”的区间反复做多机实验。

### B：建立较强的离线静态对手

静态配置允许知道完整路线及危险位置，只限制任务期间保持不变。初期固定RC1模型，搜索各机周期；不能声称此阶段覆盖完整FALCON模型池。

候选周期20/30/40/50/60/80ms；先含六个统一周期配置，再用逐机坐标改进，最多20次联合配置评估。每机周期允许不同，不能仅比较“所有飞机都80ms”。保留最短可实现周期的强对照。所有策略计入同样的调度/通信资源。

离线名义全程QoC评估可在不产生接触的门宽上沿**完全相同参考轨迹**执行，计算J和时序；不按后续窄门碰撞结果挑选“最容易失败”的静态配置。静态选择目标、资源约束和预算预先固定。若名义评估去掉物理窄门，必须明确这是近似FALCON式QoC静态选择，不是有完整碰撞约束的离线优化器。

选择后冻结配置，再在真实窄门上配对测试。有限搜索只能称为“本预算内找到的最佳静态配置”，不能说全局最优或原FALCON完整复现。

### C：主实验和最少消融

| 组别 | 目的 |
|---|---|
| 最佳找到的固定配置 | 主要对照：整段J较好但是否有局部失效 |
| 始终使用合适快周期 | 强对照：安全能否靠固定加频解决，资源和J代价多大 |
| 完整启发式动态 | 检验局部识别、实际调整与全机保护 |
| 去掉物理危险反馈、保留同样资源管理 | 检验收益是否来自物理反馈，而非仅仅自动降频 |

初轮每组3次、顺序交错；一次26秒参考任务，加初始化。先看开发案例是否存在稳定差异，不直接启动大矩阵。若有清楚信号，冻结规则后用新的路线变体和5次以上配对重复确认；所有种子和所有结果均保留。

碰撞只让对应飞机停止，其他飞机继续。碰撞后退出计算负载会改变其他机等待；记录退出时间和剩余负载，主要因果对比同时报告首碰前同负载区间。不能把失败退役后的减载当作调度器优化。

## 5. 为什么危险时段错开有意义

把真正需要快速更新的飞机集合记为H(t)。只用于挑选实验规模的经验容量筛查为：

\[
U_{dyn}(t) = \sum_{i\in H(t)} C_i/T_i^{fast}
 + \sum_{i\notin H(t)} C_i/T_i^{normal} + U_{management}.
\]

固定配置若要覆盖每架飞机曾经出现的最坏危险，则要长期保留相应快周期；动态可以复用时间上错开的空闲。最有意义的共享资源区间是“全程快更新明显有代价或不可行，而仅给当前危险回路加频仍可行”。利用率只作筛查，不能代替响应时间和端到端检查。

必须用实际资源成本确定规模。当前板端小模型6机×1.32ms/20ms的平均板内服务需求约39.6%，并不自动过载；串行UDP等待和PS工作要另测。若始终快更新在当前硬件上轻松可行、控制表现也更好，说明此规模不足以证明资源转移的必要性。可以增加真实任务数或换用双方均可使用、已验证可飞的较重控制器，不得凭空加延迟或压低虚构FPGA容量。

即便无需超过容量上限，若动态在同等安全下达到接近最优J且明显节约实际计算，也可以报告该收益；不能把它替换成“静态一定无法安全”的结论。

## 6. 必须画出的因果证据

对一个具体局部危险门，按同一时间轴保存：

1. 门框几何余量、接近速度和保持控制预算B；
2. 旧配置预计下一控制到达时刻与绝对安全期限的差；
3. 首次检测危险时刻、提出方案时刻、全组检查完成、实际安装时刻；
4. 各机实际周期和模型、EDF执行顺序、旧工作阻塞与真实命令返回；
5. 静态的接触时刻，与动态通过同一门的实际余量。

主图应能读出“什么时候发现、改了什么、何时真正生效、是否及时”，不能只画最终碰撞柱状图。若配置在危险发生后才安装，不能归因于它救回。

全机同时核对：危险飞机改善后，原本平稳的飞机是否因为让出资源而发生新的安全失效。当前DPU只能整任务EDF重排；不能展示不存在的任意时刻抢占。后续自定义PL才加入分段收益。

## 7. “又安全、又好”的评价

- 安全：物理碰撞架次、任务完成率、逐门机体余量、条件物理期限违规；所有尝试进入统计。
- 控制质量：共同任务窗口上的原定J口径、位置/速度误差；不把训练MSE当飞行质量。
- 实时性：R相对本任务T、计划释放覆盖、丢弃、实际命令间隔、方案安装延迟、决策均值/P99/最大值。
- 资源：实际板端工作量、PS处理和通信/等待、总请求数量，避免只有MACs。

J沿用工程 `paper_score` 的Eq4形式时，要明确Wx、窗口与参考定义；不能直接把这种工程口径称为逐项复现论文原条件。各策略用独立于控制周期的同频观测（可复用现有观测通道）评价，不因80ms少采样而低估误差。额外观测成本两组一致并计量。

触碰停止的飞机仍可由独立观测记录到统一终点，使用其真实停止/悬停状态计算失败代价，不拼接理想轨迹。不完整的J标为缺失并单列任务失败，不能当作更优值或悄悄删除该轮。仅成功子集的平均J要明确条件，安全率另报。

预先把“好”的容忍区间定下来，例如相对最佳找到的静态配置，J下降不超过5%作为第一阶段工程目标，同时碰撞明显减少；5%是实验取舍而非理论定理。若实际J更好，直接报告。小样本只给配对原值和效应，不提前宣称显著性。

## 8. 正式运行前只补必要项

阶段A已接入冻结case，按实际门数验收，并交付[80/30ms首轮配对入口](IP37_RECOVERY_PAIR_RUNBOOK_20261107.md)。命令预留已与后续回读分开、补充尾部释放和线程CPU分解；真实配对由用户执行。以下正式六机动态实验准备项仍需逐项完成，不能把首轮固定周期筛查当作动态收益。

同一次实验入口改动应完成：

- 接入六机case布局与各自门数量，取消“每机恒为5门”的验收假设；保存冻结case/hash；
- 修正历史最大准备/通信/后处理相加导致后期全部拒绝的成本模型，记录CPU时间与阻塞等待；保留真实周期期限和超期丢弃，不通过忽略坏样本制造可行；
- 分开命令下发预留与命令后的状态回读，后者不能无限抬高前者并阻止后续控制；
- 补尾部计划释放覆盖、逐门机体余量及检测→安装→命令的时间链；
- 补完整参考状态和统一观测的J评价，保留接触后真实记录和退役负载标记。

这些是让核心实验可解释的准备项，不再扩展新评分网络、RL、超网训练或复杂新调度模块。先固定c，验证T与整任务执行顺序能否完成局部安全纠正；有收益后再扩展模型/超网和PL段级抢占。

失败也要有明确结论：最快可实现控制也失败，归入控制器/轨迹恢复能力；B触发晚，归入识别；早已触发但未安装，归入决策/准入；已经及时安装仍失败，归入选择或控制能力。不要再次把所有问题混称为“动态不行”。
