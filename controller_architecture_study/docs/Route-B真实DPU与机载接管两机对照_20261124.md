# 真实 DPU 接入后，按需分配有收益吗？

这轮把真实 Zynq DPU 接入上一轮的两机机载控制。两架各飞三道实体门，沿用 2.6 m 门宽和同一份机载控制律。在这个场景里，**用真实 DPU 的两组都扩大了过门余量，固定轮询两次都优于误差优先分配**。这些结果只覆盖当前两条路线、模型和请求预算。[机载路径原实验](Route-B两机机载闭环初验_20261124.md)

## 一条 DPU 命令如何到飞控

1. Windows 从 AirSim 采样，用现有参考规划器和 237D 编码构造输入，经 IP37 UDP 发到 Zynq。板上只有一条共享推理队列，使用冻结的 release001 模型 ID 11。启动前核对包清单和三条 INT8 黄金输入，两次最大误差均为约 $3.9\times10^{-8}$。
2. 板端给出推力加速度和三轴角速度。Windows 用原标定换算油门，再把角速度和油门提交给独立 Blocks 内的裁决入口。输入年龄达到 55 ms、序号落后或越出原命令范围，均不进入飞控。
3. 机载路径仍在仿真器内直接读本机状态，目标是速度和高度。DPU 角速度与油门沿原接口交给同一飞控，每条已采用的 DPU 命令最多保持 20 ms，且不能超过样本新鲜度。有效窗口结束后，机载路径继续提供目标。两条路径的切换及采用序号在固件更新后记录。[接管逻辑](../airsim_command_timing/onboard_pilot.hpp) · [板端试验驱动](../airsim_command_timing/run_onboard_dpu.py)

## 怎样比较资源分配

纯机载先确认路线可飞。带 DPU 的两组都有同一机载控制、同一个 DPU、同一个模型，以及 80 ms 名义槽位，每槽最多选一架飞机。固定组按飞机轮询，按需组把请求给当前横向误差较大的飞机，并在等了四个名义槽位时提高优先级。模型档位固定，本轮只检验请求给谁。

在相同的中央槽位刻意扣住一条真实 DPU 结果约 180 ms，中间两个槽位不发请求。两组实测每轮各用 **94 条**请求。第一轮先固定再按需，第二轮顺序交换。延迟注入只阻塞 Windows 提交中央结果，仿真器与机载路径照常运行。

## 结果

表中余量取两架飞机和三道门中最小的一个。门附近按半径 0.525 m 的机体近似计算，接触以仿真器报告为准。

| 策略 | 每轮 DPU 请求／实际采用 | 门平面最小余量，两轮 | 门附近最小余量，两轮 | 两机过门 |
| --- | ---: | ---: | ---: | --- |
| 纯机载 | 0 / 0 | 13.48 / 13.48 cm | 5.38 / 5.38 cm | 6/6，无接触 |
| 固定轮询 | 94 / 93 | **20.19 / 20.24 cm** | **11.50 / 10.97 cm** | 6/6，无接触 |
| 横向误差优先 | 94 / 93 | 18.83 / 19.06 cm | 10.65 / 10.69 cm | 6/6，无接触 |

四个带板端的试验共发出 **376 条**请求，全部由 ID 11 成功推理，输入保护未拒绝。UDP 往返中位数为 **3.057 ms**，DPU 运行调用中位数为 **1.304 ms**。这两个计时分属 Windows 往返钟和板端调用钟，未跨机器相减。四条刻意延迟的真实 DPU 结果均被拒绝，其他 **372 条**按序号与飞控采用记录一一对应。

中央中断实际持续 **183.50–186.88 ms**。两机各在此期间采用 **8–9 条**本机更新，最久的新命令间隔 **21.17 ms**，随后新 DPU 命令重新进入飞控。这里验证的是正常运行的仿真器里，中央短暂停顿时的接管。

这组数据支持「有 DPU 时飞行余量可以更大」，也说明「误差大就优先」在当前路线给不出稳定增益。下一步值得把两机的急弯错开，并比较一次及时 DPU 修正能给每架机增加多少余量、还来不来得及用。只有比同预算的固定轮询可重复地好，才适合将按需分配作为研究贡献。

## 复跑

用上一轮方法重建并启动专用 Blocks 副本，使用本轮源码及本地 41592。板端运行 [独立服务脚本](../airsim_command_timing/run_onboard_dpu_service.sh)，它在 `/run` 创建本轮目录，使用 5240 和原冻结模型。若共享 DPU 正在被占用，脚本停止启动。[Blocks 编译与启动命令](Route-B两机机载闭环初验_20261124.md#怎样复跑)

```powershell
$py = 'F:\Airsim\AirSim\PythonClient\.venv\Scripts\python.exe'
$bundle = 'controller_architecture_study/docs/main18_requant_release001_delivery_20261115/board_package_requant18_release001'

```

复现实验的交换顺序轮使用新目录，并加 `--adaptive-first`。这次实际结果在 `controller_architecture_study/results/onboard_dpu_20261124_001/trials_002/` 和 `trials_003/`。首个测试启动时将源黄金哈希与部署文本哈希混用，已修正为检查部署包清单，原报错日志保留。两次正式对照完成后释放独立板端服务和独立 Blocks 进程。
