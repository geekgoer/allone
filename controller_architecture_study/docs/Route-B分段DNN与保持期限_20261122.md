# Route B 分段 DNN 与控制保持期限

## 决策

先验证旧控制到期时退出单机普通调度，再在独立测试程序里测分段。最近的十二机日志显示，整任务确实会阻塞新请求，但缩短阻塞和减少超期是两件事。单块 DPU 上，所有任务为每个切口付出的固定代价可能大于少数急任务获得的等待收益。

当前最值得验证的差异是**用控制状态推出来的有效期限选择何时值得切段**。简单的候选条件是，新紧急任务等当前网络跑完会缺预算，等到最近合法段边界则有机会完成，而且被暂停任务的续段和其他既有任务依然可完成。由测得的段耗时、切口开销以及各任务绝对期限共同决定。切段、有限抢占和固定优先级本身已有充分先例。

可以在长任务启动前，从已知释放日历取一个最急的后续任务 $u$。设长任务从 $s$ 开始，整网费用为 $C_w$，前后段费用为 $C_1,C_2$，$h_1,h_2$ 分别是段完成后交出设备和恢复时额外计入的成本。令 $q_u$ 为急任务输入最晚就绪时刻，$d_u,d_w$ 为已经扣除下发预留的 DPU 期限。只看这两个任务时，急任务的两种完成时刻为

$$
F_u^{\mathrm{whole}}=\max(q_u,s+C_w)+C_u,\qquad F_u^{\mathrm{split}}=\max(q_u,s+C_1+h_1)+C_u.
$$

在估计日历上，只有 $F_u^{\mathrm{split}}\le d_u<F_u^{\mathrm{whole}}$ 且 $F_u^{\mathrm{split}}+h_2+C_2\le d_w$，这个切口才值得进入全组校验。实际验证还要把其余设备预约、发布后的固定承诺及最后的下发时间放回日历。代价需要按实际计时口径归属，已计入 $C_1,C_2$ 的开销只计一次。整网一旦启动就没有办法改成两段。使用分位耗时与预测就绪时刻时，这是一条候选筛选规则。用它作实时保证需要可信上界及端到端检查。

直接保留设备、等急任务先整网执行，也可以消除阻塞。该做法使长任务在 $\max(s,q_u)+C_u+C_w$ 才完成。如果急任务和长任务这样都来得及，就有一个无需切段的候选。分段独有的价值出现在需要利用急任务就绪前的这段空档、否则长任务也会超期时。分段前缀可以在空档内做完一部分计算，急任务结束后只剩后缀。实现时可用先启动整网、推迟整网、切段预留这三种局部动作生成候选，仍由同一份全组日历决定能否提交。

接入路线 B 时，先用 $d_i=\min(d_i^{\text{slot}},d_i^{\text{hold}},d_i^{\text{fresh}})-O_i^{\text{post}}$ 把控制有效期限换成 DPU 期限，再做上述检查。若确认切段，提交时同时登记两段及其依赖，并记录请求 ID、控制版本、激活缓冲区和后缀期限。暂停只是前段已经执行完，设备可交给别的 UAV。恢复前需复核版本和绝对期限。过期后释放该次中间激活，不登记新命令。这个日历接法是设计，现有闭环执行器仍按整任务运行。

## 实验三　只切开模型还不够

在真 DPU 上让两条 ID 11 推理竞争。先到的普通请求绝对期限为 3.30 ms。急请求在普通请求释放后 0.30 或 0.90 ms 就绪，相对期限都为 1.65 ms。硬件真实执行，释放时刻与期限由程序设定。每个组合重复 80 次，轮换策略运行顺序。

| 派发方法 | 0.30 ms 时两条均按时 | 0.90 ms 时两条均按时 | 0.90 ms 时急请求／普通请求完成时间中位数 |
| --- | ---: | ---: | ---: |
| 普通请求先整网执行 | 0/80 | 0/80 | 2.609／1.305 ms |
| 普通请求切段，段末只看已就绪的任务 | 80/80 | 0/80 | 2.632／1.328 ms |
| DPU 空等，急请求先整网执行 | 80/80 | 0/80 | 2.266／3.579 ms |
| 先做前段，按已知就绪时间保护切口，再续跑后段 | 80/80 | 80/80 | 2.264／3.011 ms |

在 0.90 ms 的组合里，前段约在 0.58 ms 结束。如果段末只看队列，当时还没有急请求，于是会启动后段并重新造成阻塞。如果从一开始空等，急请求能按时，但普通请求结束得太晚。先在空档做前段、等急请求、最后做后段，两个期限才能同时满足。0.30 ms 的组合里，直接等急请求已经足够。本实验区分了提前知道就绪时间的价值和切段本身的价值。实际闭环里只知道计划释放，输入何时准备好还受 PS 和 RPC 影响。实验结果尚不能说明存在多少这样的可预测空档。[四策略原始结果](../results/ps_segments_20261122_001/dnndk/contention_four_policies.csv)

### 派发拒绝的独立复算

审计沿每轮原始日志重放两条在线规则：命令预留随已观测峰值增加，每个模型的 `service_ms` 随该模型从日历派发到回收的最长记录增加。重建的最终预留和各模型成本与三份板端最终日历一致。派发检查时刻由日志中的执行器出队时刻近似，成本更新用有因果保证的下一次配对采样起点作为已更新的时刻。

修订版整轮记录了 **694** 次入队后因“没有模型满足剩余交付预算”被拒，复算命中 **694/694**。保留各次拒绝的实际绝对期限、派发时刻和下发预留，如果只把最快模型成本换成初始表值，**664/694** 次会通过这一道检查。另外 154 条在入队时就超期，单独结算。最快档的经验预留由 **0.123 ms** 逐步涨至 **5.896 ms**。这个结果定位了准入规则为什么拒绝，并不预测放行后的 DPU 交付或飞行结果。

修订版中一个典型样本是 `Drone9:175` 的 ID 5 推理。日历把整个 **10.907 ms** 抬成该模型的服务成本，其中从取派发时间戳到执行器记录出队已经过去 **10.750 ms**，实际 DNNDK 提交到读到结果只过了 **108 μs**。历史日志不能继续分清这段派发阶段的等锁、队列选择和线程未获 CPU 的时间。

已在 C++ 拒绝行中记录当次检查时刻、剩余预算、命令预留、所需模型与实时使用的服务成本。固定配置记录固定模型，自适应配置记录候选中的最低成本。诊断版执行器另外记录进入日历的时刻、日历返回时刻与取锁前到取锁后的墙钟间隔。取锁间隔仍可能包括该线程被系统暂停的时间。复飞时用这些分阶段计时确定尖峰归属，再评估是否把 PS 派发阻塞和 DPU 模型成本分开入账。现有准入规则和上轮到期处置保留。[审计脚本](../ps_planner_repair/audit_segment_opportunities.py)

拟验证的计账方式是 $F_i^{\mathrm{bound}}=t+W_i^{\mathrm{PS,rem}}+C_i^{\mathrm{DPU}}(c)+O_i^{\mathrm{post}}$。其中 $W_i^{\mathrm{PS,rem}}$ 只含从当前时刻起仍可能发生的 PS 派发等待。锁后再次检查时，以新的 $t$ 计算并只留剩余预留。这让派发阻塞可以保留在端到端期限里，同时避免把同一段等待永久记入某一个 DNN 的执行成本。各项预算的适用条件需要独立测量。

## 实验八 · 单次原子下发检查（2026-11-23）

新路径先将 DNN 输出转换为命令，再取得一次日历锁。锁内刷新时钟，核对当前周期仍拥有该机执行位置、推理成功、控制版本仍匹配、未取消或退役，并验证 `当前时间 + 下发预留 < min(任务执行期限, 最新保持期限)`。通过即登记命令在途，防止重复下发。RPC 在锁外执行，迟到 ACK 仍更新实际控制版本，保持期限退役继续生效。ACK 仍用下发和 ping 返回作代理，预留仍使用实测经验成本。新路径用锁内取得的有效期限判定 ACK 是否迟到。

生成的控制程序用 `single_command_check` 切换路径，默认 `false`。开启后省去推理返回后的完整日历行复制和单独的成本读取。新字段 `command_admission` 记录取锁等待、锁内决策时间、有效期限、预留与拒绝原因，日志在返回或拒绝后补写。原任务期限字段保留，便于对照。固定策略、模型候选池、保持期限退出和规划逻辑沿用原配置。

## 实验十 · 按无人机隔离命令预留（2026-11-23）

`isolate_command_costs=true` 时，每架无人机从相同的配置下限开始，分别维护命令后处理上界 `post_ms` 与下发预留 `command_reserve_ms`。新的 ACK 样本只增大发出该命令的无人机对应的值。派发候选筛查、就绪队列尾部检查与最终下发保护使用相应任务的预留，规划快照使用该机的后处理成本，至少覆盖同一预留。有效成本增长会使旧派发顺序失效，联合计划仍走现有的快照版本复核。采样准备和 ACK 后收尾成本继续由原共享估计维护。

例如 A 的预留升至 42.606 ms。A 在 20 ms 周期内仍放不下任何 DPU 模型，原有期限规则继续丢弃。B 保留本机已观测的预留，按自己的期限继续派发和下发。A 如果后续没有可及时生效的命令，原保持期限检测会退出 A；本改动没有接入悬停或制动。这个经验最大值也不支持硬实时 WCET 保证。若同一主机或网络故障同时影响多条回路，各回路的预算仍会随各自观测上升。

Windows 回归 43＋164＋47 项通过。新增用 42.606、35.104 ms 两种长尾复现：旧全组估计使第二架同样被拒，隔离后第二架完成下一条 ACK，异常机仍保留迟到 ACK 的控制版本，并在保持期限到期后单机退出；规划快照也核对了两机各自的后处理成本。将相同逻辑逐条应用到实验九固定日志，两个失败轮各有 87 条属于其他飞机的超周期预留拒绝。在原派发时刻、原模型成本不变的假设下，分别有 87 条和 76 条能通过这道设备预算门槛。它们的实际推理、通信及物理完成情况需要新运行验证。
