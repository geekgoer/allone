# 重启后的恢复与时序阶段结果

日期：2026-10-26。接续[上一阶段集成报告](FRAMEWORK_PIPELINE_INTEGRATION_20261025.md)。原始成功、失败、模型和旧模式表均保留，没有训练新网络。

## 当前结论

**正常七机原型已重新通过，但尚未得到“静态真实撞门、动态按时安全完成”的配对证据。** 最新三个扰动配对中，动态均因遇到新的未知模式格子中止。不能将中止或清理悬停计为安全完成。

本阶段最有用的发现是：接近原未知点的状态，在正确记录控制量与控制年龄后，两种DNN都能恢复；原未知标签不等于控制器不能恢复。另一方面，仅往表里补少量成功轨迹点，并不足以构成框架要求的连续恢复区域。这部分构建方法需要纠正。

机器可读记录：[audit.json](../results/framework_recovery_stage_20261026/audit.json)。117项相关回归通过，测试结果保存在同目录`regression_tests.xml`；源码快照和下一阶段的三个完整状态种子也已保存。

## 已完成的修正

1. **分开外部服务和前端重复等待。** 仅去掉助手已完成之后、与已计入串行前端工作重叠的通知等待；RPC、IPC及其余可见延迟保留。未确认的在途操作仍使用原父进程可见最大值作为经验尾部估计。
2. **分开三个命令时间段。** 父进程发出至RPC返回的预测约3.769ms，助手自身RPC约2.425ms，命令加后续状态完整可见约7.805ms。助手已走过上游排队后，不再重新预留完整上游交付时间。绝对期限、实际返回检查和30ms输入年龄限制没有放宽。
3. **简化空闲推理等待。** 空闲时直接阻塞读取任务，去掉独立的零字节探测等待。忙碌时仍只在完整两层FC段之间检查新任务，无段内抢占。这不是Windows硬实时保证，也未通过独立消融证明它是所有长等待的唯一原因。
4. **缩小在线搜索。** 用一次可行预测的完成时间计算余量，最多再校验一次延后释放，不再二分多次。某些开发记录中规划均值从约2.52ms降至1.82ms，但运行长度与状态不同，不能当作严格配对性能结论。
5. **补充并行采样候选。** 离线检查证明，两个启动拒绝现场中的单任务都可行，整体也存在不改变成本和期限的排法。增加“首两路同时采样，其余错峰”的通用候选；所有候选仍经完整流水线预测检查，总数上限5。真实拒绝现场已作为独立回归夹具保存。

经验成本使用固定的`max(1ms, 1.25×开发p95+0.5ms)`规则。数据来源、算法假设与源码哈希均保留；它不是WCET，跨阶段p95也不提供整体最坏时延保证。

## 未知点恢复检查

先以固定35ms更新、5/30ms交替输入老化运行，轨迹没有在前0.5s进入目标未知格子，因此没有凭空选点。随后按旧日志重放前约0.1s的控制前缀，采集新的完整运动学状态。命令重放最大时间误差约0.012ms，不声称精确复现旧内部状态。

重放目标附近的特征约为：h=0.323m，ḣ=−1.048m/s，ψ=2.076。分别测试命令前和同一物理步命令后的状态/保持控制组合；两组不能混称为同一个控制条件。

每组测试9×512、9×1024两个冻结模型，以及新鲜输入和5/30ms交替输入两种协议，共8次恢复检查：

- 8/8完成恢复，运动学初态匹配检查通过。
- 实测最大控制更新间隔约36.000768ms。
- 交替协议实测最大输入年龄约30.000640ms；线上限制仍严格保持30ms，没有据此改为更宽期限。
- 恢复初始时保留旧控制已持续的时间，没有从重建时刻重新给予完整预算。
- 匹配的是位置、速度、四元数、角速度和加速度；仿真重置会重置隐藏的执行器/内环状态，不能声称完全恢复了旧系统内部状态。

这些是暂停后步进的控制实验，不是端到端CPU时延验证，也不是区域安全证书。本轮未显示9×1024在该目标点比9×512更有恢复能力，不能据此证明必须动态增加网络复杂度。

数据在`unknown_mode_recovery_20261026_v1/v2/v3_post_command`。v1保留了“没有找到未知目标”的负结果；v2为命令前组合，v3为命令后组合，各自源码均冻结。

这三个动态报告的`timing_passed=False`包含“试验中止未完整验收”的含义；对应的`actual_timing_violation_observed`均为False，过期输出和迟返列表均为空。本批失败原因是模式覆盖不足，不能直接解释为又发生了期限违规。

这是七架真实AirSim回路、同一个CPU分段执行器下的开发结果，窗口为3s，不是整条五门任务或FPGA实验。静态来自此前52候选的有限经验搜索，没有SVM和完整硬件搜索；不能称为原始FALCON的全局最优实现。

另一个重要边界：正常动态475次预算分析、最新三个扰动合计93次分析中，物理距离/速率B均没有成为最终期限的主导约束；主要约束来自经验等待/更新上限。因此，本批也不能证明物理B本身带来了安全收益。

## 下一阶段：区域校准，而非继续补单点

三个新未知点的完整状态、当前实际控制、控制年龄代理和参考阶段已冻结在[next_region_seeds.json](../results/framework_recovery_stage_20261026/next_region_seeds.json)。它们是待检验的种子，不是正标签。

后续按以下顺序执行：

1. 从一个种子开始，固定很小的连续运行域与允许的姿态/控制条件。先检查中心在相同保持控制、剩余时间预算和输入老化协议下能否恢复；不能恢复就不扩表。
2. 预先声明邻域边界、角点及中间样本，统一恢复判据。先测试成本最低的现有模型，必要时再测大模型；已有失败保留，不能取平均后把混合成败区域全部标成合格。
3. 只在预定样本/协议都通过的范围内建立经验区域；不声称连续状态的形式化安全。遇到相同投影内稳定相反的结果，先收缩适用域并检查遗漏条件，不能无限补体素或直接扩大特征维数。
4. 区域覆盖有效后，重跑同样三个七机配对，并核对期限究竟由哪一项主导。若物理B仍始终宽于经验上限，先校核Safety Analyzer对动力学、当前控制和恢复需求的界定；不得人为放宽经验上限只为让B激活，也不能把模式上限的效果包装成物理B的收益。
5. 再考虑8/12机。新的并发规模需要匹配的成本测量与静态对照，不能直接套七机时延。
6. 出现同一对“静态碰撞、动态完整完成”后，才做预先固定的邻近状态复核和消融。当前不具备宣称安全优势或超网必要性的条件。

物理预算B仍为距离/速率原型，尚未实现控制感知或鲁棒CBF安全时间界；后续接口可以升级，不引入DNN误差模块。上述工程和实验进展不能替代这一理论边界。
