# 为什么30ms与80ms的过门差别只有几厘米

## 当前判断

这不是可以跳过的问题。现有证据已经排除“30ms普遍被拖成80ms”和“额外计算基本只是在读旧状态”。更强的解释是：**两组都在执行同一套教师控制律，而教师的平移预测与其姿态执行过程不一致，造成约1米的共同跟踪偏差；缩短采样周期改善的只是其中一部分。**

这里的“主因”是有日志与离线受控模型支持的工作判断，尚不是对真实AirSim全部误差来源的完整辨识。未修改运行控制器、权重、量化或原始报告，未新增试飞。

## 1. 先确认实际控制周期

审计三档宽度的6组请求和轨迹：`ip37_recovery_pair_20261107_135811`、`135833`、`135935`。以下列出无丢弃、可完整对照的3.8m组。

| 实测项目 | 固定80ms | 固定30ms |
|---|---:|---:|
| 实际采样平均间隔 | 79.998ms | 30.001ms |
| 仿真状态时间戳平均间隔 | 79.965ms | 29.990ms |
| 命令提交平均间隔 | 79.993ms | 30.002ms |
| 命令返回平均间隔 | 79.993ms | 30.002ms |
| 急弯3.5～6.35秒内命令数 | 36 | 95 |
| 该窗口命令返回间隔均值 | 80.018ms | 30.003ms |
| 该窗口最大命令返回间隔 | 83.741ms | 32.829ms |
| 连续采样的状态时间戳相同 | 0% | 0% |
| 急弯中连续两次4维输出全部不变 | 0% | 约1.06% |

因此，30ms确实提供了更多新状态和新控制，不是名义加频。RPC提交/返回是可观测代理，不是精确电机生效时间；本审计不夸大其测量范围。

另外两档30ms各有一次命令迟返及一次忙丢弃，确有尾部问题，但它们不解释3.8m干净对照中同样较小的周期收益。

个别通道因量化会重复：例如3.8m急弯30ms组推力通道约50%、wy通道约47.9%的相邻输出相同；但4维同时相同仅约1%。量化可能限制小幅修正，不能说额外推理整体没有作用。此前未量化的教师20ms仍撞同门，也排除了“只因量化”的解释。

## 2. DNN学的是控制策略，不是完整动力学

本237D模型监督学习的是：

\[
\pi_\theta(z)\approx u_{\mathrm{teacher}}(z),
\]

输出推力加速度与三轴角速度。它没有直接输出下一状态，也没有被要求在网络内部完整识别AirSim动力学。

所以要区分两种问题：

- DNN是否准确拟合了教师的命令；
- 教师本身是否能让真实姿态和运动跟上这条参考。

拟合教师很好，仍可能继承教师的控制结构偏差。既有同输入分析已发现量化与拟合误差，但不能用它们解释教师自己的实飞失败。

T也不是237D中的显式输入。30ms、80ms调用的是同一个策略，而非分别训练出的高频/低频控制器。

## 3. 当前教师“预测的动作”与“实际执行的动作”之间多了一层

`convex_teacher.py`先用平移QP优化加速度，模型近似为：

\[
\dot p=v,\qquad \dot v=a_{\rm QP}.
\]

然后把加速度转换成期望姿态和推力，再用姿态误差生成角速度：

\[
\omega_{\rm cmd}
=\operatorname{clip}\left(3.5\,\operatorname{Log}(q^{-1}q_d)\right).
\]

真实执行过程是：

```text
QP算出想要的加速度
          ↓
换成需要的机身倾斜方向
          ↓
发送角速度，让机身逐渐转过去
          ↓
推力方向改变，才逐渐获得需要的横向加速度
```

QP的状态里没有这个姿态响应过程，也没有一致的优化姿态角速度前馈。源码明确没有直接叠加规划轨迹的角速度，因为规划姿态和QP优化姿态不是同一个目标。

局部小角度、理想角速度跟踪、固定目标条件下，反馈增益3.5对应约`1/3.5≈0.286s`的姿态误差衰减时间尺度；这是该反馈律的近似解释，不是辨识出的真实AirSim时间常数。目标姿态在急弯中持续变化时，误差还会持续产生。

每30ms重发一个角速度，并不会让机身转速自动变成每80ms发送时的2.67倍。角速度单位是rad/s，上一命令在下一命令到达前持续作用。加频改善反馈更新与保持误差，不会自动改变增益或消除转向时间。

## 4. 离线受控对照复现了“大偏差＋小周期收益”

使用同一个QP、同一路线、同一个初态和固定7ms计算/交付延迟，在离线模型中只改变“优化加速度怎样执行”。

| 离线执行模型 | 80ms第4门横向偏移 | 30ms第4门横向偏移 |
|---|---:|---:|
| 理想平移：立即执行优化加速度 | +0.0343m | +0.0701m |
| 加回原教师姿态反馈，且角速度仍理想跟踪 | −1.1069m | −1.0680m |

第二行已经复现约1米共同偏差，以及30ms仅改善约3.9厘米。即使把计算/交付延迟设为0，第二行仍为−1.0968m／−1.0579m。

参考实飞3.8m组第4门横向偏移为−1.1845m／−1.1284m。模型与实飞接近支持该解释，但**不能把它们接近视为已经识别全部动力学**。

离线模型不含电机动态、阻力、量化、网络抖动，也没有拟合参数去追实飞结果。姿态变体直接积分教师请求的角速度，借助当前姿态和推力计算平移加速度；其角速度执行本身仍是理想的。因此这首先指向现有教师控制结构的响应过程，而不是仅仅“AirSim底层太慢”。

数值积分间隔从5ms减至2.5ms后，30ms＋7ms姿态变体第4门偏移变化约0.0000155m，小于2mm检查界限。

第一行中30ms未优于80ms，也说明特定QP离散化、参考相位和代价下，固定点误差没有随调用频率严格单调下降的保证；不能从一个门的误差大小推导普遍规律。

## 5. 为什么门间还有时间也没有完全调回来

第2、3、4门的参考时刻约4.10、4.50、6.11秒。第2到3门只有约0.40秒；第3到4门虽约1.61秒，但参考一直在横向转弯和制动，没有在门之间停住等待误差收敛。

教师20ms实飞约5.50秒时，横向速度仍约−4.05m/s；QP首步希望+6m/s²制动，而当前姿态与推力下的理想值仅约+3.87m/s²。这里“已经计算了很多轮”，仍然不能代替尚未完成的姿态转向和物理制动过程。

预测窗口使用20个100ms步长、覆盖2秒；外部30/80ms是重新采样、重新求控制的周期。这是两种时间，不代表内部100ms才更新一次。参考窗口以实际elapsed时间求值，没有把30ms输入统一舍入到100ms。

## 6. 已排除、仍未排除以及下一步

已排除为本轮唯一解释：30ms普遍无法按时采样；大量读到旧状态；额外输出基本完全重复；仅因INT8；仅因主机响应时间。

仍需分离：姿态反馈增益与缺少一致前馈、推力/阻力模型、偏航响应、DNN拟合和量化的各自贡献。基于相邻四元数差分及命令提交代理估计，滚转/俯仰平均角速度比例接近1，偏航比例约0.4；这不是直接陀螺仪或执行器辨识，不作为已证实的偏航故障。

下一阶段应暂缓靠门宽细调或增加飞机数来寻找救回，先保留当前教师，另做版本隔离的教师姿态响应单变量诊断。改善方向可以是与优化姿态一致的前馈，或把姿态响应纳入预测；不能直接乱加规划器角速度，也不据本轮离线结果立刻重训全部DNN。

**本轮没有确认“修好教师就一定出现调度优势”。它确认的是：当前实验的主要共同误差很可能遮盖了周期变化的效果，应先解决控制能力与执行模型的一致性，再检验实时分配价值。**
