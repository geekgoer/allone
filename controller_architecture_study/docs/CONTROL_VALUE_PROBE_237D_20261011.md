# 阶段 A：模型精度、响应延迟、控制周期的配对闭环试验

## 目的与边界

承接 `DYNAMIC_CONTROL_SCHEDULING_FRAMEWORK_20261005.md` 的阶段 A。
先验证“大模型的额外计算是否值得等待”，不继续堆叠调度器，也不开始超网训练。

本次新建独立实验入口，原训练数据、四个模型权重、既有三机调度入口均不修改。
本轮使用单机短窗口，隔离控制价值；**不代表多机争用、真实 FPGA 延迟或正式安全保证**。
这不是为了强行得到大模型优于小模型，近似等效或更差也是有效结果。

## 默认设计

四个冻结的 237D 模型由 `dynamic_probe_common.RUNS` 定位并校验来源：

- plain4x256
- plain4x512
- plain6x1024
- residual21x1024

路线：验证环境 48、route 0。读取存储的全局 C2 轨迹，不重新规划、不改变标称 5 m/s 路线。
测试集不读取；48–53 仅为验证环境，不应宣称此试验是最终 held-out 泛化评估。

| 变量 | 默认取值 |
|---|---|
| 模型 | 上述四个 |
| 起始状态 | 静止起步、跟踪、路线转弯段、横向恢复、速度恢复、姿态恢复 |
| 周期 T | 50、100 ms |
| 额外延迟 | 0、20 ms |
| 重复次数 | 2 |
| 每次观察窗口 | 4 s |

合计 192 次。纯观察时间 12.8 分钟；还需模型加载、192 次场景重置/生成门、RPC 和落盘时间，实际会更长。
两次重复只适合筛选方向，不能据此声称统计显著；先看是否有值得进一步验证的差异。

同一状态/周期/延迟/重复编号构成一个四模型配对组，打乱组顺序，并在重复轮次轮换模型顺序。
不能完全消除 Windows 抖动或物理引擎隐状态差异，故每次检查并保存放置后的实际位置、速度、姿态。

### 起始状态

- startup：参考相位 0，零线速度。
- tracking：参考相位 2 s（短路线则取不超过四分之一轨迹时长），参考位置/速度/姿态。
- turn：在路线候选时间网格中选横向/竖向参考加速度较大的位置；这是本条路线的转弯样本，不保证高难度。
- lateral_recovery：跟踪初态横向加 0.8 m。
- velocity_recovery：跟踪初态线速度增加 `[1, 1, 0] m/s`。
- attitude_recovery：跟踪初态叠加 0.15 rad 滚转。

所有状态只在**每次试验开始前、暂停的仿真内**放置。飞行期间不瞬移、不注入新的状态、不暂停物理仿真。
因此看到每隔四秒无人机重新出现在某处，是切换到下一次独立试验，不是本次飞行突然跳跃。
短窗口可能只穿过一两个门，不以“五个门全通过”作为此阶段验收条件。

## 时间语义

参考窗口一直取 `初始参考相位 + 单调时钟经过时间`，不会因为延迟、门切换重新从静止生成轨迹。
改 T 只改控制更新频率，不改标称路径速度，也不改原模型的预测时域参数。

额外延迟是在**本次实际特征生成和推理完成之后**再等待，不是把总响应时间强行设成 20 ms。
因此应比较保存的实际 `sample_to_dispatch_ms`，不能把请求的延迟直接当成 R。
等待期间上一条控制持续作用，且状态观察继续。输出超过该次已承诺的 T 时中止，不通过扩大 deadline 掩盖超时。
命令使用一秒有效期并在下一次下发时覆盖，避免人工延迟造成底层命令提前结束；清理时主动发送 hover。
一秒有效期是本实验的有限保持机制，不是“控制周期一秒”。

状态观察目标间隔为 20 ms，与控制周期独立；推理和 RPC 仍会造成观测间隙，实际最大间隔会保存。
跟踪指标对真实观察时间做梯形积分、按完整四秒归一化，而不是直接平均不同 T 的控制样本。
记录的时间是 host 请求状态和异步命令提交的代理时间，不是精确传感器采样/执行器生效时刻。

## 运行

1. 手动打开现有 Blocks，确认 ClockSpeed=1，点击 Play。
2. 若还有旧测试门，先 Stop 再 Play 清除；程序不会删除其他试验的门。
3. 关闭训练、其他控制脚本；只让当前程序控制仿真。不要同时打开第二个 AirSim 实例。
4. 在 PowerShell 运行下面整段。不要复制提示符 `(base) PS ...>`。

```powershell
$proj = 'F:\FalconReproduction\airsim_control'
$trainPy = 'D:\files\PYTHON\cv_lab\Yolov8_Beginner_Demo-main\.venv\Scripts\python.exe'
Set-Location -LiteralPath $proj
Remove-Item Env:PYTHONPATH -ErrorAction SilentlyContinue
if (-not (Test-Path -LiteralPath $trainPy)) { throw 'Python 路径不存在' }
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\controller_architecture_study\run_control_value_probe.ps1 -Python $trainPy
if ($LASTEXITCODE -ne 0) { Write-Warning '实验中止，已有结果保留，请查看最后的错误信息。' }
```

默认连接 127.0.0.1:41451、Drone1，使用 GPU，不启动 UE、不训练模型。
其他无人机随每次 reset 回到初始状态，不参与本轮控制。

## 保存与断点续跑

输出：`controller_architecture_study/results/control_value_237d_v1/`。

- setup.json：模型/归一化/路线/代码来源哈希、运行环境、初态、完整试验顺序。
- 每个 trial/attempt_XXX/initial_state.json：放置请求与实际初态。
- 每个 trial/attempt_XXX/trace.json：位置、速度、参考位置、误差、仿真时间戳。
- 每个 trial/attempt_XXX/commands.json：释放、采样、推理完成、延迟结束、实际下发和限幅记录。
- 每个 trial/attempt_XXX/report.json：成功/失败、时间完整性与闭环指标。
- summary.json、summary.csv：每种组合的重复次数、有效/无效次数、有效试验均值和范围。
- model_pairs.csv：同条件下相对 plain4x256 的配对 MSE 差值，负值表示候选更好。
- timing_effects.csv：同模型同状态同重复，增加延迟或增大 T 相对最小取值的 MSE 差值。

每次试验结束立即保存，不等整批跑完。Ctrl+C 后再次运行同一命令：完成项跳过，未完成项新建 attempt 重跑。
碰撞、超时等已结束的失败项**也跳过并保留**，不会自动反复尝试直到成功。RPC 断开或中断的未完成项可恢复。
更改模型、路线、运行条件或代码时拒绝混写同一实验，需换 `--output` 路径重新运行。
建议只开一个该实验进程，避免重复重置同一个 AirSim。

## 如何解读

`comparable=True` 要求完整时间窗、起始状态匹配、仿真/墙钟速度比在 0.95–1.05、无异常/超时/跳过释放、
无已观察到的门外穿越，以及观测最大间隔不超过 100 ms。
这些阈值是实验数据质量筛选，不是控制稳定性证明。
门未在四秒内到达不会被当成穿门成功；查看 crossings 中 crossed/valid。

先看每组 invalid 数量，再看均值；不能只比较幸存的成功案例。中途结束的低积分不会进入配对排名。
重点回答：

1. 哪类状态下大模型的配对跟踪误差更低？差异是否大于两次重复的变化？
2. 加 20 ms 延迟后，大模型的优势是否还在？用实际响应时间交叉检查。
3. T 从 50 到 100 ms 后，哪些状态/模型恶化更多？
4. 正常状态和恢复状态是否需要不同选择？如果区别很小，不强推动态复杂度。

本试验是“固定候选在不同状态、R、T 下的控制价值表”的第一批数据，尚未训练状态价值预测器，
也没有实现 EDF/控制价值调度、推理中早退或超网。
收到 summary.json 后，再决定需要扩大状态集，还是进入模型池强基线。
