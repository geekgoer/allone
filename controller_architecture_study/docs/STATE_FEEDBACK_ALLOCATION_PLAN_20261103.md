# 直接状态反馈资源分配：研究与实施计划

日期：2026-11-03（Asia/Shanghai）。

状态：**计划，尚未实现。** 本次只核对源码、已有报告和文献，编写交接文档；没有修改控制代码、训练模型或启动试飞。后续Agent应先阅读[当前框架](../../docs/FRAMEWORK.md)、[协作进度](../../docs/COLLABORATION_STATUS.md)，再认领实施任务。

## 1. 目标与范围

用户希望：根据多机当前状态直接算出资源如何重新分配，不再在线枚举若干(T,c)组合并逐项评分。保持PS负责决策/调度、PL负责计算、只在段边界切换任务的分工。

建议主线：

> 在控制有效期耗尽前，利用新鲜状态和实际剩余工作量，直接分配可交付的控制更新；让局部急需控制的回路获得资源，同时约束其他回路受到的影响。

第一交付固定各机DNN，完成连续周期分配与段级EDF；第二交付才加入直接DNN选择。先确认时序机制收益，不把模型能力差异不足和调度问题混在一起。保留现有算法作对照，不覆盖原始模型、数据、失败报告和冻结部署包。

不要求实现RL、全局神经网络策略、动态增加PL核数、任务中途增宽/增深或新路径规划器。PS核数固定且对所有对照一致。

## 3. 学术定位

这是定向文献核对，不是完整系统综述，也不宣称已证明新颖性。

| 已有研究 | 已涉及的问题 | 对本计划的约束 |
|---|---|---|
| Buttazzo等，RTSS 1998，Elastic Task Model | 任务周期弹性变化，适应共享资源 | “危险机加频、其他机降频”不是新思想。[原文](https://retis.santannapisa.it/~giorgio/paps/1998/rtss98-elastic.pdf) |
| Cervin等，Real-Time Systems 2002 | 控制反馈/前馈调度、成本近似下的显式频率分配 | 连续优化、KKT或显式公式本身不是创新。[原文](https://www.cis.upenn.edu/~lee/04cis700/papers/CEBA02.pdf) |
| Samii等，RTSS 2010 | 多个自触发任务的状态相关期限与在线资源管理 | “状态→期限→调度”不能独立作为新颖性。[原文](https://lucris.lub.lu.se/ws/portalfiles/portal/6077432/8168886.pdf) |
| Yang、Belta、Tron，ACC 2019 | 给定状态与保持控制下的safe period | 提供物理期限依据，不自动处理计算等待与多机调度。[作者预印本](https://arxiv.org/pdf/1903.03692) |
| Gifford等，DECNTR，RTAS 2024 | 多模式控制、周期/实现选择、切换残余任务与安全 | 过渡负载、有条件延迟/取消已有直接相关研究。[原文](https://www.cis.upenn.edu/~linhphan/papers/decntr-rtas24.pdf) |

**贡献假说**：针对分段共享神经控制器，把“已经消耗的控制有效时间”和“尚未完成的前端/加速器工作”纳入直接资源分配可行域，避免只优化长期频率、却在当前危险窗口来不及生效；同时让分配计算自身有明确服务预算。

需要真正做出的理论/算法内容，是可计算且不过分保守的**过渡阶段可行条件**、与其匹配的低开销直接分配律及适用假设。若只是连接普通加权投影、CBF与EDF，仍不足以宣称新调度理论。

不能仅靠“CPU改FPGA”“加一个小模型”“超网有136个配置”主张创新。超网日后改变成本、能力和切换代价，不替代核心问题。

## 4. 时间与义务语义

### 4.1 输入带时间和控制版本

每回路记录：state、sample_time、held_control、command_ack_time、control_token、last_release、pending_jobs、remaining_segments。全局记录CPU/PL当前工作、段内剩余量、通信/管理预算和日历版本。

采样须与实际保持控制配对。分析期间若命令切换，重新配对或保留完整控制变化区间，不能随便拼接新状态与旧控制。RPC ACK仍是应用时刻代理，其不确定性需进入部署时的界。

### 4.2 期限是绝对时刻

状态采样于 \(s_i\)，当前命令应用代理为 \(a_i\)：

\[
d_i=\min\{s_i+\mathcal B_i(x_i,u_i,\Omega_i),\ a_i+H_i^{ctrl}\}.
\]

当前剩余时间为 \(d_i-t_{\mathrm{now}}\)，不能把B从分析完成时重新计时。80ms是当前原型的控制更新上限，不是普适常数；没有证据时不为提高通过率放宽。

安全分析沿用held-control/HOCBF接口。当前误差界、机体包络、执行器和通信界未认证，不能宣称真实飞行无条件安全。

### 4.3 明确谁承担当前控制的更新义务

- 若一条有效在途任务将产生下一条控制，该任务承担当前义务，并计入剩余工作。
- 不要求后续若干未发布任务全部承担同一个即将过期的旧控制期限。
- 新ACK发生后关闭已满足的旧义务；若晚了，保留历史超期，再用正确配对的新状态/控制分析下一义务。
- 当前义务已过期时，不能修改记录恢复过去保证。新证据可建立新的条件性分析，同时保留历史违约。

这是优先修正的语义，不是为让优化器通过而删除不利样本。

### 4.4 周期与命令间隔分开

\[
T_{i,k}=r_{i,k+1}-r_{i,k},\qquad
a_{i,k+1}-a_{i,k}=T_{i,k}+R_{i,k+1}-R_{i,k}.
\]

按绝对release运行，不能等上一条ACK再睡一个T。允许排队不等于允许过期命令乱序覆盖新命令。第一版保留同机执行顺序约束，但把独立观测与这条串行执行链解耦。

## 5. 最小算法

~~~text
有时间/版本的当前状态 + 实际未完成工作
                     ↓
绝对期限、可用余量、期望更新需求
                     ↓
直接连续分配所有回路频率（第一版固定c）
                     ↓
生成尚未发布任务的绝对release
                     ↓
一次全组时序核验和版本提交
                     ↓
既有段级EDF执行，新ACK反馈
~~~

不在线展开周期网格，不逐个运行DNN试哪个更好，不搜索调度排列。连续求解可能有有界数值迭代，不能宣传成“完全没有优化”。

### 5.1 检测还能兑现的时间余量

\[
\ell_i(t)=d_i-t-\overline R_i^{next}-\overline L_{\mathrm{manage}}.
\]

响应预算包含前端、IO、排队、段执行、交互和下发，不只减DNN核时间。管理预算只扣一次；若已计入响应界则不再重复扣。

余量接近下一次观测/管理服务的最坏等待时触发分配，而非等到已违规才处理。提前量来自检测/服务界，不增加任意“两秒前预警”常数。

若响应预算只是当前配置的点估计，改变频率后可能失效。第一版明确它仅用于提出方案，并做最终全组核验；若要证明安全，须推导在允许调整域内成立的响应上界。

### 5.2 状态直接给出期望需求

从少量可解释特征 \(z_i\) 给出：

\[
f_i^0=g(z_i),\qquad w_i=w(z_i)>0.
\]

其中 \(f_i^0\) 是资源充足时希望的更新频率，\(w_i\) 是偏离需求的控制代价权重。硬期限进入约束，不能仅靠很大的权重代替。

初版用透明分段仿射函数，参数在开发数据上冻结。后续利用离线配对延迟/周期实验拟合局部代价，在线只算一次函数值。现有486参数候选评分器不能直接改名为这个分配律。

最小目标：

\[
\min_{\mathbf f}\frac12\sum_i w_i(f_i-f_i^0)^2.
\]

这是局部资源分配代理，不是原始飞行J的精确优化。不能预设周期越短无限有益；只在验证过的区间使用近似。先检查现有数据能否拟合，再决定是否补采，不启动大DNN训练。

### 5.3 CPU、PL分别约束

固定c，令 \(A_i,C_i\) 为每次控制的主CPU服务量和PL占用量：

\[
\sum_i A_i f_i\le\rho_{\mathrm{CPU}},\qquad
\sum_i C_i f_i\le\rho_{\mathrm{PL}},\qquad
\underline f_i\le f_i\le\overline f_i.
\]

成本用秒，频率用Hz。管理、IO/驱动、固定工作及资源余量有明确归属。同一等待不能同时作为CPU和PL执行需求重复计费。段间协议造成PL空闲可以降低可用服务，但与核计算分开报告。

这两个利用率约束是简化资源模型，**不保证带任意期限、流水线依赖和有限抢占的全部任务及时完成**。

### 5.4 为什么能直接算

固定成本、正权重、凸可行域下，KKT条件给出：

\[
f_i=\operatorname{clip}_{[\underline f_i,\overline f_i]}
\left(f_i^0-\frac{\lambda_{\mathrm{CPU}}A_i+
\lambda_{\mathrm{PL}}C_i}{w_i}\right).
\]

乘子表示资源紧张程度。资源宽松时靠近期望频率；拥塞时，代价较小且约束允许的回路让出资源。

用预先限定次数的连续求解，报告残差、可行状态、耗时；未收敛或违反约束不称最优/安全解。单资源可有界二分，双资源不能假装两个独立二分一次就得到联合解。若加入更多过渡约束，乘子数量也会增加。

### 5.5 重点研究当前过渡窗口

输入必须包含旧任务剩余CPU/PL需求、段内阻塞、已发布任务和命令阶段。降低未来频率不会消除这些工作。

有限窗口内可以从可用服务扣除旧工作与管理需求，形成保守容量。**仅扣“旧工作/H”不够**：还要处理第一批释放突发和截止时间；总负载低也可能前10ms挤满。

实施顺序：

1. 现有流水线预测器对直接生成的单个方案做一次核验，保留全部在途工作。
2. 用拒绝反例推导紧迫期限前缀的保守需求约束，形成可直接放入分配器的过渡可行域。
3. 证明其覆盖的CPU/PL依赖、段阻塞、释放条件；未覆盖的仍由最终检查承担。

不能把任务视为无依赖、可任意抢占的单核任务后，套利用率阈值称为端到端证明。若约束过保守导致始终拒绝，报告可行域损失，不直接调松常数。

### 5.6 频率与下一次release的连接

对确实由“下一条未发布任务”承担当前更新义务的回路，若有有效响应上界：

\[
r_i^{next}\le d_i-\overline R_i^{next}.
\]

若采用 \(r_i^{next}=r_i^{prev}+T_i\)，本次周期上限为：

\[
T_i\le d_i-\overline R_i^{next}-r_i^{prev}.
\]

下限同时满足最小允许周期和提交前不能发布。由正的T区间转成f区间；区间为空则当前条件不可行，不修改过去release或推迟期限制造可行性。

当前义务若由在途任务承担，不把同一个d强加给所有后继。后继使用其有效名义/控制质量约束，新ACK后再分析新held-control期限。第一版据此只能主张有限窗口条件，不宣称无限时域递归可行。

### 5.7 调度σ与DNN配置c

σ继续有限抢占EDF：段完成后选择绝对期限最早的任务。B大不代表可无限抢占，要看剩余工作、期限和阻塞。EDF在该流水线下不是无需分析即可全局最优。

第二阶段c采用小型直接选择器：

\[
c_i=\pi_c(z_i,\text{允许延迟},\text{资源价格}).
\]

首选深度受限决策树，一次走一条路径返回一个模型ID；未知输入返回明确标记和预先规定的默认项。标签来自离线配对恢复/延迟数据，不假设大模型更可靠，不把默认最大模型写成安全保证。

只在任务边界改c。选完c后重算成本、连续分配T、检查一次；模型时序要求与分配不一致时不安装，不反复在线遍历模型组合。

现有数据尚未证明稳定的模型资格差异，不能承诺这一步一定有收益。固定c是合法消融；上述分解不声称离散模型与周期的联合全局最优。

## 6. 运行时前提

### 6.1 正确的新状态

独立观测与当前已确认控制配对后送入分析器，不一律等完整控制链结束。保留版本检查和状态年龄；后台用最新覆盖邮箱，不积压旧建议。

同一状态/控制版本的安全分析可复用，版本变化失效。不要在高频路径重复旧、新、全组安全分析而不计费。

### 6.2 管理成为有预算的任务

固定PS侧角色与核心，决策不放PL。明确观测交付等待、决策服务等待/执行、提交复核等待、接管命令响应预算。

每个DNN周期可更新状态，不要求每机每周期分别求解整个十机问题。采用一个全局有预算的服务入口，紧迫度变化触发、重复请求合并。预算由测量和可调度条件决定，Python循环写10ms不是硬保证。

第一目标是让提出调整到实际生效的时间可计费、可归因。优化器另占PS核也消耗资源，静态/动态对照必须同核数。

### 6.3 一次检查仍必须存在

检查版本配对、义务归属、旧工作、全部回路期限、CPU/PL预算、输入时效、段阻塞、命令顺序和管理成本。

发生竞态时不安装旧快照方案，下次服务读新状态。旧配置只有仍满足适用条件才可称为可行回退；否则记录当前没有已证可行方案。

历史超期不能永久阻止未来恢复，但必须保留。探索试飞按预先声明规则继续，不把继续飞行标成硬安全通过。

### 6.4 暂不默认丢任务

现有latest已替换未派发旧请求。更激进取消只能针对尚未产生控制副作用的任务，并检查取消后下一有效控制仍满足该回路期限。首版不取消正在PL执行的段、不允许旧命令覆盖新命令。

任务跳过作为后续消融，不是解决全部不可行的默认捷径。

## 7. 三本开销账

### A. 决策反应时间

连续记录：

~~~text
sample → paired snapshot → worker begin → proposal ready
       → review begin → install → first affected command ACK
~~~

相邻差相加得到完整反应时间。危险发生到sample的检测延迟另外报告；仿真可用真值，实物不可观测时使用采样/估计界。

未install样本记录拒绝，不填0ms、不混入成功平均。多机快照逐机报告年龄及最旧年龄，不只报快照创建时刻。

### B. 资源成本

区分线程CPU时间、墙钟时间、PL忙碌时间：

\[
U_q=\frac{\text{资源q上本模块实际占用时间}}{\text{观察窗口}}.
\]

区分实际运行、等锁/IPC、被OS调度出去。父跨度包含子跨度时用exclusive统计或区间并集，不能相加。

逐项记录观测配对、安全分析、状态需求函数、连续分配、流水线检查、提交、日志的mean/P99/max和预算超限率。

### C. 控制响应

计划release至命令ACK拆成：

~~~text
发布抖动 + 派发等待 + 采样/回传 + 前端准备等待/执行
         + 加速器排队/分段执行 + 下发等待/执行
~~~

CPU决策与PL可并行，不能把两条墙钟全部顺序相加。真正新增开销用同资源、同输入/配置启用/禁用管理模块配对测量；动态改变任务数后，两组R均值之差不能直接称算法开销。

建议开发目标（不是已达成性能）：10回路直接分配内核P99≤1ms，固定预算、无离散组合枚举。完整管理路径另外设预算，不能用1ms代替整个链路。

自然路线用部分机平稳、部分机多弯、部分机前稳后急，并错开危险时刻。门宽、初态、参考速度和输入契约配对一致。开发集可搜路线，确认集冻结；不依赖额外瞬时扰动。

先验证接管链，再扩展3/7/10机和多种子。各组资源相同，静态在同模型池和实际资源条件下以预先规定的离线预算选J较好配置。没有完整SVM/FALCON复现时称“FALCON式离线基线”。

最小对照：

1. 同平台重新选定的静态配置。
2. 经典弹性分配＋相同EDF/IO。
3. 状态相关有效期＋直接分配。
4. 再计入信息年龄和过渡剩余需求。

保留各回路完成/碰撞、有效命令间隔、期限越期、安装/交付、管理成本和J。碰撞后J缺失需报告，预先定义失败评价，不只统计幸存者J。退出改变负载时，另比首次失败前共同窗口。

若优势仅来自给新方案更多CPU核，必须给基线同样资源重测。人为降低基线资源或让它违反自身期限，不能证明核心假说。

## 9. 最小理论任务与停止条件

1. 固定c、正权重、凸约束下的解唯一性，以及有界求解残差/失败出口。
2. 当前调度前缀的条件性到达保证：正确版本、有效执行/通信界、真实旧工作和段阻塞下，获准更新按其义务期限到达。
3. 其他回路保护来自全组约束，不是仅把危险回路排第一。
4. 物理安全需有效保持控制界，并对新命令及后续窗口重新分析；一次到达保证不等于递归安全。
5. 若研究跳过任务，需覆盖至下一有效命令的保持窗口，不以“B较大”替代证明。

若无法得到更紧的过渡可行域、及时的真实采用或可重复收益，应降低主张，不把统计经验改名为硬保证。若只是经典弹性分配移植，则如实作为基线，不硬称新算法。

## 10. Zynq对应与交接

AXU3EGB为XCZU3EG，PS有4个A53和2个R5；R5不是默认加入Linux SMP的两个普通核。[厂商手册](https://www.alinx.com/public/upload/file/AXU3EGB_User_Manual.pdf)

当前Windows是功能分工原型，不是周期精确Zynq仿真。日志中前端/协调器同核，后台另核、IO/监测另核，模拟XPU占一个CPU核。不是整个系统都挤在单核；阶段串行与旧状态传播仍存在。

板端用固定A53资源做IO/完成处理、调度和管理，PL执行分段计算。核数/亲和性部署前冻结，对基线一致；R5、多PL核和动态重构不是首版前置条件。

重测AXI/驱动提交、DMA/DDR、缓存一致性、段完成通知、上下文保存恢复、模型和网络成本。普通Linux、核亲和性不自动给出硬实时；PREEMPT_RT减少部分不可抢占来源，仍需驱动、IRQ、内存与总线边界。[内核文档](https://docs.kernel.org/core-api/real-time/index.html)

若AirSim仍在Windows，迁移调度不会消除Unreal、Windows网络和仿真步进不确定性。板端计算链与完整网络闭环分别报告。
