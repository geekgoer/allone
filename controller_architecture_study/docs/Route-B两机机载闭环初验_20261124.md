# 中央命令晚到时，机上还能继续纠偏吗？

这轮是两机机制试验。每架飞机在独立 Blocks 副本的 SimpleFlight 更新线程里直接读本机状态。一个轻量控制律按实际位置算横向速度，保持高度，然后把目标直接交给同一个飞控。每次 `firmware_->update()` 完成后记录这一条新目标的来源、序号、采样和采用时刻。两架机各飞三道实体门。

## 如何做对照

- **纯机载，无故障。** 验证两架飞机都能靠轻量控制过门。
- **纯中央，无故障。** 外部线程通过回环 RPC 读取两机状态并提交样本，中央代理用同一条控制律计算目标。用于核对新链路本身能正常飞。
- **纯中央，有缺口。** Drone1 到达相同位置后，外部线程暂停约 180 ms 再继续发。暂停期间另一个回路与仿真照常运行。留一条延迟前采的旧样本，在延迟结束后尝试提交，用于核对过期拒绝。
- **中央加机载，有缺口。** 相同的中央请求和延迟。在新鲜中央目标仍可用时继续用中央目标。一旦超过 55 ms 输入年龄，机载路径按 20 ms 名义间隔计算和采用。中央恢复时只允许新样本接回控制。

中央对照里的控制律和机载端相同。外部线程确实经过 RPC，计算则由诊断代理完成。记录的空窗指两个新外环目标实际进入飞控更新之间的时间，内置姿态和速度环仍照常执行。这轮验证的是中央更新缺口能否由本机补上。板端 DPU、$T,c,\sigma$ 资源分配和独立机载 CPU 预算还未进入本轮对照。[注入与度量](../airsim_command_timing/run_onboard_pilot.py) · [机载控制与新鲜度检查](../airsim_command_timing/onboard_pilot.hpp)

## 首轮为什么停下

基线以 2.5 m/s 的前向限速、2.0 的横向反馈增益试飞。两机都穿过三个门平面，但进入第三道门时各自碰到了外侧立柱。Drone1 碰撞位置的前向坐标约 8.503 m，门平面在 9 m。机身中心穿过门平面时的余量仍为正，所以只看穿门瞬间会漏掉这次碰撞。

保留这两次失败，门宽仍为 2.6 m。将前向限速调到 1.65 m/s，横向增益调到 1.3，记录门附近的最小余量，再冻结这组参数做四个对照。该净空使用半径 0.525 m 的简化机体近似，碰撞判定以仿真器实际接触记录为准。初始数据在 `controller_architecture_study/results/onboard_pilot_20261124_001/`。

## 实测结果

最终代码以相同设置冷启动复跑两次。每次四组都完成，两架合计每组 6/6 道门，全程无接触。表里的最长空窗、门附近最小余量来自注入对象 Drone1。

| 方案 | 最长新命令空窗，两轮 | 门附近最小估计余量，两轮 |
| --- | ---: | ---: |
| 纯机载，正常 | 21.34 / 21.38 ms | 5.38 / 5.38 cm |
| 纯中央，正常 | 33.09 / 33.11 ms | 5.03 / 4.78 cm |
| 纯中央，暂停发命令 | 213.12 / 216.02 ms | 3.97 / 4.21 cm |
| 中央加机载，同样暂停 | **57.01 / 54.00 ms** | 5.27 / 5.01 cm |

纯中央的实际暂停为 180.24 / 184.40 ms，带机载方案为 180.95 / 183.28 ms。两轮机载方案均在暂停期间实际采用了 **8 条本机命令**。刻意延后提交的旧样本在四次注入中都被拒绝，之后恢复了新的中央命令。原始事件中，两轮中央采用的样本年龄均低于 55 ms，序号递增，仿真采样记录的最长间隔低于 10 ms。

这次支持的结论是，在仿真器仍运行、只有中央新命令中断时，机载路径能补上外环更新，把约 213–216 ms 的空窗缩至 54–57 ms。两种注入方案都成功过门，且门平面余量与门附近最小余量给出的比较方向不同。目前可以确认时序改善，过门安全收益还需要更有区分度的场景和更多重复。

下一步让真实 DPU 的命令接入同一裁决入口，在相同机载预算下比较纯机载、固定中央分配和按需中央分配。当前试验机载控制律给速度和高度目标，原板端 DNN 给角速度和油门。应先核对两条路径采用同一控制接口时的适配和接管，再做质量比较。当前结果与原始飞行日志在 `controller_architecture_study/results/onboard_pilot_20261124_002/trials_001/` 和 `trials_002/`。

## 怎样复跑

在工程根目录编译独立副本。需要本机 AirSim 的 Blocks 源码、UE 4.27 和包含 AirSim 客户端的 Python 环境。

```powershell
$out = (Join-Path (Get-Location) ('controller_architecture_study/results/onboard_recheck_' + (Get-Date -Format 'yyyyMMdd_HHmmss')))
$engine = 'E:\epicGamesStrg\UE_4.27\Engine'
$py = 'F:\Airsim\AirSim\PythonClient\.venv\Scripts\python.exe'
& $py -m controller_architecture_study.airsim_command_timing.prepare_onboard `
  --blocks 'F:\Airsim\AirSim\Unreal\Environments\Blocks' `
  --output "$out\Blocks" --settings controller_architecture_study/configs/airsim_safety_12.json
if ($LASTEXITCODE) { throw 'Blocks copy failed' }
& "$engine\Build\BatchFiles\Build.bat" BlocksEditor Win64 Development "-Project=$out\Blocks\Blocks.uproject" -WaitMutex -NoHotReload -NoXGE
if ($LASTEXITCODE) { throw 'Blocks build failed' }
if (netstat -ano -p tcp | Select-String ':41592\s+.*LISTENING') { throw 'Pilot port already in use' }
$diag = Start-Process -FilePath "$engine\Binaries\Win64\UE4Editor-Cmd.exe" `
  -ArgumentList @('"' + "$out\Blocks\Blocks.uproject" + '"', '/Game/FalconEmpty', '-game', '-unattended', `
    '-RenderOffscreen', '-nosound', '-ResX=640', '-ResY=400', ('"-settings=' + "$out\Blocks\diagnostic_settings.json" + '"')) `
  -WorkingDirectory "$out\Blocks" -WindowStyle Hidden -PassThru
```

等待 `netstat -ano -p tcp | Select-String ':41592'` 显示诊断进程已监听，再运行四个短对照。

```powershell
try {
    & $py -m controller_architecture_study.airsim_command_timing.run_onboard_pilot --output "$out\trials_001"
    if ($LASTEXITCODE) { throw 'Pilot did not pass the mechanism checks' }
} finally {
    if (!$diag.HasExited) { $diag | Stop-Process }
}
```
