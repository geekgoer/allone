# 把一次让出规则扩大到四架和六架

两机原型中，把一次推理让给仍来得及纠偏的一架、再补给让出方，能在部分条件下增加全队最小净空。这次提高共享 DPU 的飞机数量，用同样的一套判据验证整场效果。[两机整场结果](Route-B一次让出整场对照_20261125.md)

## 怎么扩大

- 四架和六架分别在独立横向航道飞行，航道中心距 12 m。门位沿用已校准的新路线，横向振幅交错使用已测的 0.52 m 和 −0.58 m。首尾出发间隔都为 0.90 s，四机相邻间隔为 0.30 s，六机为 0.18 s。每种幅度的飞机沿用相同幅度的校准余量和收益。
- 沿用源板端调用的第 1 秒、第 9 秒回放窗口，每场各有 18 或 12 个可用推理槽。飞机增加，推理预算保持固定。六机每架平均可分到 2 或 3 次推理，常规控制仍由各自机载闭环完成。
- 每个机数和窗口比较三种方法，各做两场，第二次反转方法顺序。两种机数共 24 场。所有方法使用真板模型 11，在相同槽位发出推理。

| 方法 | 怎么选 |
| --- | --- |
| 知道可用槽的静态表 | 提前知道路线、出发间隔和完整忙闲表。用纯机载校准航迹预测各机位置，用原选机规则一次性排好所有可用槽 |
| 原在线 | 用实际位置按原规则选机，优先照顾已等四个名义槽的回路 |
| 允许一次让出 | 继续用两机时的窗口、余量和下一可用槽补回判据。多架接手方都合格时，先选预计余量最小的，余量相同时优先给已测收益较大的 |

静态表的全部接收者在该窗口开飞前冻结。在线方法只在槽到来时选机，槽不可用时由外层回放跳过。允许让出的试验组每场只有一次额外交换，下一可用槽优先给让出方。其他飞机的分配也逐条记录，因为“补回”本身同样要占用一个槽。

主要看全队最小净空和各架飞机的最小净空，同时核对碰撞、过门、请求与真实采用。历史调用用于复现可用性，实际推理在板端，机载闭环由 AirSim 执行。该设置使规模与额外推理预算可比较。

## 结果

每格取两场全队最小插值净空的平均，单位毫米。24 场全部完成，无接触，共过 360 道门。360 条板端推理均按原始槽号和采样时间核对到实际采用。

| 机数与忙闲窗口 | 知道可用槽的静态表 | 原在线 | 允许一次让出 | 让出次数 |
| --- | ---: | ---: | ---: | ---: |
| 四机，第 1 秒窗口 | 124.37 | 124.55 | 124.55 | 0/2 |
| 四机，第 9 秒窗口 | 118.06 | 118.06 | 118.09 | 0/2 |
| 六机，第 1 秒窗口 | 115.42 | 115.38 | 115.38 | 2/2 |
| 六机，第 9 秒窗口 | 116.38 | 116.60 | 116.62 | 0/2 |

四组中，三种策略各自的两场均值相差不到 0.25 mm。四机和六机第 9 秒窗口共六场没有触发让出，派发序列与原在线相同。六机第 1 秒窗口两次都把第 29 槽从 Drone5 给了 Drone6，第 30 槽补回，实际生效间隔 159–180 ms。

| 六机第 1 秒窗口，换槽相对原在线的变化 | 第一场 | 第二场 |
| --- | ---: | ---: |
| 接手方 Drone6 最紧处 | +0.77 mm | +0.64 mm |
| 让出方 Drone5 最紧处 | −0.58 mm | −0.44 mm |
| 全队最紧处 | 约 0 mm | 约 0 mm |

**真正限制全队的是 Drone4。** 它在第三门只有约 115.4 mm 净空。新规则先看单位交换能否帮到接手方，接手的 Drone6 得到一些改善。它和 Drone4 使用同一类校准数据，两架的实际净空仍有差别。只凭同一类航迹的余量表和一个让出关系，很难发现哪架当前决定了全队表现。

18 槽窗口有 5 次请求发生在全队都离开最后门框区之后，12 槽窗口有 2 次。这些请求仍计入等预算对照。四机和六机的最大任意控制更新空窗分别为 22.16 和 22.96 ms，最大 DPU 采样到采用时间分别为 38.93 和 25.55 ms。有限的这批场次不足以比较两种规模的长尾顺序。

这轮把原型成功扩到了四机和六机，复现了让出和补回。两机时的整场净空收益在这里没有复现。留下一次让出作为机制，接下来优先看**能否认出全队那架真正最紧、并且还来得及帮的飞机**。两段窗口均来自同一个历史运行，路线是两种已校准幅度的平行航道，真实背景任务并发与更多路线留作后续验证。

## 复跑

使用独立 41592 Blocks 和板端 5240 模型服务，准备对应机数的配置文件。下面命令生成配置并运行四机。六机把 `$n` 改成 6，关闭本次独立 Blocks 后开启新实例。独立工程位置和板端启动方式沿用前次。[启动方式](Route-B真实DPU与机载接管两机对照_20261124.md#复跑)

```powershell
Set-Location -LiteralPath 'F:\FalconReproduction\airsim_control'
$n = 4
$r = 'controller_architecture_study\results'
$kit = Join-Path (Get-Location) ($r + '\onboard_fleet_scale_' + (Get-Date -Format 'yyyyMMdd_HHmmss'))
New-Item -ItemType Directory -Path $kit | Out-Null
$cfg = Join-Path $kit "settings_$n.json"
$vehicles = [ordered]@{}
for ($i=1; $i -le $n; $i++) {
    $vehicles["Drone$i"] = [ordered]@{ VehicleType='SimpleFlight'; X=0; Y=(-66+12*($i-1)); Z=0 }
}
$json = [ordered]@{ SettingsVersion=1.2; SimMode='Multirotor'; Vehicles=$vehicles; ApiServerPort=41592; LocalHostIp='127.0.0.1' } |
    ConvertTo-Json -Depth 5
[System.IO.File]::WriteAllText($cfg, $json)
$blocks = (Resolve-Path (Join-Path $r 'onboard_dpu_20261124_001\Blocks')).Path
$editor = 'E:\epicGamesStrg\UE_4.27\Engine\Binaries\Win64\UE4Editor-Cmd.exe'
$arguments = ('"{0}\Blocks.uproject" /Game/FalconEmpty -game -unattended -RenderOffscreen -nosound -settings="{1}"' -f $blocks,$cfg)
$blocksProcess = Start-Process -FilePath $editor -ArgumentList $arguments -WindowStyle Hidden -PassThru
# 等待 41592 开始监听，并确认独立 5240 板端服务已 READY。
$py = 'F:\Airsim\AirSim\PythonClient\.venv\Scripts\python.exe'
$bundle = 'controller_architecture_study\docs\main18_requant_release001_delivery_20261115\board_package_requant18_release001'
& $py -u -m controller_architecture_study.airsim_command_timing.run_onboard_deferral_policy --fleet $n --bundle $bundle --replay-from (Join-Path $r 'onboard_load_replay_20261125_001\trials') --output (Join-Path $kit "fleet_$n")
Stop-Process -Id $blocksProcess.Id
```

原始结果在本机 `controller_architecture_study/results/onboard_fleet_scale_20261125_001/`。两种机数各有 `fleet.json`、冻结静态表和 `summary.json`。父目录的 `audit.json` 保存按槽核对和单机代价，`request_phase_audit.json` 保存最后一道门之后的请求数。12 项门测试通过，复查后 41592 与板端 5240 均已释放。
