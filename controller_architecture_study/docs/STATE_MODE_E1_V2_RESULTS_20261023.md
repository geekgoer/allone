# E1 v2：216 次配对恢复试飞与三次基线诊断

日期：2026-10-23。状态：**Windows AirSim 实验已执行完；尚未证明状态相关的最低神经计算需求。**

后续执行更新：本文步骤A/B已完成一轮4次校准与24次廉价子网配对试飞，见[校准与补测结果](STATE_MODE_CALIBRATION_CAPACITY_RESULTS_20261023.md)。新校准转弯保持约5m/s；四配置24/24持续控制通过，21/24时序联合通过；仍未观察到恢复能力分界。本文保留原E1结果，不回填新试验。

## 1. 结论先行

本轮程序正常跑完，但研究假设不能据此宣布成功：

- 216/216 次试验保存完成，90 次满足控制恢复要求，84 次同时满足时序要求。
- 六个配置在相同状态、相同重复轮次下，二元控制恢复结果全部一致；未发现“小配置失败、大配置成功”的能力分界。
- 五组直线状态全部模式通过；最紧的高速偏离直线状态全部失败；六组转弯状态全部未满足恢复判据。
- 两次实际 QP/MPC 教师对照也未通过对应失败场景的完整要求。因此不能把失败首先解释成 DNN 规模不足。
- 无扰动转弯的最大子网虽然被判通过，但它在初始阶段便满足了恢复条件，后续仍有较明显跟踪误差。当前“窗口内曾持续达标”的判据，不等价于恢复后始终保持达标。

下一步优先校准**教师可达到的转弯恢复行为和恢复判据**，再补足更便宜配置的能力覆盖；不需要现在重新训练、扩大调度器或进入 FPGA 实现。

## 2. 实际执行了什么

1. 读取用户首批 12 次输出及原始轨迹，确认修复后的转弯失败不是初态放置扫掠导致的远处门框碰撞。
2. 用同一冻结计划续跑剩余 204 次，没有重跑、覆盖或筛除首批结果。
3. 汇总全部 216 次报告，并按相同状态、重复轮次配对比较六个模式。
4. 单独新增三次基线诊断：教师转弯、教师紧边界直线、最大子网无扰动转弯。三次均完成，时序均可比。
5. 重新运行相关回归测试：14 项通过；教师适配器检查确认 237D 编码不变、实际调用原 QP 教师。

没有修改训练权重、归一化、六配置选择规则、E1 源码或冻结阈值。没有启动训练、Ubuntu 或 FPGA 工作。原 v1 数据保留，不与 v2 混合统计。

## 3. 冻结实验条件与边界

- 模型：`incremental_supernet_237d_v4_grid5000/export` 的共享 FP32 网络。
- 检查点 SHA256：`d9b9c0fd7ffb394f1c11099056e38308d6ef685d9cc99d01e3cd47698f3b2dca`。
- 平台：Windows CPU 推理，手动打开的 Blocks AirSim；只控制 Drone1。
- 场景：environment 48；直线路线 0、转弯路线 3；每种几何固定一个参考相位。
- 初始剩余间隙 `h`：0.3 / 0.6 / 1.0 m；闭合速度 `h_dot`：−0.4 / −1.0 m/s。
- 12 个状态 × 6 个模式 × 3 次重复 = 216 次；分块交错运行配置，避免模式与运行次序完全绑定。
- 周期 50 ms；共同命令发送目标 20 ms，比较容差 8 ms；发送前真正过期的输出不下发。
- 恢复窗口 3 s；位置误差 ≤0.3 m、速度误差 ≤0.6 m/s，同时持续 ≥0.25 s；还要求观察安全、净空穿越及路径推进比例 ≥0.8。
- `h` 是声明的移动路径管道剩余间隙，不是 UE 网格的精确最短距离；真实门框碰撞和门平面净空另外检查。
- RPC 返回不等于精确执行器生效时刻。这是时序代理明确受限的经验实验，不是安全证书。
- 本轮固定一种更新时序，不证明任意 `0≤δ≤δ_bar` 都合格，更不是完整的状态到模式运行表。
- 没有读取 test 数据；没有加入在线 DNN 误差变量。

### 4.3 时序与失败类别

- 12,334 条控制命令记录。
- 发送前硬截止期过期：0 次。
- 共同发送目标偏差：22 次，均出现在最大配置；仍保留控制观察，但对应 trial 不进入时序合格集合。
- RPC 返回晚于 job 截止期：7 次；不把这等同于实际命令必然过期，但无法确认可比时序。
- 216 次中 199 次时序可比、17 次不可比；两类时序事件可能在同一 trial 中发生。
- 紧边界直线 18 次失败包括 13 次实际右门柱碰撞、5 次门平面穿越不满足声明净空。
- 转弯 108 次均无报告错误、通过已观察安全/碰撞检查，但没有达到位置和速度同时恢复的要求；路径推进比例最低约 0.9896。
- 72 个“状态 × 模式”单元中，24 个为三次联合通过的探索性观察，32 个为可比失败，16 个仍为 unknown。

`deadline_misses=0` 不意味着所有实验时序都合格；`recovery=False` 也不等同于发生碰撞。

## 5. 三次诊断：失败不只是模型大小问题

诊断沿用 E1 的周期、发送目标、初态、路线和判据，另存目录，不回填或改写 E1。

| 诊断 | 结果 | 关键观察 |
|---|---|---|
| QP 教师：turn_h0.6_v0.4 | 控制失败，时序可比 | 无碰撞，正常穿过观察窗口内的 Gate3；推进比例 0.9893；位置/速度没有同时进入恢复带 |
| QP 教师：straight_h0.3_v1 | 控制失败，时序可比 | 后续能恢复误差，但 Gate1 穿越不满足净空，不能以最终恢复掩盖先前违反要求 |
| 最大子网：无扰动转弯 | 当前判据通过，时序可比 | 从参考状态开始，0.273 s 已满足持续达标；后续跟踪并非始终达标 |

进一步检查原始轨迹：

- 教师转弯末端位置误差约 0.248 m、速度误差约 1.516 m/s；1 s 后两者中位数约 0.978 m、1.575 m/s。没有任何观测同时满足位置和速度阈值。
- 最小测试子网在同一转弯条件的第 0 轮末端误差约 0.046 m / 1.163 m/s；最大子网约 0.144 m / 1.338 m/s。不能只看末端很小的位置误差，就说恢复判据太严或速度已收敛。
- 无扰动最大子网在 1 s 后的位置/速度误差中位数约 0.851 m / 1.227 m/s，虽然早期满足判据，后续仍退出误差带。
- 教师紧边界直线在约 1.899 s 满足恢复持续时间，末端位置/速度误差约 0.100 m / 0.112 m/s，但先前净空失败仍使完整结果为失败。

**能支持的推断**：当前转弯恢复问题涉及教师闭环、参考机动与接口/更新条件的共同表现，不能主要归咎于神经网络近似容量；当前恢复指标也不能承担“恢复后持续稳定”的额外解释。

**不能支持的推断**：尚未唯一定位为教师增益错误、动力学不匹配、参考曲率过大或阈值不合理。三次诊断各只有一次，不是教师成功率的统计估计。不要直接放宽阈值并把原失败重新标成通过。

## 6. 对框架的意义与限制

### 6.1 目前没有证明动态复杂度的必要性

当前看到的是“有些状态所有测试模式都能恢复，有些状态所有测试模式都不能满足要求”。这能说明场景与完整状态重要，但不能证明需要状态相关的计算量分配。

没有模式覆盖全部 12 个状态，不意味着动态选择能覆盖；七个状态在当前测试集合中根本没有合格模式。因此本轮全状态动态节省 oracle 未定义，不能捏造相对静态基线的收益。

### 6.2 两维特征存在路径上下文混叠

例如相同初始 `h=0.6 m, h_dot=-0.4 m/s`，直线 18/18 控制通过，转弯 0/18。`[h,h_dot]` 不能单独解释这些结果。

这暂时只说明两种路线/参考条件不能直接混成一个无条件表，**尚不能证明加一个曲率维度就解决全部混叠**。第一版先按直线/转弯分层保留数据，不立刻引入新的在线预测网络或高维状态表。

### 6.3 候选集可能没有覆盖真正便宜的控制器

六模式来自“验证 MSE 不超过最好配置 10 倍”的前沿筛选，最低成本已经达到 553,216 MACs。全超网最小合法配置为 30,848 MACs，另有例如 d3_w0256 的 160,000 MACs 配置尚未试飞。

因此当前结果不能推广成“全部 136 个配置恢复能力一样”。全局平均离线 MSE 筛选也可能排除简单状态中已经足够好的廉价配置。后续应在有意义的教师可恢复区间，预先选取少量更便宜的**已有**配置，而不是故意训练差模型来制造分界。

### 6.4 不能把本机 CPU 可比性当成 FPGA 成本

MACs 是工作量代理，不是板端时延；最大配置在 Windows 下更容易偏离共同发送目标，也不是 FPGA 的实测结论。本轮仅识别给定时序条件下的控制表现。

## 7. 接下来最小且必要的工作

### 步骤 A：先校准转弯基线，不重训超网

检查教师在相同更新/接口条件下的参考机动可达性和恢复后跟踪行为；区分“曲率/时间尺度过激”和“教师/接口跟踪不足”。仅使用少量教师与最大子网对照，不再立即运行 216 次。

验收：在预先声明的非零偏差范围中，教师能满足完整安全、推进及恢复要求，并且恢复后的跟踪状态可解释。如果教师都做不到，暂不拿该场景要求小子网通过。

若必须修订参考机动、窗口或判据，应建立新版本，并保存本报告的负结果；不得改 v2 结果。修订目的应是匹配可达的控制任务，不是让大网络看起来更好。无扰动初态的早期达标也不能代替“恢复后持续跟踪”的独立检查。

### 步骤 B：扩大成本跨度，不扩大实验实体

基线校准后，保留一个当前便宜模式和最大模式，再加入一至两个此前未试飞的浅/窄配置。先在少量预先声明的轻/中偏差状态、相同更新时间上配对。

验收：检查控制性能的连续量及恢复成败是否存在可重复的状态与配置交互；并列记录输出变化、跟踪误差和时序，不要求结果严格随规模单调。

若廉价配置在所有重要状态仍足够好，就接受更简单控制器结论，不强行发明超网必要性；若能力差异仅体现在连续控制代价，而非二元恢复，可相应收敛研究问题。

### 步骤 C：有证据之后才扩展运行时与硬件

只有步骤 B 出现稳定、实际有价值的配置差异，才继续延迟包络、低开销状态选择、多回路调度和板端成本验证。不要现在生成 136 配置的全状态表，也不要用调度优化掩盖基线控制问题。

不新增在线 DNN 误差模块、RL、额外资源回收模块或复杂 QoC 预测器。当前主线仍是检验 state-dependent minimum-cost admissible mode 是否存在，而不是预设答案。
