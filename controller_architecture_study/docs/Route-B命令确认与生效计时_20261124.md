# 收到 ping，飞机就用上命令了吗？

**结论是两件事可能相差几十毫秒，而且差值可以朝两个方向变化。** 在独立测试中，AirSim 的 `ping()` 能在命令写入 SimpleFlight **之前**就返回。也能在命令早已生效的情况下，因为控制程序迟处理返回而表现为晚确认。现有 PS 日历把异步下发后的 `ping()` 返回当作命令确认代理。这个值适合记录通信或程序看见了什么。要判断某架飞机的旧命令维持了多久、是否应该改期，必须继续核对飞控采用的是哪条命令。

## 实验怎么做

用现有 Blocks 工程的 AirLib 头文件和已构建的库，编译一个独立程序。它使用真正的 AirSim RPC 客户端、服务端和 SimpleFlight，固定一架虚拟飞机的传感状态，让控制器周期更新。所有事件在一个 Windows 进程内用同一个单调墙钟计时。监听只绑定本机 `127.0.0.1:41590`，也可显式指定其他诊断端口。程序不启动 Unreal、不使用板端资源。

每条命令的角速率为零，并使用本轮唯一的油门值。探针记录发布、进入下发回调、写入目标返回、首个四旋翼模拟电机输出全部匹配该油门、实际 ping 返回以及控制程序记录确认。测试期间只允许一个移动命令在途。比较采用时刻用的是**模拟电机输出首次匹配的时刻**，这比看到服务器收到指令更进一步。代码在任务计时以外等待移动 API 完成，再发下一条命令。

每次运行交错做三组，每组 12 条。跑了两次，共 72 条。

| 条件 | 怎样控制实验 | 模拟电机 20 ms 内更新 | 记录的确认 20 ms 内返回 |
| --- | --- | ---: | ---: |
| 正常 | 照常下发 | 24/24 | 24/24 |
| 目标写入前慢 | 在 SimpleFlight 回调里、写入控制目标之前加 40 ms | 0/24 | 24/24 |
| 确认处理慢 | 在原始 ping 返回后、记录确认前加 40 ms | 24/24 | 0/24 |

这里的 20 ms 从**命令提交**算起，用来展示判定差异。整机的任务期限还需要计入提交前的时间。

写入前慢这一组，实际 ping 在 **24/24** 次中都比目标写入早。两轮 ping 中位数约 0.15 和 0.17 ms，模拟电机更新中位数约 55.82 和 56.10 ms。确认处理慢这一组，模拟电机更新中位数仍约 10.15 和 9.76 ms，程序记录确认的中位数约 41.04 和 54.80 ms。Windows 线程唤醒精度影响了这些绝对时间。探针刻意使用两处不同的注入点，目的在于核对事件顺序。两轮 CSV 审计还逐条验证了四个模拟电机输出确实匹配对应指令。

## 这对联合调整有什么影响？

可以把问题想成快递。现在代码问「营业点能接电话吗」，听到回应后，就把「包裹已签收」写进时间表。探针说明，电话和签收可能在两个方向上错开。

- **确认得太早。** 调度器可能先更新旧命令的版本、重启保持时间，飞机却仍在用上一条指令。
- **确认得太晚。** 调度器可能以为飞机缺了一次反馈，继而放大下发预算或重新排期。实际上，飞机可能已经在使用新指令。

这支持一个具体的下一步。在完整 Blocks 测试中给命令加序号，让飞控侧记录该序号第一次进入模拟电机输出的时刻。PS 分开保留网络连通、命令写入和命令生效，只有匹配到序号的生效事件才能更新保持期限。跨设备时钟没有对齐之前，可以先做同一时钟内的先后关系或保留时钟偏差区间。下一轮要回看自然出现的 38～39 ms 长尾，判断它属于哪一种，再决定优先改确认依赖、移动本地控制，还是两者都做。历史记录只有 ping 的样本目前无法倒推出飞控的采用时刻。

本轮固定状态，完成了真实 AirLib 与 SimpleFlight 的隔离验证。完整 Blocks 飞行时的渲染、物理更新、板端网络、DPU 和多机开销还需实测。上一轮机载分工的 16 次反事实筛查仍属于预算估计。参见[机载与中心 DPU 的分工](Route-B机载分工与时序初筛_20261124.md)。

## 本地复跑

进入当前 `airsim_control` 工程，使用已安装的 Visual Studio 2022 和已有 Blocks AirLib 库。原日志放在 `controller_architecture_study/results/airsim_command_timing_20261124_001/`，已完成的两轮为 `raw_002.csv`、`raw_003.csv`，对应审计为 `checked_002.json`、`checked_003.json`。

```powershell
$out = 'controller_architecture_study/results/airsim_command_timing_recheck_' + (Get-Date -Format 'yyyyMMdd_HHmmss')
$airlib = 'F:/Airsim/AirSim/Unreal/Environments/Blocks/Plugins/AirSim/Source/AirLib'
cmake -S controller_architecture_study/airsim_command_timing -B "$out/build" -G 'Visual Studio 17 2022' -A x64 "-DAIRLIB=$airlib"
if ($LASTEXITCODE -ne 0) { throw 'CMake configure failed' }
cmake --build "$out/build" --config Release
if ($LASTEXITCODE -ne 0) { throw 'Build failed' }
& ".\$out\build\Release\probe_command_timing.exe" 41590 | Set-Content -Encoding ascii -LiteralPath "$out/raw.csv"
if ($LASTEXITCODE -ne 0) { throw 'Probe failed' }
python -m controller_architecture_study.airsim_command_timing.summarize "$out/raw.csv" |
    Tee-Object -FilePath "$out/summary.json"
```
