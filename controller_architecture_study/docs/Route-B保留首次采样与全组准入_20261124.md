# 给控制任务更多时间，仍按原时刻采样

旧版本把两件事绑在一起。20 ms 的周期变成 80 ms 时，下一次采样也会晚 60 ms。上一条命令的有效期仍在倒计时，这 60 ms 可能正是恢复需要的时间。[历史拒绝复算](Route-B真实晚用改期拒绝复算_20261124.md)

## 新规则怎样工作

假设下一条任务原定在 100 ms 采样。把周期从 20 ms 改到 80 ms 后，新版本仍在 **100 ms** 发布。它的周期截止从 120 ms 改成 180 ms，再下一次发布才在 180 ms。若旧命令的保持期限在 165 ms，新命令仍须在 **165 ms** 前送达。输入新鲜度和试验终点也继续限制完成窗口。

1. 只处理带派发拒绝凭据、旧控制版本仍匹配、且后续任务尚未发布的回路。选择第一个能容纳本机准备、DPU 和下发预算的较长周期。
2. 检查目标窗口内其他仍在运行的飞机。先算它们各自独占资源能不能按时完成。有任何一架单独也装不下，就记录机号、所需预算和原周期。
3. 其余情形用已就绪任务的截止时间排序，回放共享 PS、非抢占 DPU 和下发工作。包括已排队的任务，以及目标完成期限前的新发布。任何回路的完成期限或下一次发布前的收尾要求过不了，就拒绝安装。临时取不到匹配状态或已有推理、下发在途时，本试验版保守退回。
4. 回放在日历锁外执行，最多纳入 96 条任务，只做一次全组检查。重新持锁时校验日历版本、提交时刻及下一次发布时间；试验给这次检查预留 1 ms，超预算直接拒绝。1 ms 是提交门槛，实际计算耗时由日志单独记录。

每轮仍使用固定 DNN ID 11 和整次非抢占推理。全组回放依据实测成本的经验预算和有限窗口，覆盖所模拟的并发任务。获得准入后，线上仍逐条检查当时的输入、保持期限和下发余量。当前证据范围是时序检查、改期行为与相应实验结果。[日历实现](../ps_planner_repair/live/live_calendar.cpp) · [回归](../ps_planner_repair/live/live_calendar_tests.cpp)

## 旧日志告诉了我们什么

旧十机日志中，目标单机筛查得到四个有派发拒绝、首件仍可编辑的机会。邻机的最低经验预算为 **49.977 ms**，其中共享准备 42.416 ms，推理 2.296 ms，共享下发预留 5.265 ms。这里只用初始共享下发预留来压低估计，各邻机实际预留可能更高。

| 目标及周期 | 邻机独占仍装不下的数量 | 可以推出什么 |
| --- | ---: | --- |
| Drone5，第 179 周期 | 8 | 这八架的原周期为 20 或 30 ms。按旧经验预算，只改 Drone5 无法让全组通过。 |
| Drone7，第 775 至 777 周期 | 0 | 这三次没有查出邻机单机时限冲突，仍需要核对共享队列和状态有效性。 |

这解释了为什么「给出一个目标机能用的配置」和「现在可以安装」之间还有距离。对 Drone5，即使能临时把 DPU 全给目标机，另外八架的单机账也过不了。它们的窗口被同一次共享准备时间峰值抬高。该峰值可见于历史记录，未来每条任务的实际准备耗时仍要逐条测量。这个对照可用来检验按本机和链路归属预算、区分偶发与持续拥塞能否减少误拒绝。[复算脚本](../ps_planner_repair/analyze_adoption_retime.py)

## 回归和复跑

Windows 与 Zynq ARM 通过相同的基础 355 项检查。额外以锁外构造开关复跑 265 项。回归重建两条历史本机预算，验证原策略拒绝、邻机宽松时按原采样点安装、共享竞争时拒绝、检查超时拒绝，以及安装后仍按更早的保持期限下发。

### 第一次十机对照

| 方案 | 运行时段 | 日志按时交付 | 改期尝试／安装 | 到期退出 |
| --- | ---: | ---: | ---: | ---: |
| 原策略 | 32 秒 | 6,070 | 20／5 | 5 架 |
| 保留原采样 | 1.324 秒后提前结束 | 104 | 0／0 | 10 架 |

原策略安装后的五条首件都在日志中标为按时交付。开组从约 0.21 秒起有多机同时等状态 RPC，最长一条等了 **1,067.866 ms**。其后的碰撞查询不到 1 ms。队伍在第一次限核之前已全部到期，这轮没有进入改期函数。两个结果不能用来估计新规则对交付或退出的影响。压缩对照日志在开组测量启动前 30 秒已结束；板端持久分区已经满，现有日志只能把等待定位到状态调用，不能区分模拟器处理、网络与返回线程。[两组应用日志](../results/ps_pin_release_20261124_001/final/)

### 内存盘复测

将相同开组二进制和配置放入新的板端 `/run/tcs_command_trace_20261124_pinoG3xn4`，从头重启隔离仿真。复测跑足 **32.005 秒**并完成三次限核，7,147 条记录为按时交付，7 架到期退出。**37 次尝试均未安装**，其中 21 次通过目标单机初筛。

| 拒绝位置 | 次数 | 日志证据 |
| --- | ---: | --- |
| 邻机自己的时限已不够 | 18 | 首个挡住的邻机都是 20 ms 周期，独占时仍需 33.493–39.017 ms 的经验预算。 |
| 目标机单独也排不下 | 15 | 保持期限、输入新鲜度、可选周期共同给出的窗小于所需预算。 |
| 邻机当前状态无法配对 | 3 | 未进入全组回放。 |
| 当前记录没有可编辑的后继 | 1 | 未建立本次改期资格。 |

最慢一次尝试用 **101 μs**，包含调用计时及取锁。所有尝试都在快速筛查阶段结束，这个数字只覆盖筛查路径，完整全组回放的真板耗时仍待测。复测与原策略轮的存储位置、瞬时负载不同，7,147 对 6,070 不能归为新规则带来的收益。复测没有安装改期，也就没有取得改期后控制质量的观测。[真板复测汇总和日志](../results/ps_pin_release_20261124_001/tmpfs_repeat/)

证据支持两个不同的瓶颈。首轮是多机同时等状态，调度决策还没开始。复测是邻机原有的预算已超过它们的 20 ms 时限，给一架飞机改期无法修复整队。下一轮应在固定的小范围里核对准备预算，单独记录各机状态 RPC、碰撞 RPC 与共享 PS 计算。用相同日志比较全队共用最大值与按阶段、按归属计费时的准入差异，再选择值得上板的规则。

### 复跑入口

实测套件从已有独立采用事件版生成。配置仅差 `retime_pin_release`，两个运行入口都使用十架同路线、20 ms 起始周期和三次短时限核。板端目录为 `/home/root/tcs_command_trace_20261124_pin5Dv6EN`，AirSim 使用单独的 41591。可按已有诊断副本的启动方式运行，并传入本次 `final/settings.json`。[独立 Blocks 启动模板](Route-B完整仿真命令采用计时_20261124.md#如何复现) · [生成和采集入口](../airsim_command_timing/prepare_event_pair.py)

在板端复制本轮已部署的输入与二进制到一个新目录。若使用 `/run`，先从本工程上传新版 `run_ps_trace.sh` 到该新目录，以便运行器接受内存盘路径。

```sh
src=/home/root/tcs_command_trace_20261124_pin5Dv6EN
kit=$(mktemp -d /home/root/tcs_command_trace_20261124_pinXXXXXX) &&
tar -xf "$src/payload.tar" -C "$kit" &&
printf '%s\n' "$kit"
```

从工程根目录运行下列命令，将 `$diagPid` 设为本轮专用 `UE4Editor-Cmd` 进程号。第一轮结束后重启同一个独立 Blocks 副本，再用新的进程号执行第二轮。

```powershell
$out = 'controller_architecture_study/results/ps_pin_release_recheck_' + (Get-Date -Format 'yyyyMMdd_HHmmss')
New-Item -ItemType Directory -Path $out | Out-Null
$kit = '填入板端打印的新套件路径'
$pulse = 'controller_architecture_study/airsim_command_timing/run_ps_trace_pulses.ps1'
& $pulse -Output $out -BoardKit $kit -DiagnosticPid $diagPid -Arm event_schedule
# 重启独立 Blocks 并更新 $diagPid 后执行
& $pulse -Output $out -BoardKit $kit -DiagnosticPid $diagPid -Arm pin_release
```

旧日志复算使用同一份历史数据，新增参数 `--include-peers`。原始结果、复算 `peer_slot_audit_final.json`、Windows 回归和板端回归在 `controller_architecture_study/results/ps_pin_release_20261124_001/`。
