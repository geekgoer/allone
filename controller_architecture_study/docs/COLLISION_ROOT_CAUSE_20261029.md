# 仍然撞门的原因：时序回放与保存状态接管对照

日期：2026-10-29。分析对象是global_admission_20261029_v4：种子4的2号第4门、1/3号第7门，以及种子5的2号第4门。

## 结论

现在可以把原因分开，不能再统一说“动态开销大”或“DNN精度差”。

1. **2号第4门：额外端到端等待是已得到直接对照支持的致撞因素。** 相同模型、相同已选释放时刻和deadline，移除在线分析/前端等待后，两组十机前缀都没有实际接触；复现原服务等待后，两组均重现2号第4门接触。
2. **3号第7门：现有恢复模型也有问题。** 同一保存状态、20ms更新，原2×128模型撞门；已有9×1024和MPC都通过目标门及本次恢复物理检查。大模型的实际输入到命令延迟略高，改善不能解释为计算更快。
3. **1号第7门：介入时的状态已非常不利。** 原小模型和9×1024在20ms下均接触门框；MPC没有实际接触，但没有达到原定额外过门余量。不能把它记成已被救回。
4. **当前B和准入不是“恢复能力证明”。** 当前原型检查何时完成下一控制，却没有证明该模型在该状态和允许延迟下能恢复；当新旧方案都不可行时又继续观察飞行，因此也不存在“所有硬条件已经满足仍然撞门”的结论。

本轮没有训练新模型，没有缩门，没有加风或位置扰动。增加的等待仅用于复现已经记录到的时序，是原因诊断对照，不是构造最终motivation的物理扰动。

## 1．把模型选择与等待分开

从失败日志冻结十架的任务到达时刻、模型、绝对deadline及优先级。控制输出仍按实时状态重新计算，不回放旧的四维控制值。两组均用同一模型池、一个分段CPU执行器、相同CPU放置和相同初态。

- 快速处理组：保留冻结的选择，移除在线全局预测计算，任务到达后尽快采样、推理和下发。
- 等待复现组：同一冻结选择，按原日志约束采样服务及控制下发的最早时刻，复现原等待。

| 仅比较0～6.3秒、包含第4门 | 原失败记录 | 快速处理 | 等待复现 |
|---|---|---|---|
| 种子4 | 2号第4门接触 | 十机零实际接触 | 2号第4门接触 |
| 种子5 | 2号第4门接触 | 十机零实际接触 | 2号第4门接触 |

原记录在6.3秒之后还有其他接触，本表没有把全长接触数与短前缀混比。原碰撞回路之后缺少请求，回放仅在原首次接触之后补齐短前缀；补齐的请求没有进入原首次接触前的比较。

审计逐条确认：原首次接触之前，模型、计划释放时刻和deadline一致，初态一致，仿真时钟检查通过。实际下发的等待复现有数毫秒误差，不是逐比特/逐物理tick复现。

3.0～5.85秒共同窗口，2号的平均耗时为：

| 指标 | 原记录种子4/5 | 快速处理种子4/5 | 等待复现种子4/5 |
|---|---:|---:|---:|
| 任务到达后、开始采样服务前等待 | 23.30 / 21.98ms | 1.00 / 0.74ms | 24.85 / 24.05ms |
| 输入采到后、控制命令返回确认前 | 17.28 / 16.79ms | 8.54 / 8.75ms | 18.99 / 18.19ms |
| 后端排队＋DNN计算 | 2.78 / 3.06ms | 2.94 / 3.22ms | 2.77 / 3.08ms |

**后端计算这一段没有显著变快，接触却随额外等待的移除与复现而改变。** 这比单看相关性更直接地支持“前后端等待造成反馈滞后”的解释。

快速处理仍不等于通过安全验收：种子4的2号第4门横向偏差0.324608m，距±0.325m阈值仅约0.39mm；种子5为0.328810m，虽无实际接触，仍不满足原额外余量。等待复现分别为0.353945m、0.353638m，并发生真实接触。没有放宽判据或把零接触当成所有物理检查通过。

## 2．2号不是最后一刻少更新了一次

原记录大约在5.6秒经过参考中心附近，此时相对位置看起来不大，但横向速度仍约2.1m/s。之后虽然持续减速，飞机仍向门框方向移动，约5.9秒时横向偏差越过允许范围，约5.97秒记录接触。

在较早的5.3～5.7秒，日志请求周期已经是20ms，实际选定/提交的释放间隔却常为40～60ms，采样后的控制又继续等待。因此这里不是代码完全没发现转弯：提前识别和20ms意图已经出现，实际执行没有及时兑现。

之后B降到约25ms，再降到约15ms和0；很多计划被明确标为不可行，观察模式仍保留配置继续飞行。此时再加密更新，并不能消除已经积累的横向运动。

为检验这一点，另做单机低延迟对照，使用完全相同的2号路线、同一个9×1024 DNN或原QP教师：

| 条件 | 实测输入→命令均值 | 第4门结果 |
|---|---:|---|
| 从起点，DNN，20ms | 4.28ms | 无接触，横向0.289559m，合格 |
| 从起点，DNN，40ms | 4.07ms | 无接触，横向0.309736m，合格 |
| 从起点，MPC，20ms | 3.73ms | 无接触，横向0.297220m，合格 |
| 恢复原约5.2秒状态，DNN，20ms | 3.93ms | 无接触，但0.329329m，余量不合格 |
| 同一5.2秒状态，MPC，20ms | 3.69ms | 无接触，但0.325935m，余量不合格 |
| 恢复原约5.6秒状态，DNN，20ms | 4.13ms | 真实接触，横向0.361748m |
| 同一5.6秒状态，MPC，20ms | 4.05ms | 真实接触，横向0.359960m |

20ms试验实际命令平均间隔也约20ms，不是只改了一个参数、实际上仍隔40ms执行。

**这说明40ms本身不是该路线必然失败的条件；额外R和等待的累积很关键。同时，已经到了5.6秒的坏状态后，当前DNN和当前MPC在20ms、约4ms延迟下都未恢复。** 不能再把最后的失败解释为“最后一条DNN还不够快”。这不是对所有控制器、所有更短周期的不可恢复性定理。

保存状态包含位置、速度、姿态、加速度、角速度和实际已发送的保持控制。单机恢复比较核对了相同初态；没有声称AirSim内部全部隐藏执行器状态也被完全复原。单机试验只判断控制/恢复能力，不证明十机容量。

## 3．3号确实需要关注c，1号也不能只靠最后提频

针对种子4原日志约9.3秒的状态，分别让原2×128、现有9×1024和MPC以20ms接管。三种处理的可设置初态和保持控制逐项匹配。

| 无人机、约9.3秒状态 | 原2×128 | 9×1024 | MPC |
|---|---|---|---|
| 1号 | 接触，横向0.345224m | 接触，0.330270m | 无接触，但0.325337m，余量不合格 |
| 3号 | 接触，0.325615m | 无接触，0.314141m，合格 | 无接触，0.306441m，合格 |

3号的输入到命令均值：小模型约2.40ms，大模型约3.87ms，MPC约3.80ms。**较慢的大模型反而成功，说明这一例存在控制函数/恢复能力差异，不能全部归因于时延。**

当前动态配置把1/3号的巡航和恢复都设成2×128，实际没有切到这个已经展示恢复能力的9×1024。因此，当前原型没有充分使用c这个调节维度。

这不证明“大模型普遍更安全”。1号的大模型仍然接触。也不证明把3号在线换大之后十机一定安全：上述模型能力对照是低延迟单机条件，大模型加入共享资源后的响应时间仍需满足相应条件。

从起点以低延迟20ms运行，1/3号的原DNN和MPC均观测到第1～7门的平面穿越合格、没有实际接触。部分10.2秒末尾记录覆盖不足，原始完整任务判据仍为false；这里只使用目标门和接触证据，不把它们包装成完整任务验收通过。

## 4．为什么全局准入没阻止这些接触

它检查的是给定模型下的时间可行性，不是闭环恢复能力。当前还有三个明确限制：

### B并不判断当前控制律能否刹住

safe_horizon只用位置、速度、门框几何和速率包络，未使用保持控制推演实际动力学；analyze_budget也明确记录uses_control_in_bound=false。在2号约5.6秒状态，B仍曾为150ms，而该保存状态在上述DNN/MPC低延迟接管下均未恢复。

因此，B的含义不能升级为“这个状态允许等150ms之后仍能恢复”。当前位置尚有间隙，和当前侧向运动能否被后续控制及时收住，是两件事。现有提前识别已经使目标T缩短，但物理预算与恢复可行性没有充分约束实际服务。

### MPC教师并没有把这个窄门当作硬约束

QPConfig的横向corridor_radius为1.5m，且走廊使用松弛变量；当前1.7m门宽扣除机体半径和额外余量后，可用中心横向范围仅±0.325m。教师优化的是参考跟踪与加速度等代价，query没有把门框几何作为硬约束输入。

这解释了为何即使教师低延迟飞行，也可能只有几厘米余量，以及为何更频繁调用MPC不自动等于防撞。DNN是在近似这个教师，不会凭借更低MSE自行获得教师没有提供的硬避框能力。

### 经验时延与观察续飞仍不等于硬保证

阶段时延来自经验p95及在途最大尾部，不能消除Windows前端与RPC抖动；逐请求全局预测自身也占用前端。在新旧候选都未准入时，程序按观察协议继续记录。它没有承诺这些片段安全，不能用这些结果证明“满足全部框架约束仍然撞”。

## 5．已定位到哪里，下一步应怎样对症处理

- **优先处理真实R和发布到服务之间的等待。** 2号回放已证明这是可改变接触结果的因素。仅缩短DNN核的2～3ms计算不会自动移除另外二十多毫秒的采样前等待。
- **把3号的恢复能力选择纠正过来。** 当前已有模型能在该状态恢复，不需要先盲目重训；应在满足共享资源条件的前提下使用它。
- **给B保留前瞻的侧移/制动余量，并验证控制器的恢复适用范围。** 单看下一小窗口不碰门，不能保证进入后续窗口时还存在可行的恢复控制。可以沿用现有Safety Analyzer接口，不必新增一个庞大模块。
- 1号等边界状态需要更早介入或更合适的控制策略；现有证据不支持“最后换大模型一定救回”。如果最终要求严格防撞，还需要核对教师/控制律与真实门洞约束的一致性。

这次没有修改上述控制策略来挑选有利结果，完成的是原因分离。关于数据缺失还是训练优化不足，本轮只能证明某些已有DNN在具体恢复状态下不如教师，不能进一步断言唯一原因是训练数据不够。
