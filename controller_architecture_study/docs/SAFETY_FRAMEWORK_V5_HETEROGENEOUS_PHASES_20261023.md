# v5：异步任务阶段的八机配对比较

## 为什么开新版本

v4 保留了静态复跑成功、动态正常工况失败的负结果：动态八机均穿过两个门，但在约 2.53 秒开始连续截止时间失败。八机同一轨迹相位，预算一起降至约 100ms；处理抖动和保守成本使全局余量不足。不能把已穿门或随后悬停改算成功。

v5 不删除上述结果，也不放宽物理截止时间。新增一个事先固定的场景族：八机沿相同已存曲线路径、不同独立门组，相位均匀分布在原相位之前 2.1 秒的范围内。相位跨度不是依据成功结果拟合的参数。各机可能处于不同危险程度，这是状态感知资源分配的目标工况；它不能代表所有飞机同时危险时也能服务。

## 保持公平

- 两策略相同模型候选、完整任务串行资源、相同逐机初始状态、同一组相位、净门宽 2m、实时时钟和 3 秒窗口。
- 预期通过哪些门由保存的参考轨迹预先计算，不根据实际飞行结果降低要求；实际有效穿门数必须满足对应任务要求。
- 改变物理场景后重新执行全部静态候选搜索，不继承 v3/v4 的最优配置。
- 先静态搜索，再动态正常工况；通过后才执行全部 16 对扰动，最后对发现案例做新重复及较快静态配置对照。
- 全部失败保留。拒绝过期控制、停止或悬停不算安全完成；不将经验 p95 叫作 WCET，不将距离/速率预算叫作安全证书。

## 本阶段产物

`results/safety_framework_comparison_v5/n8_net2`：setup、逐次配置与初值、状态轨迹、推理分段、全局释放决策、静态搜索、正常工况和配对比较报告。此次不训练模型、不改权重、不启动 FPGA，也不操作屏幕。
