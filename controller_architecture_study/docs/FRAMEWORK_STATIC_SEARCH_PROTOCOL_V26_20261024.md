# v26：真实碰撞接口下的静态基线与七机配对协议

日期：2026-10-24。当前研究目标是找到可重复的配对：静态配置真实碰撞，状态感知原型按时完成，并在共同完成的工况下比较控制性能J。

## 固定条件

- 真实七机同时飞行；启动环境保留12机，控制其中Drone1–Drone7。
- 门洞净宽2m、净高4m，球形包络半径0.5m，额外净空0.025m。
- 同一已保存转弯路线、5m/s名义速度、3s物理窗口、2.1s车辆参考阶段跨度。
- 使用已有六个237D控制器，模型、归一化与训练数据均不改动。
- 一个共享分段CPU推理后端，前端和通信进程分配不同物理核；试验期间Unreal避让这些核，结束恢复原CPU亲和性。不是OS独占或硬实时保证。
- 使用专用碰撞API和新事件时间戳，防止has_collided短暂标志清除后漏报。
- 使用新双RPC快照路径的冻结经验成本，时延契约`parent_visible_state_and_direct_collision_v3`；沿用声明的p95加余量规则，未针对发现集下调成本。
- 两种方法同样停止过期控制、晚返回、碰撞或飞行保护异常；悬停清理不计为任务成功。

本轮保持原环境与扰动集，先隔离碰撞采集修复的影响。旧接口“碰撞0”已经失效，不能因旧记录而断言当前环境不够难。

## 静态选型

1. 六个模型分别测试T=25/30/35/40/45/50/75/100ms，共48个同构候选，D=T。
2. 对初次通过候选中J最高者，检查固定优先级反转、同步释放、最后一机相邻两个周期，最多4个局部邻居。
3. 初次完整通过的候选按J排序，前三个分别额外运行两轮正常工况。三轮均通过才允许最终选型；分数为三轮平均J。
4. 若前三个都未通过重复检查，则停止，不启动扰动集，也不将某一次偶然通过称为可调度保证。
5. 选型冻结后运行一次动态正常工况。若动态未通过，同样停止，不把其预测拒绝包装成安全优势。

这是预先限定的经验局部搜索，没有SVM或全硬件搜索，不能称为完整FALCON全局最优。

## 扰动发现与确认

- 沿用16个预声明扰动：临界机取第一/最后优先级位置，横向扰动方向正/负，初始位置偏移0.05m，初始横向速度偏移0.6/1.0/1.4/1.8m/s。
- 静态与动态交替先后运行；双方初始指令、目标状态及首次测得的位置/速度/姿态必须一致。
- 静态在整个发现集使用冻结的配置。动态仅按已验证模式表与等待上限进行状态选择，任务内模型及deadline冻结，仅在完整段边界抢占。
- 干净安全优势要求：初态一致，静态有观测到的真实碰撞且此前时序/物理时钟有效，动态无中止完整通过所有任务、恢复及实时条件。
- 只在出现上述优势后进行相邻扰动与重复确认；否则报告完整负结果。

完整任务J按相同公共网格计算。撞毁或中止的部分轨迹J记缺失，不与完整轨迹比较。静态三轮正常均值与动态一轮正常观察也不能解释成统计效应。

## 数据位置与边界

结果目录：`results/framework_runtime_v26_fine_static/n7_net2`。

- `setup.json`与`frozen_source/`：协议、成本、模型、模式表及源码身份。
- `calibration_results.json`：全部候选，包括失败。
- `baseline_validation.json`：前三名的重复检查。
- `selection.json`：最终选择与正常动态检查状态。
- `discovery_summary.json`：完整16对扰动、实测初态一致性及安全优势标记。
- `confirmation_summary.json`：有条件执行的后续确认。

当前二维模式表是有限代表状态/等待点的经验结果，并非整个连续格子的安全证明。20ms危险区仍可能在本CPU预测模型下不可接纳；查表不合格、预测拒绝和真实碰撞应分别报告。B仍为启发式，全部CPU结果不得转换成FPGA或CBF安全保证。
