# 恢复边界采样与实际周期接管验证

本阶段要回答两个问题：候选之间有没有真实恢复差异，以及新方案实际执行后是否有收益。不是再做一轮只记录建议的影子测试。

> 2026-11-02更新：采样与两轮六次对照均已完成。120次有效采样尚未捕获恢复资格差异；新建议首轮执行过1组，优化复核未实际安装，尚不能证明额外收益。结果与下一步顺序见[阶段结果](F:/FalconReproduction/airsim_control/controller_architecture_study/docs/BOUNDARY_TAKEOVER_RESULTS_20261102.md)。以下保留原试验设计，不能将设计目标当作已取得的效果。

## 1. 先采什么数据

固定路线、门洞和名义速度，独立重置初态后改变横向偏差和向边界运动的速度。不在飞行中注入扰动，也不根据结果移动门框。

预先固定六条路线：

- 3400–3403：训练发现集，每条最多查询5个状态。
- 3500–3501：确认集，固定5个状态，不根据训练结果挑选。

训练发现集先测轻松/困难两个端点，再最多细化3次。细化位置根据已观察到的恢复结果变化确定，不假设“更危险一定单调更差”。所有查询保留，包括同成、同败和无效基础设施记录。

每个状态做四个配对动作：

| DNN | 周期 | 第一次接管等待 |
|---|---:|---:|
| 2×128 | 20ms | 10ms |
| 2×128 | 80ms | 10ms |
| 3×256 | 20ms | 10ms |
| 9×1024 | 20ms | 10ms |

合计最多120次2秒步进物理试验。

前两项比较周期影响；其余项目在相同周期和等待条件下比较模型。恢复合格继续沿用不碰撞、回到跟踪误差范围、持续稳定和任务进展等条件，不能只看最终离门框更远。

这是恢复能力诊断，不是自然多机飞行演示，也不把暂停仿真中的10ms协议当成实测端到端响应时间。

## 2. 数据怎样用于评分器

已有控制DNN权重保持不变，只重新拟合轻量评分器。

新训练状态加入原有非测试数据。同一路线上的相邻边界状态放在同一个交叉验证折中，不能让同一路线的一部分状态进训练、另一部分进验证，制造虚假的泛化。

同一路线的多个状态按路线数归一化权重，避免主动采样较密的路线支配训练。确认集不参与拟合和超参数选择，原始保护测试集不使用。

若结果没有候选差异，就如实记录；不以“必须让大模型更好”为采样或标签条件。

## 3. 实际接管先启用什么

这一阶段真正安装通过检查的未来任务计划，但**只调整周期、释放时间和相应deadline，不切换控制网络**。各机使用历史离线选定的相同模型，执行器都用两层FC一段的EDF。

这样可以先判断时序调整是否有收益，不把模型精度、周期与调度算法同时换掉。

新方案是对现有动态控制器的受检增强，旧规则仍作为运行基础；不是已经完全替换成独立新控制器。已经发布的任务不改，已在途控制不冒充成新状态。

安装流程：最新配对状态/实际控制 → 控制相关预算 → 全部回路的时序和负载检查 → 原生原子比较并提交。任一环节不通过则不安装该建议。

当前动力学界仍是开发假设，CPU代价是实测包络，试验仍不能称为硬实时或物理安全认证。

## 4. 怎样做对照

用同一套冻结模型、同一套代价参数、相同EDF执行器和相同初态，比较三个组：

1. 历史离线选定的静态配置。
2. 现有规则式动态方案。
3. 现有动态方案加上新全组检查后实际安装的周期建议。

顺序为静态→旧动态→新增强，再反序新增强→旧动态→静态，共六次自然十机飞行。测试路线种子预先定为6；没有飞行中扰动，没有初始跟踪偏差。

静态组是已有离线搜索结果，不冒充完整FALCON/SVM原文实现。本轮不复现原论文全部硬件或建模条件。

关闭虚拟长前缀计分，只使用实际飞过的窗口计算一致的短程指标。出现碰撞或观测窗口不完整时，不能把缺失的全程J当成可比较的成功分数。两轮也不构成统计上的普遍安全结论。

## 5. 怎样确认不是又做了影子测试

分别记录：

- 通过检查的建议次数；
- 原生实际安装的整组次数；
- 带该安装版本标记、实际发出的控制命令数；
- 其中名义周期改变、释放相位改变、deadline改变各有多少；
- 是否有网络被意外替换（应为零）。

只有原生安装成功、并出现后续带版本标记的实际控制，才算观察到接管。只增加建议计数不算。
