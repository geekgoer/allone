## 当前实现

| 环节 | 实现和入口 |
|---|---|
| 试验编排 | `run_reviewed_rate_trial.py`。选定静态配置后，对照各机固定同一DNN，初始周期设为55ms。6架机使用不同转弯段，发布相位在周期内错开。 |
| 原生时钟和控制 | `framework_native_io.py`、`native_runtime/native_io.cpp`、`probe_seven_continuous_timing.py`。原生采样和命令下发分别绑定物理核。每个已发布任务用 `D_job = r_planned + T_job`，发布、采样、推理、丢弃和回执分别记录。 |
| 执行器 | `framework_runtime_worker.py`、`framework_cpu_xpu.py`。237D独立DNN在共享CPU执行器上按最多两层FC划段，CPU协调器按绝对期限EDF派发。 |
| 状态与预算 | `held_control_safety.py`、`joint_contract_recovery.py`。观测与实际保持控制、命令确认及版本配对，按保持控制和预设误差界计算绝对期限。物理期限进入准入检查，周期期限用于运行时丢弃。 |
| 周期建议 | `joint_contract_shadow.py` 的 `decide_snapshot` 和 `direct_period_proposal`。用发布时刻与当前绝对期限之间的余量构造紧迫度，再由 `heterogeneous_load_guard.py` 的 `project_frequencies` 把频率投影到前端和执行器容量内。 |
| 复核与提交 | `joint_commit_guard.py`。按最新配对状态及日历重建建议，把在途工作带入全组流水线预测。原生原子检查确认控制版本、日历版本和剩余时间后，才安装未发布任务的安排。已经承诺的下一次释放时刻保留，新周期影响随后的释放。 |

固定周期槽位的紧迫度取 `clip(1 - (deadline_s - planned_release_s - minimum_period) / 0.060, 0, 1)`，目标周期取 `0.080 - 0.060 * urgency` 秒。`minimum_period` 同时受20ms下限和经验流水线耗时约束。后台用单一最新快照邮箱，信号量通知，按6ms预算产生候选。前端管理服务以10ms为目标间隔、3ms为预算，这些均为Windows上的经验设置。

本轮六机入口使用固定槽位的显式周期分配，日志中的 `selection_objective` 为 `state_slack_frequency_projection`，`quality_ranked` 为 `false`。冻结 `ranker.npz` 仍是入口依赖。学习评分器主要用于其他候选评分路径，固定槽位分支不以它决定周期。实际飞控仍使用DNN。六机所用模型为Drone1和Drone3的 `plain_mlp_h2_w128_seed0`，以及其余四架机的 `plain_mlp_h9_w1024_seed0`，入口会校验整个八模型池。

## 恢复步骤

1. 在资源管理器中把zip解压到一个新的目录，保留包内路径。解压前可对照同目录的 `.zip.sha256` 用 `Get-FileHash -Algorithm SHA256` 核对压缩包。包内 manifest 的 `git_base` 供比对，`files` 可核对源码和依赖的哈希。
2. 使用原Python环境 `D:\files\PYTHON\cv_lab\Yolov8_Beginner_Demo-main\.venv\Scripts\python.exe`。本轮PyTorch为 `2.4.1+cu121`，控制推理走CPU。从解压根目录先运行 `python -m controller_architecture_study.run_reviewed_rate_trial --help`。DLL位于 `controller_architecture_study/native_runtime/build/Release/falcon_native_io.dll`。如需重建，从包内根目录执行 `controller_architecture_study/build_native_runtime.ps1`，本机依赖MSVC、CMake及 `F:\Airsim\AirSim`。
3. 只做记录回放时，先读前面的四种JSON记录。需要复跑时用原Blocks工程和包内 `controller_architecture_study/configs/airsim_safety_12.json` 启动12机配置，手动进入Play并保留可见窗口。引擎路径为 `E:\epicGamesStrg\UE_4.27\Engine\Binaries\Win64\UE4Editor.exe`，工程位于 `F:\Airsim\AirSim\Unreal\Environments\Blocks\Blocks.uproject`。
