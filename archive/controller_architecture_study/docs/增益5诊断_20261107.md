## 先区分控制周期和响应时间

此前 `teacher_period_sweep_20261107_191116` 的110ms是控制周期T；该组平均实际响应时间约5.586ms，P99约10.185ms，237条命令均交付。它不能证明实际响应延迟110ms仍安全。

另一个独立证据是 `teacher_delay_offline_20261107_v1/report.json`：固定增益7、T120ms，在理想模型中人为设定R100ms，采样几何余量仍正。这是离线模型结果，不是110ms延迟的AirSim实飞。

## 这次改了什么

- `teacher_attitude_probe.py` 增加显式 `gain5`：姿态反馈增益5，无前馈；QP、角速度限制、推力输出定义保持一致。
- `fly_ip37_joint.py` 接受 `--teacher-variant gain5`，仅CPU教师诊断可用，不能借此改写板端DNN。
- `run_teacher_period_sweep.ps1` 增加 `-TeacherVariant`，默认仍为gain7；新汇总记录教师版本并继续核对整批教师/case签名。
- 43项相关检查通过，PowerShell语法和CLI参数检查通过。原 `convex_teacher.py` SHA256仍为 `b36e776594b57ce3b547a02b83ddefaedea231b59ff58f41ca1cab875c1d2f1f`。

旧结果保留。降低增益是寻找控制器适用范围的诊断，不是动态方案的成果；后续静态和动态必须使用同一个冻结教师，并保留gain7对照，不能只选对新方法有利的控制器作结论。

## 用户执行的真实飞行

Unreal进入Play，窗口保持展开。此命令依次进行四次单机CPU教师飞行，不调用板端服务，不注入额外延迟，不改路线或门宽，每组约26秒飞行，另有初始化时间。

```powershell
Set-Location -LiteralPath 'F:\FalconReproduction\airsim_control'
Remove-Item Env:PYTHONPATH -ErrorAction SilentlyContinue
powershell.exe -NoProfile -ExecutionPolicy Bypass -File `
    'F:\FalconReproduction\airsim_control\controller_architecture_study\run_teacher_period_sweep.ps1' `
    -TeacherVariant gain5 -PeriodGrid '30,50,80,120'
if ($LASTEXITCODE -ne 0) { Write-Warning '请保留末尾输出与结果目录。' }
```

输出为新的 `results/teacher_period_sweep_<时间戳>/summary.json`，各T子目录保留实际采样、命令、响应时间、碰撞和漏周期记录。

先比较真实命令间隔、急弯偏差、余量和完整任务结果；毫米级差异不直接解释为稳定优势。如四档仍相近，停止继续细分T。下一步才是固定T、独立改变响应延迟R的配对诊断；该实飞功能本轮没有新增，不把本表的模型R100误作现有命令已经实测过。
