## 2. 预演是怎样做的

源码：`teacher_attitude_probe.py::simulate`，同一个实际QP教师和同一条参考轨迹在本地闭环运行。

1. 到达采样时刻kT，取模拟的当前位置、速度、姿态及未来2秒参考。
2. 运行实际教师，得到推力加速度F和机体系角速度omega。
3. 将结果保留R秒；等待期间继续保持旧控制。
4. 时间到后施加新控制，用简化动力学推进状态，再进行下一次采样。

NED坐标下主要动力学是：

\[
\dot p=v,\qquad
\dot v=g e_3-F\mathcal R(q)e_3,\qquad
\dot q=\tfrac12 q\otimes[0,\omega].
\]

这里角速度被理想执行；未建模电机和角速度内环滞后、空气阻力、估计噪声、量化、操作系统抖动。默认5ms积分步，推力方向取姿态中点近似，姿态按旋转增量更新。R是人为设定的模拟时间；QP实际算了多少墙钟时间不决定此模型中的R。

门框用膨胀几何在轨迹采样点检查，未运行真实接触物理。负余量后仍继续积分，所以穿过13个门平面不等同于安全穿过13门。正采样余量也不是连续时间安全证书。

它适合排除明显失效、比较趋势、缩小实飞参数范围，不能独立证明碰撞或安全。本次gain5模型预报余量约0.7～1.2cm，实飞约2.7～3.0cm；这个厘米级差距足以让临界碰撞结论变化。没有把模型调到恰好命中这一批结果。

**本轮没有找到单靠增益就使30～120ms周期稳定呈现显著优势的控制器。** 找到的是另一种可解释取舍：较大增益能改善短延迟跟踪，却可能降低长延迟下的表现。提高增益并非在所有时序下都免费有效。

如果下一步需要一个新候选，K10值得做短/长R实飞，理由是它在短延迟下本身控制较好、R52也较好，而长R出现明显性能损失；K7应保留为延迟容忍较强的对照。K14仅在本次短延迟RMSE这一单目标下最好，不能称为全局最优。K10也尚未被选为冻结生产教师，原DNN不能因此被当作已经模仿K10。

## 4. R是否比T重要得多

不能作普遍判断。T决定多久重新测量/计算一次；R决定这次测量对应的控制多久以后才起作用。固定R、没有丢弃时，两条命令生效的间隔仍为T，但每条命令都落后于用于计算它的状态R秒。

设采样等于释放，`r_k=kT`、`a_k=kT+R`；在两次生效之间，保持控制所依据的状态的年龄为：

\[
A(t)=t-r_k\in[R,R+T),\qquad \bar A=R+T/2.
\]

这只是此理想条件下的信息年龄，不能替代B、安全条件或稳定性证明。

| 组合 | 平均信息年龄 |
|---|---:|
| T30/R7 | 22ms |
| T120/R7 | 67ms |
| T120/R52 | 112ms |
| T120/R100 | 160ms |

因此此前T30到T120使平均年龄增加45ms，而R7到R100使它增加93ms，变化量本来就不相同。等平均年龄增量也不等于等控制效果，因为采样保持与纯延迟作用不同，闭环还涉及增益、预测、饱和和轨迹变化。

本次五个增益中，R7到R52并没有统一导致灾难；例如K7的RMSE仅约0.0825→0.0860m，K10约0.0311→0.0440m，K14则约0.0206→0.1059m。时间敏感性确实与控制器共同决定。

采样保持和计算延迟应分别建模，这也符合[MathWorks官方计算延迟/采样建模说明](https://www.mathworks.com/help/slcontrol/ug/modeling-computational-delays-and-sampling-effects.html)。该资料不是本工程参数效果的证据，效果以上述原始轨迹为准。

## 5. 对研究路线的结论和下一交付

当前路线及预测教师对T30～120ms不敏感是需要接受的数据结果。降低增益没有解决这一点，继续在5附近找一个碰撞阈值不能证明普遍必要性。

这不否定调度研究：共享执行时，排队和阻塞能让R增大；低开销调度若能使危险回路获得更及时的反馈，仍可能改善控制。但需要证明真实资源条件产生了相应R，并验证调整前后实际效果，不能只注入延迟就声称优于FALCON或获得多机安全收益。

下一交付宜为固定控制器/固定T的独立R实飞诊断，优先K10和K7有限配对，而不是再让用户重复一整轮T扫描。当前实飞入口尚未增加任意增益和模拟延迟参数；本轮没有交付可直接运行K10/R100的飞行命令。确认R方向后，才决定新教师训练、共享资源实验及是否需要更快变化的自然路线。

若论文必须证明单独缩短T显著改善安全，应另用物理可达的、更快变化的任务检验，并用独立路线/种子复核；不能仅靠调弱教师制造快慢分离。
