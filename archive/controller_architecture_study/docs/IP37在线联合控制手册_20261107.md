## 本轮做什么

将已有A/B/C决策器接到真实IP37推理服务。默认三架飞机，分别使用已保存的 env48/route00、env49/route02、env50/route04，独立平移到不重叠的航道，从各自轨迹起点静止出发。三个路线的局部几何不同，不注入扰动。

先固定50ms，再在线启发式；模型、路线、初态、门尺寸和执行资源相同。门框中心线间距为4m，净宽约3.85m；高度同为4m中心线间距。第一轮沿用已飞过的宽门，不通过缩门强行制造碰撞。

本轮目的是让新启发式真正参与多机闭环，并量化安装、拒绝、超期及开销。静态组只是固定50ms对照，**尚未离线搜索FALCON式总体J最优配置**。本轮只有轨迹误差等实际指标，不把它冒充论文原J，也不预设动态一定改善。

## 在线怎样运行

1. 独立日历按绝对时钟发布任务。每机错峰 `i*T_initial/N`；以后周期改变只影响尚未发布的任务。每条已发布任务的 `D_job = r + T_job` 冻结。
2. 每机一个独立RPC工作线程，采样、碰撞回读、准备237D输入，提交到共享板端执行器。若上一个IO处理仍未结束，新释放记为 `dropped_busy_io`，不会把释放偷偷顺延。日历迟醒也逐条记录丢弃，不突发补算过期任务。正常空闲时释放后立即派发采样，实际抖动有日志。
3. 共享工作线程一次只发一个真实IP37请求。主机在每次整任务返回后按EDF选择下一任务，绝不声称能抢占DPU内部。固定组默认也用EDF。
4. 输出必须在周期期限前留出下发余量。超期的排队或返回结果丢弃；已运行的DPU任务仍占资源到真实返回。命令已发出但RPC晚返回，单列 `command_return_late`，不伪装成可撤销。
5. 安全预算使用已有 `GateHoldAnalyzer`，输入当前状态和**实际转换/限幅后的保持控制**。新命令返回后另取一次状态，绑定新的控制版本；旧版本分析随即失效。碰撞只退出该飞机，其他飞机继续，后续减载必须单独解释。
6. 独立规划线程每轮检查后等待10ms，不依赖前台“有空再执行”。它复制全机状态、将来释放和旧工作；调用A/B/C有界修复；最后核对版本、实际决策耗时、全组时序和每机单IO流水线，原子安装未来周期。每次调用最多8次局部调整、5次完整回放。

候选周期为20/30/40/50/60/80ms。本轮只有已经实际飞过的RC1模型11，**不启用DNN切换**。这些周期是探索允许集合，不是已经认证的恢复资格表；查不到严格证书或修复失败时保留当前配置继续记录，不因“未知格子”结束整组飞行。实际碰撞、通信错误或飞行守卫超限退出对应飞机。

## 安全和成本的口径

第一条未来任务的期限约束为 `min(当前保持控制的绝对期限, r_next + T_next)`，旧任务另行保留。后续预测任务检查周期期限；不会把当前B当作所有未来状态的安全预算。未来状态继续在真实采样时刷新。因此本轮准入是有限时序检查，不是全航程安全证明。

沿用显式开发假设：加速度误差2m/s²、位置误差0.01m、速度误差0.05m/s、最大保持分析150ms、barrier rate 10。飞机膨胀半径0.5m、额外间隙0.025m，分析的有限门框盒与本轮生成几何一致。基本命令更新上限160ms。这些动力学界未经AirSim/实机认证；B为0表示这组界下没有证书，不等于必定碰撞。

板端成本来自同一RC1包的40次黄金回放：最大Windows端完整RTT加1ms余量。它包含网络、板端PS处理及DPU API执行，作为一个不可抢占服务段计入，不再叠加一次纯DPU成本。初始主机采样/准备3ms、命令及后续状态配对2ms，后续按本轮观测最大值只增不减；后者计入命令返回后的额外状态回读，不能藏掉这部分CPU开销。规划预留3ms，真实墙钟超过预留则不安装该轮建议。它们都是经验包络，**不是WCET证明**；活动请求一旦超过成本包络，就等待它实际返回，不把剩余时间当0。

当前主机仍是Windows/Python RPC多线程，板上是真实PS+DPU；未把管理代码移植到PS，也未做自定义PL分段抢占。Windows前端时间不能当成Linux/Zynq的测量结果。

## 怎样读结果

目录：`controller_architecture_study/results/ip37_joint_<时间>/`。

| 文件/字段 | 含义 |
|---|---|
| `summary.json` | 两组完整结果，逐架任务完成与轨迹误差 |
| `setup.json` | 包、模型、路线、来源hash、经验成本和安全假设 |
| `requests.json` | 每条计划释放、采样、排队、板端请求、命令返回、丢弃；保留raw237 |
| `decisions.json` | 诊断、尝试动作、旧工作、全组预测、提交或拒绝原因 |
| `period_updates` | 真正安装的周期改变次数，不是建议次数 |
| `snapshot_skips` | 无匹配状态、日历已到期、活动请求超出包络等情况 |
| `context_changed` | 计算建议期间现场改变，旧快照建议没有安装 |
| `decision_budget_exceeded` | 包括等待提交锁在内的决策时间超过预留 |
| `per_vehicle_pipeline_overlap` | 共享资源预测虽可行，但提前后的释放会撞上同机旧IO处理 |
| `no_feasible_repair` | 本次有界修复未找到整组可行方案，不等于不存在解 |
| `physical_deadline_missed` | 命令晚于当前假设下的保持期限；与周期超期分开 |
| `post_refresh_ms` | 命令返回到新状态/控制配对完成，说明额外状态回读占用多久 |

若三机结果正常但 `period_updates=0`，先根据预算、诊断、拒绝原因判断是没有需要调整，还是新方案没能采用；不能直接当成动态收益。下一步才考虑六机及更明显的局部转弯，保持同资源公平对照。
