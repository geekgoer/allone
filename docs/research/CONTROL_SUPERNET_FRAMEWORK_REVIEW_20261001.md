# FALCON 后续研究：动态更新时刻、控制器精度与共享计算的联合设计

日期：2026-10-01。本文是候选研究框架和证据审查，不是已经实现或验证的算法，也不构成新颖性或安全性的证明。

## 1. 建议采用的研究问题

在多个无人机共享 FPGA 的条件下，如何根据物理状态、控制近似误差、计算队列和切换成本，联合决定每架无人机下一次采样的时间、控制器的计算量与执行次序，使控制更新在安全余量耗尽前完成，并改善任务性能或减少资源消耗？

建议定位：**面向多无人机共享 FPGA 的状态感知控制更新与弹性计算联合设计**。

超网是候选实现机制。其价值须由和常驻独立模型池的公平对比建立，不能先假定超网必胜。可能的成果包括安全可行域扩大、相同飞行质量下计算/能耗降低、突发竞争下的恢复能力提高；单独增加模型数量、降低平均 MSE 或缩小权重文件均不足以建立完整论证。

## 3. 修正现有论证中的边界

### FALCON 的约束

FALCON 并非对 T 完全没有约束：式 (12) 包含 R <= D <= T，正文采用 D=T。它还通过拟合性能函数考虑周期的影响。

本次核查未发现优化式中存在用户提出的、由当前横向安全余量推导的动态物理上界。适当表述是：现有实时可调度性约束和经验性能优化，没有显式给出当前状态对应的这种物理安全证书。

论文直接将深度空间取为 {10,22,34}、宽度取为 {512,1024}。论文报告多任务组合优化代价增加，但不能据此断言“选六个模型的唯一原因就是搜索空间爆炸”。共享权重也不会自动消除架构和多任务联合调度的搜索空间。

### PPT 的时间推导

设第 k 次采样为 t_k，执行控制命令为 a_k=t_k+R_k，下次采样为 t_(k+1)=t_k+T_k。则两次执行之间的间隔为：

    a_(k+1)-a_k = T_k + R_(k+1) - R_k

从当前采样到下一次执行的时间为：

    a_(k+1)-t_k = T_k + R_(k+1)

设门洞有效半宽 e_max=(W-W_d)/2-m，当前剩余余量 d_k=e_max-|e_k|。若整个相关区间内相对横向误差变化率满足 |e_dot(t)| <= v_bar，且该门洞/走廊边界在区间内适用，则一个保守充分条件是：

    v_bar * (T_k + R_(k+1)^ub) <= d_k
    T_k <= T_max(k) = d_k/v_bar - R_(k+1)^ub

PPT 例子：W=1m、W_d=0.4m、m=0.05m、|e_k|=0.05m，得到 d_k=0.20m。若 v_bar=2m/s，则总时间预算为 100ms；R 的上界为 20ms 或 60ms 时，T 上界分别为 80ms 或 40ms。

关键限制：

1. R_(k+1) 是未来响应时间，须通过候选调度的上界或有明确风险含义的估计处理，不能以刚观测到的 R_k 自动替代。
2. v_bar 应约束相对门/参考轨迹的横向误差变化，不是简单使用前向巡航速度；当前横向速度为零也不能忽略后续加速度与扰动。
3. 此不等式只证明指定时间区间和指定边界下的充分条件。违反条件意味着不能凭该条件认证安全，不能推出必然碰撞。
4. 门前横向位置在门洞投影外未必立即危险。应使用接近走廊、门平面穿越几何或可达区域；不能把所有飞行阶段都当作必须处于同一个门洞投影内。
5. 更新到来之后是否仍可安全恢复，需要后继状态约束、可恢复集合或备用控制策略。一次更新前不越界不等于永久安全。
6. R 必须包括传输、排队、选择、切换、推理及执行接口延迟。P99 不是硬最坏情况保证；仿真暂停造成的时间停止也不能算真实实时性证据。

因此 PPT 第 3 页适合描述“FALCON 可行配置可能不满足新增的保守物理安全条件”，而不是单凭这张表认定 FALCON 实际会撞。

## 4. 60 个模型是否放得下

板卡资料：AXU3EGB 配备 PS 侧 4GB DDR4、PL 侧 1GB DDR4。XCZU3EG 的 AMD 官方选型表给出约 7.6Mb BRAM、无 UltraRAM；注意 Mb 是 bit，和 GB DDR 不同。约 7.6Mb 对应约 1MB 的片上存储量级，实际可用于权重的容量还要扣除其他模块和缓存。

## 5. 放得下之后，超网还可能有什么价值

### 存储、带宽和计算复用是三件不同的事

独立模型常驻 DDR 时，可以通过地址和描述符切换，不必重新从磁盘加载。模型多也不代表每帧读取全部模型，更不代表时延按模型数量成倍增长。

片上存储远小于 DDR。若工作权重不能留在片上，每帧 DDR 流量及多任务竞争可能影响延迟、能耗和抖动。共享权重只有真正保留在缓存、使用一致布局并被硬件复用时，才减少流量；软件切片或屏蔽无用神经元不自动节省硬件运算。

SUSHI 已研究共用子图的片上持久缓存和硬件状态感知调度，这不能作为本项目独有创新。

### 更强的候选机制：同一次控制请求内的渐进计算

建议先考虑固定宽度、多个输出出口的共享前缀网络。先形成一个基础控制候选，再按需执行额外残差块形成修正候选。仅在当前请求、相同输入下复用中间计算：

    共享前缀 -> 出口 1 -> 扩展块 -> 出口 2 -> 扩展块 -> 出口 3

当另一架无人机的紧急任务出现时，在出口/计算块边界结束或调度，利用已算出的候选输出。60 个独立网络虽可常驻，但已经对网络 A 算出的隐藏特征通常不能直接作为网络 B 的隐藏特征继续运行。基线可以先算小网络再算大网络，代价须纳入公平比较。

这让超网的论点从“保存许多模型”推进到“共享已完成计算，并在剩余安全时间内决定是否继续细化控制”。不过它需要专门的多出口训练和执行器支持。一般的弹性宽度切片不天然具备这个能力；增加宽度后先前隐藏层结果可能需要重算。

更深出口不保证每个状态下更准确、更平滑或更安全。各出口须单独评估，量化后重新校准误差，必要时加入出口一致性/增量修正训练与控制候选接受检查。共享权重也可能使某些子网比独立训练更差，这个代价必须保留在结果中。

## 6. 候选 framework

### 核心耦合

响应时间 R 不只是网络本身的执行时间 C：

    R = 输入传输 + 排队/阻塞 + 选择/检查 + 切换/必要搬运
        + 推理 + 输出传输/执行接口

若性能分析中搬运已包含在推理时间，就不要重复相加。各部分采用同一个时间起止定义和可对齐的时钟。

选择更小网络会降低 C，但可能提高控制误差；提高采样频率会减少保持旧控制的时间，但也增大共享计算队列。某架无人机多用计算，可能缩短自身误差，却增加其他飞机的响应时间。因此在线输入不能只是一对外部给定的 (MSE, latency)。

### 模块与闭环

1. 状态和时间测量：物理状态、路径/门信息、当前已执行命令、采样与命令时间戳；同时观察 FPGA 队列、缓存和当前计算块。
2. 短时安全预测：给出旧命令等待阶段与新候选命令保持阶段的可达范围，保留扰动、估计误差、模型近似与量化误差。
3. 联合决策：选择每架飞机的下一次采样间隔 T、子网/出口 q、任务优先级或执行次序；初版固定硬件配置，不做在线重综合。
4. 弹性执行：运行共享前缀与扩展块，在规定边界产生候选输出。输出接受检查和切换成本均计入时序。
5. 执行与反馈：落实控制命令，记录实际响应与安全余量。若没有可行选项，进入已评估的备用减速/避让/控制模式；不能仅继续放大周期。

### 将安全时间从“只与速度有关”扩展到“与控制候选有关”

可从如下抽象约束入手：

    E_k(x_k, u_previous, q, T, R_upper, disturbance, switch) <= d_k

E_k 是相关边界方向上的位移/偏差上界，所有量须保持物理单位一致，不能直接把四维控制 MSE 加到米制距离上。

简单一维启发模型可以是 v_bar*H + 0.5*a_bar*H^2 <= d_k，其中 H=T+R_next_upper；进一步使 a_bar 或可达范围反映候选控制误差。实现时必须处理命令应用前后的分段动力学。经验分位数只能支撑经验或概率声明，不能冒充严格上界。

用 tau_safe(x,q) 表示在明确假设下得到的有效更新时限，则可以考虑：

    T_i + R_next_i_upper <= tau_safe(x_i, q_i)
    R_i_upper <= T_i          # 若采用隐式截止期的周期任务模型

由于式中有未来响应时间，在线决策必须为下一次更新保留预算，或验证下一次调度仍可行；不能只贪心检查当前任务。

更准确的 q 可能延长 tau_safe，但也增加 R。这两方面谁占优，应由当前状态与实测硬件决定，而不能按网络越大越好排序。

### 优化目标

初版选一个明确主目标，例如：在安全约束与最低任务进度下，最小化加权跟踪损失加平均计算/能耗成本。也可固定能耗预算最大化跟踪表现。应避免用任意权重把“碰撞”换成较高平均得分。

控制器的静态全局 MSE 适合做离线筛选。在线价值应考虑当前误差方向、接近速度、执行新命令的剩余时间及其他任务受影响程度。

### 有限候选和分层运行

先离线剔除明显被支配的候选，将有限的周期档位与已评估出口组成表。在线采用短预测域、小规模联合枚举或增量资源分配，并在提交前做一致的可行性检查。

慢层在任务/环境或资源状态明显变化时更新候选与资源预算；快层处理下一次更新与出口选择。这是需要验证开销的设计选择，不是已证最优算法。无需一开始构建复杂的神经网络选择器或每帧搜索巨大 NAS 空间。

## 7. 可尝试形成的贡献与已有工作关系

| 候选贡献 | 相对现有工作的具体增量 | 主要反例/风险 | 所需证据 |
|---|---|---|---|
| 模型误差、周期与响应时间的联合可行域 | 不把准确度和截止期当作彼此独立的外部要求；显示其对物理边界的共同作用 | 安全界过松/过紧；已有控制研究已经覆盖同类形式 | 明确假设、推导或经验覆盖验证，对照相同控制器的动态周期基线 |
| 三机状态与硬件竞争共同驱动的计算分配 | 一架飞机的架构和周期选择影响其他飞机响应时间；检查后继可行性 | 小模型很快，实际并无竞争；普通 EDF 足够 | 实际负载与时序、不同危险状态组合、公平 EDF/模型池基线 |
| 多出口增量控制及有界中断开销 | 将共享权重进一步转化为当前请求内可复用计算，用于应对计算中预算变化 | 已有 anytime/early-exit；出口质量不单调；中断代价抵消收益 | same-state 增量耗时、所有出口误差、预算突然收缩实验 |

“与 SUSHI 不同”不足以证明新颖性。SUSHI 的 state 重点是加速器缓存状态；TimelyNet 已有车辆状态驱动动态时限与超网选择；self-triggered control 已有基于状态决定下一次更新；early-exit 已有渐进预测。潜在增量需要在这些交叉处提出具体问题与机制。

## 8. 最省时间、最有判别力的验证路径

### 先检查研究前提

用已有模型，先选几个有代表性的候选，测统一平台上的闭环质量与端到端响应，不重训所有大网络。必须加入当前表现最好的小模型。

若同一小模型在所有有意义工况都满足安全和质量且计算更少，当前工况没有足够的模型适应收益。应接受结论，将重点转向动态周期；或基于实际控制需求研究更复杂动力学/任务，而非为了证明大模型必要而人为制造问题。

真实复杂度可来自不同速度/曲率、外扰与模型偏差、执行器约束、多步避障、机间耦合。输入信息必须足够表示这些决策条件；缺失信息导致的标签歧义不能靠增加模型容量解决。

### 必需基线

| 基线 | 隔离的问题 |
|---|---|
| 最佳固定小模型 + 固定周期 | 最简单方案是否已足够 |
| 最佳固定小模型 + 动态周期 | 仅调整 T 的收益 |
| 6 个独立模型常驻 + 同一联合调度器 | 原有离散候选是否限制表现 |
| 更多独立模型（例如 60 个）常驻 + 同一调度器 | 导师提出的直接替代方案 |
| 超网 + 固定周期 | 弹性网络本身的作用 |
| 超网 + 动态周期 | 联合设计的作用 |
| 多出口增量执行，与普通选择后完整推理对比 | 复用当前计算和应对预算变化的作用 |

60 模型池应训练合理的小中大候选、常驻内存、使用高效切换；不要故意每次重新加载磁盘或只用表现差的大模型。比较候选前沿时，不只看参数量或 FLOPs。

### 主指标与实验条件

- 成功率、碰撞率、最小安全余量、轨迹误差、恢复时间、完成时间或最低任务进度。
- 周期变化、端到端延迟和尾延迟、实际时限违约、控制间隔/信息年龄。
- 选择、切换、缓存填充和推理分别耗时；DDR 流量、实际权重/工作区、能耗（可测时）。
- 单机与三机，平稳与突发竞争，不同状态组合，多个 seed 与不确定性区间。
- 人工延迟/带宽限制须明确标成压力测试，不代表板卡实际负载。
- 延迟须相对持续运行的物理/仿真时间计算。暂停仿真等待推理的结果不能证明满足真实截止期。
- 当前模型说明中的 sample_period_seconds=0.05，即 50ms；改变部署更新周期后须验证闭环性能，不能假设训练时有效就对任意 T 都有效。

### Go / No-go

1. 动态 T 有收益，但超网不胜独立模型池：保留联合时序研究，降低超网贡献级别。
2. 权重省很多，但时延/能耗/控制质量无收益：只能报告存储效率。
3. 只有压力测试极端条件才有收益：诚实限定适用范围。
4. 同样安全率与任务性能下减少 DDR 流量/计算，或同样资源预算下显著扩大可安全运行的状态与负载范围：形成支持框架的主要证据。

## 9. 给导师的核心表述草案

我接受独立模型池能够替代超网细粒度选择的质疑，当前小模型也确实可以大量存进 DDR。拟研究的问题是多个控制回路共享 FPGA 时，控制器误差和计算等待共同消耗状态相关的安全余量，应怎样联合决定下一次更新时间和本次计算量。超网的候选价值是共享权重以及同一次请求中的渐进计算：先形成可评估的控制候选，再根据剩余安全时间决定是否继续计算。实验会使用常驻的独立模型池作为强基线，验证共享执行是否在相同安全和任务要求下减少计算、访存与切换代价。若没有这些收益，不将超网作为必要结论。
