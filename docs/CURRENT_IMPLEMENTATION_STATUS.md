# 当前实现与实验进度（2026-11-08）

这份说明用于快速了解现状。目标计划见`RESEARCH_GOALS_AND_PLAN.md`，逐次证据见`COLLABORATION_STATUS.md`。以下描述区分已实现功能和已证明效果。

## 1. 最终研究什么

多架无人机共享一个加速器。希望依据各机实时状态，把计算机会优先给真正需要及时控制的回路，在相同资源下维持或改善整体控制质量与安全表现。不能只证明程序能切换周期，也不能只证明少发请求。

## 2. 目前实际在哪里运行

Windows负责AirSim、采样、237D输入准备、安全分析、周期决策和任务队列；Zynq板端DPU执行一个237D DNN。尚未将整个控制前端迁移到PS。用户已决定暂缓部署比较。

每个周期按日历释放任务，不等上一任务完成才计时。任务需要经过采样、准备、排队、板端推理、命令下发。来不及的任务按原规则丢弃并记录期限失败；丢弃不能算硬期限通过。命令返回只是真正生效时刻的代理。

## 3. 当前控制与调整怎样工作

正常控制输出是推力加速度和三个机体角速度，经适配调用AirSim角速度/油门接口。当前板端只有一个可用模型，因此没有在线切换DNN复杂度；普通DPU只允许整任务执行，不能中途任意抢占。

安全分析根据位置、运动、当前实际保持的控制及门框几何，估计保持当前控制的时间预算B。它有明确模型误差假设，但这些假设尚未得到完整实机认证，因此不能声称已经具有严格物理安全保证。

在线启发式用少量尝试诊断：释放是否太晚、资源窗口是否超载、执行顺序是否造成等待；尝试修改未来周期/合法队列顺序，显式检查全组任务与旧任务残余工作，再核对上下文后安装。普通板端没有段级抢占、当前也没有模型池切换。

## 4. 为什么增加独立观测

旧路径在控制返回后继续回读状态和分析，造成下一任务到点时本机worker仍忙。全部推迟回读又让规划器拿不到有效状态—控制配对。

新实验路径让每机独立RPC线程持续观测。控制发出期间暂不提交观测；发布前后版本不一致、或已有更新状态时，拒绝旧结果。控制任务返回后不再承担重复配对回读。该功能默认关闭，需要`--independent-observer`启用，额外开销已开始测量，缺观测问题仍存在。

## 5. 已经知道什么

- 现有旧DNN能在合适路线反复飞完，暂不需要因本轮任务强制重训。
- 较快急弯路线50ms相对120ms表现出更大过门余量，样本少，部分仅几何余量失败而非实际碰撞。
- 平稳路线50/120ms均较宽裕；双机固定50/120ms三轮完成且无丢弃，减少约29%请求，但没有证明DPU拥塞或危险机控制改善。
- 原在线策略会错误放宽急弯回路；历史最大墙钟开销也会令规划器长期拒绝修改。
- ETW已观察到一个命令确认54.33ms的样本中线程Waiting约52.35ms，不等同CPU独占执行。阻塞来源尚未完全分清，迁移PS不能保证消除。
- 独立观测已恢复周期安装，但两次中仅一次同时通过机身和严格时序检查。尚不能证明动态优于静态。

## 6. 当前正在验证什么

新增可选、场景绑定的经验周期集合：急弯回路先仅允许已测过的50ms，平稳回路允许50/120ms。目的是诊断错误降频，而非用人工标签替代最终状态反馈规律。没有证明短周期自动更好，因此不自动加入20/30ms。

允许周期仍须通过全组时序检查；两架均从50ms开始。若拒绝仍多，就继续查成本与期限；若不再错误降频且功能可用，也只能得到当前场景的机制对照结果。

本轮两次对照已结束：两轮均飞行/机身检查通过，急弯最小余量7.14/7.51cm；r0在3.316秒将平稳回路50→120ms一次、748次交付和1次推理丢弃，r1无安装、1001次交付和3次丢弃，严格时序均失败。r1历史最大准备成本仍到70.58ms，故候选资格并未解决长尾与准入。证据`controller_architecture_study/results/qualified_observer_20261108_v1/`。此经验限制是对照条件，不能宣称通用学术算法或策略优越性。

## 7. 与计划的对应

阶段1第一轮初筛完成；阶段2迁移比较按用户要求暂缓；阶段3正式环境冻结未完成；阶段4已有时间敏感性探索；阶段5第二模型尚未接入；阶段6启发式原型正在修复和验证；阶段7正式静态/动态收益实验尚未开展。
