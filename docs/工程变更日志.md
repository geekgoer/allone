本日志从 2026-11-22 的路线 B 工作开始补记。后续按对话工作轮次追加。每条记录说明问题、代码或实验改动、验证证据以及剩余问题，并与当轮改动一起提交。飞行通过、时序验收和离线复算分别记录。

## 2026-11-23 · 隔离单机 ACK 长尾对全组预算的影响

- **改动**  新增可选的 `isolate_command_costs`。把 ACK 路径的后处理与下发预留经验最大值挂在各无人机上，派发、尾序列筛查、最终下发和规划各自读取任务所属回路的成本。继续执行原有控制版本、保持期限与迟到 ACK 检查。诊断脚本输出各机最终估计。
- **验证**  Windows 与 AXU3EGB 均通过 254 项回归。原日志逐条筛查中，两轮其他机的超周期预算拒绝各 87 条，局部预算分别可使 87 条和 76 条通过这一道门槛。定向闭环采用单独的测试二进制和真实 DPU，推迟 Drone3 的一次 ACK 观察。关闭隔离 12 架退役，开启后其他 11 架按时交付新增任务 10,338 条，其中 10 架持续至 20 s 窗口末。两轮生命周期审计通过，严格时序均未通过。首次试验参数 12 s 被拒并改成 20 s 后重跑。
- **发现与待办**  开启轮 Drone3 约 1.045 s 按保持期限退出。Drone4 约 18.434 s 另因本机下发等待及共享 DPU 成本上涨退出。后续定位共享模型成本中的 DNNDK 调用等待，并在自然长尾下复核。结果与复现材料在 `results/ps_command_isolation_20261123_001/`。[实现与板端数据](../controller_architecture_study/docs/Route-B分段DNN与保持期限_20261122.md#实验十--按无人机隔离命令预留2026-11-23)

## 2026-11-23 · 单次下发检查十二机闭环对照

- **实验**  用同一 ARM 二进制和冻结路线完成关闭、开启、开启、关闭四轮交错运行。每轮 12 机、20 ms、32 s 目标窗口。收齐板端原始记录并核对归档哈希，四轮命令生命周期审计通过。
- **结果**  尖峰前两组匹配分别有 2,319 和 5,535 条任务，打开开关后下发前丢弃从 45 降至 31、59 降至 15。两种路径各一次完成 144 道门、各一次全组提前退役，四轮均未通过严格时序验收。新旧默认设置沿用上轮。
- **发现与待办**  失败轮共用命令预留升至 42.606 ms 和 35.104 ms。其中 ping 返回墙钟等待分别为 41.999 ms 和 34.693 ms。超过 20 ms 后记录到 95 和 94 次 DPU 预算拒绝，各轮最终 12 架到期退出。下一步优先复现并隔离异常等待对共用预算的影响。数据见 `results/ps_command_atomic_validation_20261123_001/`。[四轮结果、配对与定位](../controller_architecture_study/docs/Route-B分段DNN与保持期限_20261122.md#实验九--十二机单次下发检查交错闭环2026-11-23)

## 2026-11-23 · 单次原子下发检查

- **问题与改动**  命令线程在推理完成后先复制日历行，又读取成本，再进入最终检查。新增 `single_command_check` 路径，省去这两次读取。`live_calendar` 在最终一次取锁后读时钟，核对任务归属、版本、保留时间和预留，成功就登记命令在途。`prepare_hold_expiry.py` 生成同一二进制的新旧两条路径。诊断脚本新增原子准入核对与历史余量筛查。
- **验证**  Windows 与 AXU3EGB 均通过 43＋126＋47 项回归。ARM 候选和三个测试程序通过板端哈希核对，部署到 `/home/root/ps_command_atomic_20261123_001`。历史数据中 138 条前置预算拒绝，按原第一次取锁耗时复算，取锁后额外耗时为 0、50、100、250 μs 时依次有 35、14、4、2 条仍有正余量。上一轮已有的统计字段逐项复核一致。
- **证据与待办**  `results/ps_command_atomic_20261123_001/historical_screen.json` 与 `atomic_board.tar.gz`。Blocks 本轮未运行，候选默认使用旧路径。十二机闭环对照需测实际按时交付和取锁耗时，同时保留推理前排队作为独立指标。[实验八与复算命令](../controller_architecture_study/docs/Route-B分段DNN与保持期限_20261122.md#实验八--单次原子下发检查2026-11-23)

## 2026-11-22 · 分段 DNN 与到期处置

- **问题与改动**  共享 DPU 上，整网任务可能阻塞后来就绪的急任务。用 `export_segmented_mlp.py`、`compile_segmented_dnndk.py` 和 `benchmark_segments.cpp` 实现模型 ID 11 的双 kernel 原型。`prepare_hold_expiry.py` 与 `live_calendar` 接入按控制版本检测旧命令到期并退出该机普通调度。
- **验证**  AXU3EGB 上 960 组整网与两段 INT8 输出逐项一致。额外耗时中位数 21.33 μs。双任务基准验证了提前为急任务留切口的收益。到期处置当轮在 Windows 和板端 ARM 各通过 204 项回归，覆盖在途推理、迟返 ACK 和单机退出。
- **证据与待办**  `results/ps_segments_20261122_001/`。分段当轮在独立基准中运行，闭环整网派发待另做负载验证。到期退出后的实际备用控制仍待验证。[分段原型和计时](../controller_architecture_study/docs/Route-B分段DNN与保持期限_20261122.md#实验二将同一-dnn-真正切开)

## 2026-11-22 · 可分段机会与派发拒绝复算

- **问题与改动**  要确认十二机的丢弃是否由连续 DPU 占用造成。`replay_dnn_segments.py` 和 `audit_segment_opportunities.py` 用实测时戳比较整网派发、推迟整网和切段预留。日历日志新增拒绝当时使用的模型成本、命令预留和剩余预算。
- **验证**  三轮累计检查 32,624 次 ID 11 起跑，局部窗口内未发现只有切段才能满足期限的任务对。修订轮 694 次模型预算拒绝均被复算，其中 664 次若采用初始模型成本会通过这道检查。该数字是反事实准入结果。诊断版在 Windows 和板端 ARM 各通过 207 项回归。
- **证据与待办**  `results/ps_segment_opportunities_20261122_001/final_audit.json`。根据分阶段实测查清模型成本中包含的派发延迟。[机会与拒绝复算](../controller_architecture_study/docs/Route-B分段DNN与保持期限_20261122.md#实验四三轮十二机日志中的可预测切口)

## 2026-11-22 · 分离派发等待与模型成本

- **问题与改动**  诊断基线有 80 条从派发到本地推理返回超过 3 ms，其中 62 条以日历取锁为主。`live_calendar` 增加可选的 `separate_dispatch_service`。派发用获得日历锁后的时钟复核，选定模型放不下时，自适应模式最多尝试一次已经允许的最快档。
- **验证**  十二机、20 ms、32 秒三次完整运行分别按时交付 18,750、18,036、19,014 条，各发布 19,200 条。只复检原档的一轮在最后检查额外丢弃 1,090 条。修复后有 2,505 条当场换档，2,500 条按时交付。三轮均通过 144 道门，严格时序均未通过。Windows 和板端 ARM 各通过 210 项回归。另一次启动空窗约 1.056 秒，零推理并触发 12 机退役，单独保留。
- **证据与待办**  `results/ps_dispatch_timing_20261122_001/`。单次顺序对照的收益仍需重复试验，队列锁竞争与 DNNDK 尾延迟需分别跟踪。[十二机分阶段计时](../controller_architecture_study/docs/Route-B分段DNN与保持期限_20261122.md#实验五十二机闭环分阶段计时)

## 2026-11-22 · 规划快照持锁优化

- **问题与改动**  原快照在锁内边构建边检查，发现后面一架机的观测不可用时会丢掉前面已经构建的内容。`snapshot_precheck` 先验证全组观测，再构建快照。`snapshot_precheck_bench.cpp` 对照同一十二机日历的快照与用时。
- **验证**  Windows 和板端 ARM 各通过 210 项回归。板端独立基准中，最后一架缺少观测时，耗时中位数从 1.977 ms 降至 10.5 μs。可用快照的 36 条任务义务逐项一致。同二进制飞行对照的前 5.82 秒内，派发等锁 P99 从 0.556 降至 0.420 ms，按时交付从 3,467 降至 3,396 条。全程分别通过 135 和 144 道门。关闭轮一架退役，两个全程的调度负载因此不同。
- **证据与待办**  `results/ps_snapshot_precheck_20261122_001/comparison.json`。保留开关供重复试验，继续检查命令下发前丢弃。[快照持锁与闭环对照](../controller_architecture_study/docs/Route-B分段DNN与保持期限_20261122.md#实验六规划快照的两步检查)

## 2026-11-22 · 命令下发余量溯源

- **问题与改动**  前一轮共同窗口中，开启预检后下发前丢弃净增 64 条。`audit_paired_command_margin.py` 对齐同架无人机和同一周期，`analyze_dispatch_timing.py` 与 `prepare_hold_expiry.py` 加入日历行读取、锁等待和命令前置检查的分阶段诊断。

- **证据与待办**  `results/ps_command_margin_20261122_001/paired_margin.json` 和 `command_timing.json`。分开处理推理前排队和命令读锁，首个候选为单次原子下发检查。[逐阶段溯源与复跑](../controller_architecture_study/docs/Route-B分段DNN与保持期限_20261122.md#实验七命令下发前的预算去哪了)
